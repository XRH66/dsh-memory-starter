## 一、交换格式与检查（新模块）

按标准第一节和第三节第 1 条实现：

1. 读 `.jsonl`：第一行是文件头（`standard` 必须是 `dsh-memory-inherit`，`version` 必须是 1），之后每行一条记录。
2. 逐条校验字段：必填项、类型、`speaker`/`kind` 的取值、`time` 的格式（完整时间带时区，或只到日期）、`text` 不超过 20000 字（按 Unicode 字符计）。
3. 检查报告（只读，不写任何东西）包括：
   - 总条数，各 `kind`、各 `speaker` 的条数；
   - 时间范围、没有时间的条数；
   - 逐行错误（第几行、哪个字段、错在哪、怎么改）；
   - 未知字段（列出字段名和出现次数，导入时忽略）；
   - 预计向量编码的条数和字符数；
   - 和库里已有内容比较后，会新增、跳过（已导入）、冲突各多少条。
4. 有任何错误，整份不导入。
5. 规模上限：单个文件 50MB、10 万条。超过就直接拒绝，不要读完再拒绝。

## 二、0.3 旧笔记转换（新模块）

按标准第四节表格第一行：

- 读 Vault 下 `chats/` 里 `facts`、`events`、`history`、`review` 四个目录的 `.md`，只认带 `memory_id` 文件头的文件。
- 正文取文件头里的 `value`，没有就取正文部分；时间取 `recorded_at`，没有再取 `created`，都没有就留空。不要从正文推断日期。
- `speaker` 为 `summary`，`kind` 为 `note`；`id` 用相对 Vault 的路径（统一用 `/`）；`source.system` 为 `basic-memory-0.3`，`source.file` 为同一相对路径。
- 文件头里的主体、属性、类型等放进 `tags`，只作显示用。
- 转不了的文件（文件头坏了、正文为空、超长又切不开等）逐个列出原因并跳过，其余照常转。
- 只读：不改、不移动、不删除 Vault 里的任何文件。
- 可以调用 `lib/legacy-notes.js` 里已有的解析函数，**但不要改这个文件**。
- `dafeiyu/` 下的主观笔记和 `index/` 下的主题页不在本转换的范围内。

## 三、写入原话库

1. **存法：**
   - 每条记录在原话库里成为独立的一条，全文和向量两路都能搜到，`memory_open` 能打开。
   - 走哪条写入路径（聊天记录导入那条，还是新记录器那条）由你读完代码后选定，回执里写明理由。原则是改动最少，并且和日常库现在的读取方式一致（日常库只有 `turns`，`raw_messages` 是 0 行）。
2. **说话人：**
   - `summary` 要作为单独的说话人保存，不能存成用户或助手。
   - 进全文索引和向量编码的文本前缀不能写"用户："或"助手："，改用"旧笔记："之类的说法。
   - 如果要扩展 `role` 的取值，相关读写（`buildTurn`、查询读取、全文、向量材料）都要接住。
3. **导入的标记：**每条都要能查到它是导入的、属于哪个批次、来源和种类，搜索标注和撤销都靠它。
4. **幂等：**
   - 同一来源（`source.system`）加同一 `id` 视为同一条；没有 `id` 时，用"来源 + 时间 + 说话人 + 正文"的哈希。
   - 正文相同的跳过；正文不同的列为冲突，不导入，也不覆盖。
   - 已经撤销的批次里的记录再次导入时，报告为"已导入但已撤销"，不产生重复。
5. **批次：**
   - 每次导入生成一个批次号，记下时间、来源、条数。
   - 可以按批次整批撤销。撤销必须能恢复，并且要走现有机制（撤回原话或按轮次排除，二选一），回执写明选了哪个、怎么恢复。
   - 撤销后的记录搜不到、预取不到、`memory_open` 打不开或标明已撤销。
6. **排除在外：**
   - 导入的记录不进短期接续（`handoff.js`、`recent-context.js`）和 `memory_recent`，因为它们不是最近的对话。
   - 也不能因为写入时间是"现在"，就被当成最近的内容。
7. **向量编码：**导入后由命令行触发向量编码（复用现有的待编码处理），费用按标准第二节在检查报告里预估。
8. **不调用任何模型。**向量编码除外。

## 五、命令行入口 `scripts/inherit-memory.mjs`（新文件）

- `check --vault <目录>` 或 `check --file <x.jsonl>`：只读，输出检查报告；加 `--out <文件>` 时把转换结果写成标准格式的 `.jsonl`，方便核对。
- `apply --vault <目录>` 或 `apply --file <x.jsonl>`：
  - 先检查，有错误就停；
  - 写之前像 `scripts/raw-memory.mjs` 的 `apply` 一样备份原话库；
  - 然后导入并做向量编码，输出批次号和新增、跳过、冲突的条数。
- `list`：列出批次。
- `undo --batch <批次号>`：整批撤销。恢复方式在 `--help` 和 README 里说明。
- 配置读取方式照 `scripts/raw-memory.mjs`（读部署配置、作用域、密钥文件路径）。不要打印密钥和令牌。
- DSH 正在运行时能不能用，要说清楚：
  - 能用的话，插件要能看到新写入的内容；
  - 要重启才能看到的话，命令行在结束时提示。
  - 回执写明你验证的结果。
