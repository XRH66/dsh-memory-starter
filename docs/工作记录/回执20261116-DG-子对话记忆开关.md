# 回执 2026-11-16-DG：子对话默认不接入记忆，设置页留开关

状态：已完成；未提交、未推送、未打标签。

## 1. 结论

- 新增配置项 `subagentMemory`，默认 `false`。
- 默认关闭时，非根代理（子代理、孙代理）看不到记忆工具，工具守卫拒绝执行，不自动预取、不附加回答规则、不带短期接续，也不保存原话。
- 默认关闭时，根对话行为不变。
- 在设置页打开并重新加载 DSH 后，恢复当前行为：子代理和孙代理可只读使用工具、预取和回答规则；仍然不保存子对话原话，也不带短期接续。
- rc.5 与 rc.3 的隔离实机都完成了默认关和打开后的对照，工具集变化符合要求。

## 2. 配置和生效时机

配置名：`subagentMemory`

默认值：`false`

- 已加入 `lib/config.js` 的 `DEFAULT_CONFIG`、Schemastery 校验和 `resolveConfig()`。
- 已加入现有功能开关快照 `pendingMemoryFlags`，保存位置与 `autoRecall`、`recentContext`、`rawRecall` 一致。
- 设置页保存后显示“重新加载后生效”；重新加载 DSH 后，`pendingMemoryFlags` 合并进 `memory`，并在启动时传给 `createSessionMemory()`。
- 生效单位是进程启动配置，不做运行中热切换。
- 兼容升级前只有三项的待生效开关；旧 `pendingMemoryFlags` 会补上 `subagentMemory: false` 后继续应用。

## 3. 实现

### 3.1 统一根代理判断

- `lib/host-compat.js` 新增 `isRoot()`，继续以 rc.5 的 `agents.isOwnedBy()` 为权威路径，以 rc.3 的 `currentInitiator()` 捕获结果为兼容路径。
- 没有活的运行时归属，但会话头明确带有 `origin: subagent` 或父会话信息时，按非根处理并沿用一次告警，不把会话头当成授权来源。
- `lib/session-memory.js` 只保留一个内部 `isRootAgent()`；`check()`、`autoEnable()`、`admitMessage()`、公开 `isRootAgent()` 和 `grant()` 都复用同一条路径。

### 3.2 默认关闭

- `sessionMemory.check(agent)` 只有在“对话记忆已授权”且“当前是根代理或已打开子对话开关”时才返回允许。
- 工具可见性继续走 `lib/platform-host.js` 现有的 `agent.ctx...restrict({deny})`，没有新增第二套工具过滤。
- 现有工具注册包装和全局工具守卫都检查同一个 `check()`，所以执行前也会拒绝非根代理。
- `onPreStep` 因拿不到读取授权，不会预取、附加回答规则或建立短期接续。
- 原话写入继续由 `admitMessage()` 的根代理检查排除子对话输出。

### 3.3 打开后

- `check()` 在 `subagentMemory: true` 时保留原有继承读取行为。
- 工具、预取和回答规则恢复。
- `admitMessage()` 仍只接受根代理，子对话正文不进入原话库。
- `selectPrestepHandoff()` 和请求阶段仍使用根代理门槛，子对话不注入短期接续。

### 3.4 设置页

- `lib/client.js` 的「记忆功能」列表新增“子对话也能用记忆”。
- 文案说明：DSH 做任务开出的子对话可以查记忆；只读，不保存子对话的话；默认关。
- 保存按钮继续向现有 `/flags` 路由提交，等待重新加载后生效。
