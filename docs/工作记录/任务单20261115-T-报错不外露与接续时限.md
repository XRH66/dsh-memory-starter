# 任务单 2026-11-15-T：报错不外露与接续时限

工作区：`<工作区 t>`（分支 `t-errors-handoff-age`，基于 main 的当前提交）。执行方按本单实现，不提交；Claude 复核后提交。

## 背景

发 0.7.0 前收两处小尾巴：

1. **报错外露**：记忆读写出故障时，模型有时会把后端报错原文说给用户。`memory_search` 自己的超时、后端失败已经返回中性提示（`lib/suzu/search-session.js` 的 `MESSAGES`），但还有几条路会漏：
   - `createMemoryQueryTools`（`lib/memory-query.js`）的 `execute` 没有兜底：取查询对象时抛的错（如"本回答的记忆入口不可用"）和检索里没被归类的异常，会原样变成工具报错交给模型。
   - `dafeiyu_records`（`lib/records.js` 约 942 行）失败时把 `'dafeiyu_records failed: ' + 错误码 + ' — ' + 英文错误信息` 放进 `summary`，这正是模型看到的文字。
   - `soften_memory`（`lib/soften-tool.js`）的 `errorMessage` 是英文；`softenRawMessage` 抛异常时没有兜底。
2. **短期接续没有时间上限**：`selectHandoff`（`lib/handoff.js`）从最新的原文往前取，直到填满 4096 个词元，不看时间。一个多星期没聊过，新对话也会把那时的原文当"最近"带上。

## 目标

### 1. 报错不外露

把工具出错分成两类：

- **调用参数问题**（模型改一下参数就能重试的：动作名不对、缺必填项、找不到指定的编号、编号版本已变等）：保留给模型的提示，但改成简短中文，不带英文堆栈和内部路径。
- **运行故障**（其余一切：存储读写失败、网络、超时、授权失效、未知异常）：模型看到的统一是中性中文提示，例如"这次没能读写记忆（技术原因已记录在状态页）。回答时自然地说这次没办成即可，不要提后端、接口、错误码，也不要编造。"；详细原因只进 `logger.warn`。

要做的：

- `createMemoryQueryTools`：给三个工具的 `execute` 加兜底。已有的中性结果照原样返回；抛出的异常转成与 `search-session` 现有错误结果同形状的返回值（模型能看到的文字用中性提示），并记日志。`createMemoryQueryTools` 可增加可选的 `logger` 参数，`lib/index.js` 里创建工具处把现有 `logger` 传进去（只改这一处调用）。
- `dafeiyu_records`：失败返回里 `summary` 和 `errorMessage` 按上面两类给中文；`errorCode` 字段保留（结构化字段不渲染给用户）。哪些错误码算"调用参数问题"由你在 `records.js` 里逐个确认，用白名单，回执列出清单。`execute` 本身抛的异常也要兜底。
- `soften_memory`：`errorMessage` 改中文；`softenRawMessage` 抛异常时按运行故障处理。

### 2. 短期接续时间上限

- 新配置项 `handoffMaxAgeHours`：默认 72，整数，范围 1～8760。加进 `lib/config.js` 的默认值、校验和解析（照 `handoffTokens` 的写法），超范围按默认值处理（与 `handoffTokens` 一致）。不做设置页入口。
- `selectHandoff` 增加参数 `maxAgeMs` 和 `now`（默认 `Date.now`）：每条原文的时间取 `source.time ?? source.recordedAt`；比 `now() - maxAgeMs` 早的、或两者都没有的，不带入。列表是从新到旧取的，遇到第一条过期的就可以停止往前翻。
- `lib/index.js` 里三处 `selectHandoff` 调用都传入 `maxAgeMs: handoffMaxAgeHours*3600000` 和插件现有的 `now`。
- 其他接续逻辑（什么时候带、带几条、词元上限、首轮预选、同一对话只留一条）不变。
