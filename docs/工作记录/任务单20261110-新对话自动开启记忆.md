## 要解决的问题

现在每个对话的记忆默认关闭，必须先聊一句、再到设置页手动勾选，而且从下一句才生效。结果是新对话第一句必然记不到，每次都要手动开。

目标：加一个开关「新对话自动开启记忆」。

- **默认关**：行为与现在完全一致（默认不读不记这道门保留）。
- **打开后**：之后新建的对话在创建时就自动开启记忆，第一句就能读能记。
- **不受影响**：已经聊过的旧对话不自动开；用户手动关过的对话保持关闭；子代理对话、分叉出来的对话不自动开。
- 自动开启的对话在设置页的对话列表里显示为已开启，并且可以像手动开启的一样关掉。

## 为什么能赶上第一句

DSH 创建对话时用串行方式等待 `agent/created` 监听器全部完成后才放行后续工作。只要我们的监听器**等授权写盘完成再返回**，首个回合开始时授权已经生效。授权区间从 `startTurn:0, startSequence:0` 开始，首回合 `turn=1` 满足 `lib/memory-policy/index.js` 里 `active()` 的「开启之后的回合」条件，所以 `memory-policy` **不需要改**。

## 代码架构

### 1. `lib/session-memory.js`

控制器新增两个方法：

**`enabledSessionIds()`**：从已读入的 `saved.sessions` 里返回 `enabled===true`、`ownerSubject` 与本控制器一致、`project==='main'` 的 `rootSessionId` 数组。

**`async autoEnable(agent)`**：满足**全部**条件才开启，返回 `true`；任何一条不满足返回 `false`，不抛错：

1. 控制器未关闭；`agent.session.id` 形如 `session-…`；`agents.get(id)===agent` 且 `sessions.get(id)===agent.session`；
2. 是根对话：`rootAgent(agent)===agent`；
3. 不是分叉：`!agent.session.inheritedEventCount`；
4. 是全新的对话：`state(agent.session)` 的 `turn===0` 且 `users.size===0`；
5. 该对话在 `saved.sessions` 里**没有任何记录**（有记录说明用户做过选择，开或关都不动）。

满足时 `await policy.set(id,true)`，然后 `readSaved()`，返回 `true`。**不要**调用 `sessions.ensure`（创建过程中不能回头等宿主）。内部异常统一吞掉返回 `false`（调用方记日志）。

`status()` 里的 `defaultEnabled:false` 保持不变。

### 2. `lib/platform-host.js`

- 新选项 `options.autoEnableNewSessions`，存成可变量 `let autoEnable=options.autoEnableNewSessions===true;`。
- `if(sessionMemory){…}` 里已有的 `ctx.on('agent/created',…)` 改成 `async`：保留开头的 `ctx.agents.get(agent.session.id)!==agent` 判断；随后若 `autoEnable` 为真则 `await sessionMemory.autoEnable(agent)`，包在 `try/catch` 里，失败只 `ctx.logger?.warn?.('[session-memory] 自动开启失败：'+…)`，**绝不能让对话创建失败**；`await` 之后重新判断一次 `ctx.agents.get(agent.session.id)===agent`，再走原有的 `trackScope` / `refreshScopes`。
- 「已知对话」改为并集：凡是现在用 `selected` 来列出状态或计算要关闭哪些对话的地方，在有 `sessionMemory` 时用 `new Set([...selected,...sessionMemory.enabledSessionIds()])`。具体两处：
  - 设置信息回调里的 `states`（现 202 行附近）；
  - `applySessions` 里 `action==='replace'` 的 `updates`（现 185 行附近），保证用户取消勾选一个自动开启的对话时它会被关闭。
- 设置信息里的 `sessionMemory` 对象增加 `autoEnableNew:autoEnable`（`defaultEnabled:false` 不改，界面靠它判断功能是否可用）。
- 传给 `registerSettingsRoutes` 的 `controls` 增加 `afterSessionDefaultSave:async(cfg,revision)=>{…}`：更新 `autoEnable=cfg.autoEnableNewSessions===true`，并和现有 `afterHandoffSave` 一样 `markApplied`、更新 `staticFingerprint` 和 `service.configurationFingerprint`。

### 3. `lib/deployment-config.js`

- 新增 `stageDeploymentSessionDefault(file,enabled,expectedRevision,afterSave)`：写法照抄 `stageDeploymentHandoff`（加锁、核对 revision、原子保存、`afterSave`）。`enabled` 必须是布尔，否则报 `'请选择有效的开关状态'`。写入顶层字段 `autoEnableNewSessions`。返回 `{autoEnableNewSessions,revision,applied}`。
- `validateSessions`：`cfg.autoEnableNewSessions` 存在但不是布尔时报错 `'新对话记忆设置无效'`。
- `readDeploymentSettings` 的返回值增加 `autoEnableNewSessions:cfg.autoEnableNewSessions===true`。
- `applyDeploymentSessionChange` 的 `unbind`：对话不在 `cfg.dshSessionIds` 里时**不再报错**，列表保持不变（自动开启的对话不在这个列表里，但用户要能关掉它）。`value` 仍须是合法的 `session-…` id。原来断言 `'该会话尚未绑定'` 的测试相应改掉。

### 4. `lib/bundle-entry.js`

`startPortable` 里组装 `settings.personal` 时增加 `autoEnableNewSessions:cfg.autoEnableNewSessions===true`。

### 5. `lib/settings-host.js`

- 没有 `controls?.sessionMemory` 或没有 `controls.afterSessionDefaultSave` → 404 `'当前入口尚未启用对话记忆开关'`；
