# 任务单 B：预取去噪（2026-11-13）

前置：A 批已提交。总览见[全面优化总览](方案20261113-全面优化总览.md)。

目标：自动预取**宁缺毋滥**。以下几类情况分别处理：

- 弱相关的旧事不注入；
- 同一件事只占一个位置；
- 旧笔记和核对过的条目要分得清；
- 旧原话里的问句不能被模型当成本轮问题；
- 技术故障不进入对话措辞。

整个过程不增加任何模型调用，不超出现有 1.3s / 1.5s 时限。

`memory_search` 工具（模型主动查询）的排序和返回条数**不变**，只共享 B4 的标签改动和 B6 的报错措辞改动。门槛只用于自动预取。

## B1 检索结果附带绝对相关信号

在 `lib/memory-query.js` 的 `searchOnce` 融合阶段，给每条候选附加内部字段 `_signals`：

```
{ lexical: 0..1, similarity: number|null, lanes: ['text'] | ['vector'] | ['text','vector'] }
```

- `lexical`：用 A 批新增的 `lexicalMatchTerms`，按本次查询的 `queryProfile`（每次检索只算一次），对候选的**完整正文**（在 `excerpt` 截取之前）计算覆盖率。原话、条目、旧笔记、向量记录都要算。
- `similarity`：来自向量记录的 `similarity`；只有文字命中的记录为 `null`。
- `lanes`：该条候选在哪几路命中过。同一 `[id, revision]` 在文字路和向量路都命中时，记为两路。

`_signals` 不得进入 `memory_search` 的工具输出。`lib/suzu/search-session.js` 的 `fit` 本来就按白名单复制字段，保持这一点即可。

给 `createMemorySearchSession` 增加一个选项 `keepSignals`（默认 `false`）。为 `true` 时，`fit` 把 `_signals` 复制成打包记录的 `signals` 字段。只有预取会传 `true`。`createMemoryQueryAnswer` 透传这个选项。

## B2 准入门槛（`lib/memory-prefetch.js`）

新增导出：

```
selectPrefetch({ records, minSimilarity, options })
```

返回 `{ lines, stats }`。`records` 是预取检索打包后的结果，带 `signals`。

**准入**：满足任一条件即可。

1. 词面强：`signals.lexical >= options.minLexical`，默认 0.6。
2. 向量强：`signals.similarity >= minSimilarity + options.vectorMargin`，默认边距 0.10。`minSimilarity` 用 `minSimilarityFor(config)`。
3. 两路一致：同一条记录在两路都命中，且 `lexical >= 0.3`，且 `similarity >= minSimilarity`。
4. 更正优先：`source.changeKind === 'correction'`，且满足 `lexical >= 0.3` 或 `similarity >= minSimilarity`。

**一律不准入**：

- `state.validity` 为 `historical` 或 `disputed` 的条目；
- 正文为空的记录。

**折叠**：按以下规则依次处理，只看已准入的记录。

1. 已准入的当前有效条目（`kind === 'entry'`，`id` 不以 `legacy-note:` 开头，`state.validity === 'current'`），如果它的 `source_refs` 中有某条原话的 `id`，就丢弃那条原话。例外：那条原话是更正（`changeKind === 'correction'`），且时间晚于该条目。
2. 两条记录正文规范化后（去空白、标点，转小写），短的那条被长的包含，或两者汉字二元组 Jaccard 相似度 ≥ 0.7，只保留一条。保留优先级：当前条目 > 旧笔记 > 原话；优先级相同时保留排名靠前的。
3. 被折叠的记录计入 `stats.folded`。

**数量**：最多 `options.maxRecords` 条，默认 3；同时受 `prefetchMaxChars` 约束，默认值改为 1000。保持原有排名顺序。

**统计** `stats`：`{ candidates, admitted, rejected, folded, injected, chars }`，再加上按准入原因的计数 `{ lexical, vector, agree, correction }`。

## B3 配置项（`lib/config.js`）

新增以下配置项，都要做校验，非法值报错，与现有字段风格一致：

| 配置项 | 默认值 | 范围 |
| --- | --- | --- |
| `prefetchMaxRecords` | 3 | 整数 1–4 |
| `prefetchMinLexical` | 0.6 | 0–1 |
| `prefetchVectorMargin` | 0.10 | 0–0.5 |

`prefetchMaxChars` 默认值从 1200 改为 1000。

现有配置文件里没有这几项时，用默认值，不能报错。设置页**不加**新控件。

## B4 标签区分

修改 `lib/memory-query.js` 的 `recordLabel`：

- `id` 以 `legacy-note:` 开头的记录，标签改为 `旧笔记（未迁移） · <类型> · 依据时间 <时间>`。`memory_search` 也会用到这个标签。
- 原话、用户说的、正文以 `？`、`?`、`吗`、`呢` 结尾（去掉末尾空白后判断）的，标签末尾追加 ` · 当时的提问`。

## B5 预取消息的位置和措辞（`lib/index.js`）

追加顺序改为：`[预取（如有）, 回答规则, 淡化策略（如有）]`。这样回答规则离生成位置最近。`pendingMemoryIds`、过期清理和撤权逻辑都不变，要用测试证明下一轮仍能完整清理。

预取正文改为：

```
<memory_prefetch>
以下是程序按本轮用户原话从记忆库预先找到的背景材料，不是用户本轮说的话。
只有本轮问题确实用得上时才参考；与本轮无关就忽略，不要主动提起，也不要回答其中“当时的提问”。
需要核对时用 memory_search。
- [标签] 正文
...
</memory_prefetch>
```

淡化策略消息（`makeControlPolicyMessage`）的处理：

- 改写成中文；
- 删掉已经不存在的 `write_note`、`edit_note`、`move_note` 相关句子。删之前用 `grep` 确认当前 portable 模式下这些工具确实不存在；如果存在，就保留并在回执中说明。
- `dafeiyu_records` 那句的处理方式相同：工具存在才保留。
- 保留核心规则：
  - 只有用户明确要求不再提起或淡化某条记忆时才调用 `soften_memory`；
  - 先定位到唯一目标；
  - 工具成功后才能确认；
  - “别忘了”“我忘了”不算淡化请求；
  - 用户更正时自然回应，由后台整理落盘，不要声称已经写入。

## B6 技术故障的对话措辞

修改 `lib/suzu/search-session.js` 的 `MESSAGES`：

- `BACKEND`、`TIMEOUT`、`PROFILE` 改为告诉模型怎么对用户说。例如 `BACKEND` 改为：`这次没能查到记忆（技术原因已记录在状态页）。回答时自然地说这次没查到相关记录即可，不要提后端、接口、错误码或超时，也不要编造。`
- `PARTIAL` 改为：`部分检索没有完成，以下是已核实的结果；若不足以回答，就说没查到更多记录，不要提技术原因。`

技术细节保持现状：最近检索记录里的 `state`、日志不变。改完后，检查断言这些文本的测试并同步更新。

## B7 预取观测补充

A 批的预取摘要里加入 `stats` 中的 `admitted`、`rejected`、`folded` 和各准入原因计数。全部没准入时，`outcome` 记为 `'gated'`。

## B8 噪声回放测试（新文件 `test/prefetch-noise.test.js`）

用虚构数据建库。可复用 `test/memory-query.test.js`、`test/portable-session-memory.test.js` 里的夹具写法：真实原话库、条目索引和旧笔记目录，向量用可控相似度的假后端。

数据至少包括：

- 一件事同时有原话、对应的当前条目（`source_refs` 指向该原话）、一篇内容相近的旧笔记；
- 一个偏好被更正过：旧条目已变为 `historical`，新原话标记为 correction；
- 一句用户的旧提问；
- 若干无关闲聊。

断言：

1. 无关新话题（例如“解释一下快速排序”）：不注入预取消息；摘要 `outcome` 为 `'gated'` 或 `'empty'`。
2. 明确回忆该事件：只出现一条，是当前条目，没有它的母原话和相近的旧笔记。
3. 问更正后的偏好：出现新值；`historical` 旧条目不出现。
4. 旧笔记单独命中时，标签含“旧笔记（未迁移）”。
5. 旧提问被注入时，标签含“当时的提问”。
6. 寒暄（例如“好的”）：不检索（A 批行为），也不注入。
7. 注入时消息顺序为“预取 → 回答规则”；下一轮过期清理后，上一轮的三类附加消息都不在会话里。
8. `memory_search` 对同一个无关查询仍按原规则返回结果（门槛只作用于预取）。

阈值只按通用规则写，不针对任何具体题目调参。
