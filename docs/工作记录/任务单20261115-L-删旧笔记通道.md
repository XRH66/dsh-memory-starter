# 任务单 L：删旧笔记通道，修"部分完成"误报（2026-11-15）

精简计划第 5 步的一部分，排在 Z 批（去掉整理层）之后。先读 `docs/项目状态.md`、`docs/工作记录/回执20261115-I-继承旧笔记.md` 和 `docs/工作记录/回执20261115-Z-去掉整理层.md`。

## 背景

- 0.3 旧笔记现在有了正式的继承办法：`scripts/inherit-memory.mjs` 把它们搬进原话库，说话人是 `summary`，全文和向量两路都能搜到，`memory_open` 能打开。用户日常库的 70 篇已经导入。
- 同一篇旧笔记现在会从三路出来：
  1. 导入后的原话记录（要保留）；
  2. 旧笔记搜索通道：搜索时直接读 Vault 文件，记录 ID 是 `legacy-note:`（`memory-query.js` 的 `legacy` 通道、`legacyRecord`、`createLegacyNoteReader`）；
  3. 向量索引里的 Vault 笔记文档：`memory-documents.js` 的 `noteDocument` 把 `chats/` 下带 `memory_id` 的笔记做成 `legacy-note:` 文档（domain 为 `fact`）。

  本批去掉第 2、3 路。
- "部分完成"误报：`lib/memory-query-lanes.js` 最后一行把状态不是 `ready`/`empty` 的通道都算成没搜完，其中也包括 `unavailable`（这个来源没有配置或不存在）。基准里没有旧笔记，旧笔记通道总是 `unavailable`，Y、Z 两次 P01 里九成以上的 `memory_search` 结果都被标成 `partial`，并带上"部分检索没有完成……若不足以回答，就说没查到更多记录"。新用户没有旧笔记、或没配向量时每次搜索都会碰到。

## 一、去掉旧笔记搜索通道（`lib/memory-query.js`、`lib/index.js`）

- 删掉 `legacy` 通道和只为它服务的代码：`localLegacy`、`legacyRecord`、`legacyDirectories`、`noteRefs`、`memory_open` 里按 `storage:'note'` 读 Vault 文件的分支、`prefetchPriority` 里 `legacy-note:` 那一档、标注函数里 `legacy-note:` 的分支、各处耗时统计里的 `'legacy'`。
- 搜索只剩原话全文、原话向量和重排。返回给模型的通道状态里不再出现 `legacy`。
- 向量通道过滤掉旧索引里遗留的旧笔记命中（ID 以 `legacy-note:` 开头，或 `anchor.ref.storage` 为 `note`），做法照 Z 批过滤旧条目向量。
- `memory_open` 收到旧的 `note` 引用时，照"来源已变化"返回空结果，不报错。
- `lib/index.js` 预取统计 `prefetchCandidates` 里的 `legacy` 计数一并去掉。
- 标注函数里 Z 批留下的条目分支，如果确认已经走不到，可以一起删；走得到的不动。回执写明删了哪些。

## 二、向量文档不再收 0.3 旧笔记（`lib/memory-documents.js`）

- `directories()` 去掉 Vault 的 fact、event、history 三个目录，保留人设主观笔记的 thoughts、diary 两个目录，以及用户在维护页手选的检索资料。
- `noteDocument` 不再产生 `legacy-note:` 文档：`dafeiyu/` 以外、带 `memory_id` 的笔记一律跳过，即使用户手选了它也跳过（这类笔记应当用继承命令导入，导入后已在原话库里）。其他手选文件照常做成 `document:` 文档。
- 已有用户的向量库里有 `legacy-note:` 文档：升级后不能报错，搜索不能再返回它们，也不能因此把原话重新编码。这些旧文档是在后台核对时清掉，还是留着不读，按现有核对逻辑的实际行为来，回执写明，并写明原话文档数前后不变。
- 原话文档那部分不动。

## 三、旧笔记模块（`lib/legacy-notes.js`）

- 删掉 `createLegacyNoteReader` 和 `readVaultNote`（只有搜索通道和 `scripts/bench-prefetch.mjs` 在用）。
- `parseLegacyNote` 保留，行为不变：继承命令（`lib/inherit/vault.js`）、`lib/vault-files.js`、`lib/raw-rag/fact-priority.js` 都在用。
- `scripts/bench-prefetch.mjs` 去掉旧笔记通道那部分，其余测法不变。
- `memory-note-path.js` 里的函数如果因此没人用了就删，还有人用就留，按实际引用关系定。

## 四、删 `entryRepository()`（`lib/raw-rag/index.js`）

Z 批留下的残留：它访问已经删掉的 `store.entries`，没有生产调用。删掉函数和导出。`raw-rag/index.js` 的其他部分不动。

## 五、修"部分完成"误报（`lib/memory-query-lanes.js`）

- 只有通道状态是 `partial`、`timeout`、`failed`、`cancelled` 时才算没搜完（`degraded`）。`ready`、`empty`、`unavailable` 都不算。
- 查一遍其他会产生 `PARTIAL` 的地方（`lib/suzu/search-session.js` 约 300 行的 `fallback||result.degraded`、预取），确认它们在这次改动后的含义：真正超时、重排来不及而退回草稿、来源变化，这些仍然要标；只是"某个来源不可用"不再标。回执逐条写明。
- 预取的准入门槛和行为除这一点外不变。

## 六、README

"从旧版本升级"一节补一句：从这个版本起，搜索不再直接读 Vault 里的 0.3 旧笔记；升级后先用 `scripts/inherit-memory.mjs` 导入，否则这些旧笔记搜不到；导入不改原文件。README 其他地方如果还说"搜索会读旧笔记"，一并改掉。
