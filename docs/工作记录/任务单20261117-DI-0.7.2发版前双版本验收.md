## 路线

### 第 1 段：自动检查

在 `a668718` 的干净克隆里：Node 24 和 `.local/tools/node-v22.19.0-win-x64` 各跑一次全量测试 `node --test --test-timeout=60000 test/*.test.js`（不加 `--test-force-exit`），`npm run release:check`。记项数和失败数。

### 第 2 段：rc.5 干净安装

1. 新的隔离 DSH 主目录，DSH 用 `0.2.1-rc.5`（可用全局那份的程序，主目录必须隔离；或装私有副本），按 setup.md 第 1～3 步装 `a668718` 的安装包。
2. 打开设置页：未启用时有引导、不显示接口报错；五步向导走完（选临时记忆库目录、勾选"新对话自动打开"、等重启、第 4 步跳过向量、看总结）。
3. 新建对话发一句虚构的生活信息（例如"我上周把阳台的绿萝换成了龟背竹"），确认用户原话和助手回复进入原话库（状态页或原话库接口）。
4. 另开一个新对话问相关问题，模型能用记忆答出（代理日志里有 `memory_*` 调用，或回答里有该信息）。
5. 子对话：在开着记忆的对话里让模型用子代理工具做一件小事，代理日志里子代理请求**没有** `memory_*`；设置页能看到"子对话也能用记忆"且为关。
6. 错误日志里记忆插件报错数。

### 第 3 段：rc.3 干净安装

同第 2 段，DSH 用 `0.2.2-rc.3` 私有副本，端口 8931。先确认使用的 Node 版本满足 24.9 以上并记下版本号。

### 第 4 段：从 0.7.1 升级（rc.5），再升级 DSH 到 rc.3

1. 新的隔离主目录，DSH `0.2.1-rc.5`，装 `v0.7.1` 标签的安装包（本地仓库 `git clone` 后 checkout `v0.7.1` 再打包），走完向导，发一句虚构生活信息，确认入库。
2. 按 `docs/install/upgrade.md` 现有写法和安装说明，把插件换成 `a668718` 的安装包，按「重启约定」重启。核对：旧原话还在、能搜到；设置页配置保留（原话检索、自动预取等开关不变）；新开关"子对话也能用记忆"为关；错误日志无记忆插件报错。
3. 在同一主目录里把 DSH 本体换成 `0.2.2-rc.3`（私有副本，Node 24.9+），重启。核对：插件正常启用（没有 `Trusted agents and sessions services required`、`host-compat` 无法确认归属之类的报错）、旧原话还在且能搜到、新发一句能入库、子对话默认没有 `memory_*`。
4. 记下每一步用户实际要做的操作（命令、点哪里、要不要重启几次），供 Claude 写升级说明"从 0.7.1 升级到 0.7.2"和"升级 DSH 到 0.2.2"。

### 第 5 段：收尾

停掉 8931～8934 和无头浏览器，隔离目录保留，在回执里写路径（用 `<本机临时目录>` 之类占位，不写用户名）。
