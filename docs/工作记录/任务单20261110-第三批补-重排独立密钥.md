# 任务单 2026-11-10 第三批补：重排独立密钥

执行者：Codex。前提：第三批（`任务单20261110-第三批-可选重排.md`）已完成、全量测试通过。硬性要求与第三批完全相同（不调用大肥鱼/DSH、不转交其他代理、不调用真实云端接口、测试只用临时目录与虚构数据、不打印受保护文件、不 commit/push/重启 DSH、只搜 lib test scripts、通用不特调）。

## 目标

重排可以使用**自己的地址和 API Key**，与向量服务完全分开；仍保留“从已保存服务里选一条复用其密钥”的方式。

## S1 保存（`lib/deployment-config.js` 的 `stageDeploymentRerank`）

- `input` 增加 `source:'service'|'direct'`（缺省 `'service'`，兼容第三批）、`apiBase`、`apiKey`。
- `source==='direct'`：
  - `apiBase` 按 `rerankServiceUrl` 的规则校验（HTTPS 或本机回环 HTTP）；
  - 有 `apiKey` 时写入新的密钥文件，目录与权限照 `writeEmbeddingKey` 的做法，但文件名区分（例如 `rerank-<随机>.key`）；`memoryRerankApiKeyFile` 指向它，`memoryRerankServiceId` 清空；
  - 没给 `apiKey` 时：若已有直接密钥且地址没变，沿用；地址变了或从没存过，报“请填写重排服务的 API Key”。本机回环地址允许不填 Key（`memoryRerankApiKeyFile` 为空，请求不带 Authorization 头）。
  - 换新密钥或改回 `source:'service'` 后，旧的重排专用密钥文件删除（只删 `rerank-` 开头、且不被任何配置引用的文件）。
- `source==='service'` 保持第三批行为。
- 配置新增 `memoryRerankSource`（`'service'|'direct'`，默认 `'service'`），照 config.js 三处写法加。
- `readDeploymentSettings` 与返回体只给公开字段：`enabled, source, serviceId, apiBase, model, candidates, hasKey`；不含密钥文件路径、不含密钥。
- `embeddingServiceInUse` 只在 `source==='service'` 时把被重排引用的服务算作使用中。

## S2 运行（`lib/memory-rerank.js`）

- `memoryRerankApiKeyFile` 为空且地址是本机回环时，允许不带 Authorization 头发送；非回环且没有密钥 → `unavailable`，原因“重排密钥不可用”。

## S3 界面（`lib/client.js`，「检索模型」页）

- **页面结构**：「检索模型」页下方分成两个并排的选项卡，左「向量」、右「重排」，点击切换，同一时间只显示一个。
  - 「向量」选项卡：放现有全部向量内容（模型选择、向量服务列表、保存按钮等），行为不变。
  - 「重排」选项卡：只放重排设置（第三批的「重排（可选）」小节整体移到这里），不再出现在向量内容下方。
  - 默认显示「向量」；切换只改显示，不丢失未保存的输入，不触发请求。
  - 选项卡样式照页面现有标签/按钮的写法，选中项有明显区分。
- 在「重排」选项卡里增加单选：「使用已保存的服务」/「单独填写地址和 Key」。
- 选「单独填写」时显示：服务地址输入框（占位 `https://api.siliconflow.cn/v1`，下方灰字“填到 /v1 为止；本机 llama-server 可填 http://127.0.0.1:端口/v1”）、API Key 密码框（已存过时占位“已保存，留空则不变”）。
- 云端确认勾选照旧；保存提示照旧“已保存。重启 DSH 后生效。”
- 「状态」页的“重排：”一行，direct 模式显示服务主机名，不显示密钥。

## S4 测试（加到 `test/memory-rerank.test.js`）

1. direct 保存写入独立密钥文件，内容正确；返回体与 `readDeploymentSettings` 不含 `apiKeyFile` 和密钥。
2. direct 模式不占用向量服务：引用过的向量服务此时可以删除。
3. 换新 Key 后旧 `rerank-` 密钥文件被删除；改回 service 模式后直接密钥文件被删除。
4. 地址改变但没给 Key → 报错；本机回环地址不给 Key 可以保存，请求不带 Authorization 头（假服务器验证）。
5. 非回环 HTTP 地址被拒。
6. 界面：「检索模型」页有「向量」「重排」两个选项卡，默认显示向量；切到重排后显示两个单选项和 Key 输入框，向量内容不显示；重排小节不再出现在向量选项卡里。

全量 `node --test --test-timeout=60000 test/*.test.js` 全部通过；再运行 `node scripts/check-release.mjs`。
