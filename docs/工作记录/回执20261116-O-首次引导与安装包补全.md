## 三项改动

### 1. 未启用记忆时的页面

- `lib/bootstrap-host.js` 新增 `frameworkLoaded` 布尔字段。只有配置对应 `.runtime.json` 的 `pid` 等于当前 DSH 进程、`state === "ready"`、且运行回执指纹与当前配置一致时才返回 `true`；未配置、待重启或回执不匹配均为 `false`。
- `lib/bootstrap-host.js` 新增并导出 `registerLoadedBootstrapRoute(ctx)`。它在已加载态注册同一前缀的只读状态路由：根路径 GET 固定返回 `{ok:true, configured:true, frameworkLoaded:true}`，不调用 `readBootstrap()`、不读档案配置文件；其他方法或子路径返回 409，并沿用 `trusted()` 访问检查。
- `lib/bundle-entry.js` 只增加该函数的 import 和 `startPortable()` 在 `memoryPersonal` 提供成功后的调用。路由挂在子插件 effect 上，已安排启用失败或被清理时会随之撤销，catch 分支仍注册完整首次配置路由。
- `lib/client.js` 改为先请求 `/api/basic-memory-bootstrap`。`frameworkLoaded !== true` 时不再请求任何 `/api/basic-memory-settings/*`。
- 「记忆」页未加载时显示首次配置或待启用说明；已安排启用后明确写“重启 DSH 后生效，生效后再到「检索模型」页配置向量服务”。
- 「检索模型」「状态」「维护」未加载时只显示一段说明和“去「记忆」页”按钮。
- 对话页未加载时显示“记忆未启用”和去设置页准备、启用、重启的指引；按钮禁用，不循环重试。
- 所有 `/api/basic-memory-bootstrap` 与 `/api/basic-memory-settings/*` 响应统经一个 JSON 解析入口；非 JSON 响应只显示中文提示，不再把 `Unexpected token...` 原样交给用户。
