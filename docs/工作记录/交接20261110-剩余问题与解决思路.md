## B. 已知未修

**B1. 上下文压缩后接续可能丢 —— 先只查不改，由 Claude 调查**
- 现状：`lib/index.js:503` 用 `session.deriveMessages()` 里是否还有那条消息来判断旧接续是否有效。插件里没有任何处理压缩的代码，DSH 压缩后模型是否还能看到那条消息未知。
- 做法：读 DSH 的压缩行为（安装位置见 `.local/automation/restart-dsh.ps1` 和记忆里的 DSH 安装位置说明），弄清压缩后那条消息在派生历史里是什么状态。把结论和依据报给用户，再决定修不修。
- 若确认会丢：把「发生过压缩」也算作需要重新注入的条件。不要直接上「隔 N 轮重发」这种会带回重复的规则。

**B2. 0.6B 不能用显卡 —— 只改界面**
- 现状：0.6B 是 `engine:'onnx'`（int8），只支持 CPU；`lib/raw-rag/settings.js` 对它选 CUDA 会报「当前本地后端尚未支持 CUDA 运行设备」。界面上显卡选项是灰的：`lib/client.js:573`（检索模型页）和 `lib/client.js:316`（专家面板）。
- 做法：非 `llamacpp` 的模型不显示显卡选项，并加一句「此模型只用 CPU」。不换后端。

**B3. `test/raw-device.test.js` 显卡回退用例偶发失败**
- 现象：全量跑时失败过一次，单跑通过。
- 猜测（未证实）：测试桩里启动日志用 `setImmediate` 写出，健康检查靠 `await delay(2)` 排在后面（第 40–52 行），机器忙时顺序可能反过来。
- 做法：先把该文件循环跑几十次复现；确认后把桩改成明确的先后顺序。只动测试，不动产品代码。复现不了就如实记录，不要硬改。

**B4. 自定义向量接口（`custom-api`）没用真实服务验证**
- 做法：不付费，用本地 OpenAI 兼容的假服务通过测试注入跑通整条链路（保存设置 → 建索引 → 查询）。现在只接受 https，不要为了测试放宽这条限制。真实服务等用户有 Key 再试。

**B5. 维护页专家面板还是旧流程**
- 现状：检索模型页是「下载 → 保存才启用」；维护页专家面板（`lib/client.js` 的 `RawModelSettings`，约 282–326 行）仍是「准备 → 待切换 → 确认/取消待切换」。
- 做法：专家面板只保留文件路径、线程、超时与等待这些参数，去掉它自己的下载和切换入口，统一从检索模型页走。动之前先确认后端的待切换状态还有没有别的入口依赖。
