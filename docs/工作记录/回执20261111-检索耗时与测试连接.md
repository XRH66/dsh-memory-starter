## 做了什么

### 测试连接

- **测试对象**：向量服务、重排、当前检索模型，各有一个测试按钮。
- **后台执行**：测试在后台进行（`lib/connection-test.js`，路由 `POST /api/basic-memory-settings/test`），用的是和实际调用相同的请求代码。
- **Key 的处理**：Key 不经过浏览器。没有填写新 Key 时，用已保存的 Key：
  - 已保存的服务：用该服务自己的 Key。
  - 当前模型或单独填写的重排：只在地址和模型都没变时沿用已保存的 Key。
  - 本机回环地址：不需要 Key。
- **结果**：一行显示「连接正常 / 连接失败」，附耗时、返回维数和主机名；失败时给一句原因加一句下一步做什么：
  - HTTP 401/403：Key 无效。
  - 404：地址或模型名不对。
  - 429：太频繁或额度不足。
  - 5xx：服务商出错。
  - 网络不通、10 秒超时。
  - 维数不符：会写出实际返回的维数。
- **结果过期**：结果绑定测试时的设置；改了地址、模型或 Key，旧结果自动隐藏。页面只保存 Key 的哈希。
- **防止连点**：同一时间只能有一个测试，第二次点击会返回「上一次测试还没结束」。
- **费用提示**：测云端会发一次很小的请求，按钮的悬停提示里写明可能产生极少费用。
- **状态页「试算／测试连接」**：用当前模型真实算一句话（新增 `profiles.probe`），显示加载时间、编码时间、设备和维数；维数和索引不一致时判为失败。

### 暂停后恢复

- **重排**：调用失败暂停 10 分钟时，状态页显示剩余时间，并提供「恢复使用」（新增 `reranker.resume()`，运行操作 `resume-rerank`）。
- **云端向量**：调用失败后暂停时，当前模型显示「已暂停」，并提供「恢复使用」。它会释放模型，下次检索重新连接。

### 检索耗时

- **记录内容**：每次检索都会记下种类（回答前／模型搜索）、总耗时、向量耗时、重排耗时、找到几条、跳过几条对话里已有的、是否含本地模型加载。
- **结果是否打了折扣**：重排超时或出错、向量没赶上、整次超时，都会记下来。
- **只存在内存**：只保留最近 20 次，不存查询内容和结果，重启后清空。
- **状态页显示两行**：
  - 「检索耗时」：最近一次的耗时和标签（正常／偏慢／打折扣／超时／含加载），小字写明各步耗时和打了什么折扣。
  - 「近 N 次」：中位数、最慢一次、打折扣或超时的次数。含模型加载的那几次不计入。
- **重排用量**：重排一行现在显示本次启动用了多少 tokens。
