### 6.4 给升级说明使用的实际操作步骤

从 `0.7.1` 升级到 0.7.2，记忆数据不需要迁移：

1. 打开 PowerShell，保留当前隔离或日常部署的 `$starter`、`$deploy` 路径。
2. 执行安装说明中的新版本插件命令。候选发布应把引用固定为 `v0.7.2`：

   ```powershell
   dsh plugin --profile web add "github:XRH66/dsh-memory-starter#v0.7.2"
   ```

3. 重启 DSH 一次。命令行启动的，按 Ctrl+C 后在原窗口重新运行 `use-deployment.ps1 -Start` 或原有启动命令。
4. 打开“设置 → 记忆框架 → 记忆”，确认原开关不变，并确认“子对话也能用记忆”默认为关。
5. 搜索一条旧原话，再新建会话发一条虚构内容，确认可检索并正常入库。

再升级 DSH 本体到 0.2.2：

1. 先确认 Node 为 `24.9` 或更高：

   ```powershell
   node --version
   ```

2. 停止当前 DSH。命令行启动的按 Ctrl+C；不要停止不认识的进程。
3. 安装新宿主：

   ```powershell
   npm install --global @deepseek-ai/dsh@0.2.2-rc.3
   dsh --version
   ```

   如果用户使用私有 DSH 副本，则把全局安装改成对该副本的 `npm install --prefix <DSH 主目录> ...`，不要同时改两套。

4. 用原来的部署和原来的端口重新启动。安装说明默认仍使用 8931 端口，因此正常不需要重新配置记忆库。
5. 打开原来的登录入口，确认：
   - “记忆框架”已加载，没有服务缺失或兼容性报错；
   - 旧原话仍能检索；
   - 新会话能继续入库。

本批实测的稳妥顺序是两次独立重启：先换插件并验证，再停服升级 DSH 并验证。未测试“插件和 DSH 一起安装后只重启一次”的合并流程。

## 8. 发现

### 8.1 发版包缺少原话历史文件

复现：

```powershell
# 在 a668718 的干净克隆中
npm ci
npm pack
tar -tf <生成的 tgz>
```

结果：

```text
包内条目数：105
package/lib/host-compat.js：存在
package/lib/raw-rag/history.js：不存在
package/scripts/raw-memory.mjs：不存在
```

安装后与候选源码逐文件比较：

```text
候选 lib/ 文件：85
安装后 lib/ 文件：84
同路径哈希不一致：0
安装包缺失：lib/raw-rag/history.js
```

原因在 `package.json` 的 `files` 白名单：没有 `lib/raw-rag/history.js`，也没有 `scripts/raw-memory.mjs`。`npm run release:check` 仍通过，因此该检查没有覆盖“已跟踪能力文件是否进入 npm 包”。

影响：本轮安装后的聊天记忆、全文检索、跨对话回忆和子代理隔离均正常；但安装包不包含原话会话历史补导入口，也不包含能处理 rc.5/rc.3 会话格式的原话历史实现。若 0.7.2 需要把这项修复交付给用户，发布前必须先补入包并增加包内容检查。按任务要求，本次未修改 `package.json` 或实现。

需要 Claude 决定：

1. 是否把 `lib/raw-rag/history.js` 和 `scripts/raw-memory.mjs` 加入 `package.json` 的 `files`。
2. 是否在 `release:check` 增加“关键已跟踪文件必须存在于 `npm pack` 产物”的检查。

### 8.2 端口切换会造成浏览器认证和向导跳过标记失效

隔离验证中，rc.5 使用 8933，升级后按规范把 rc.3 换到 8931。浏览器认证和“先跳过向量”的本地存储都按来源隔离，因此新端口首次访问出现 403，重新使用宿主日志中的一次性登录入口后恢复；设置向导也因本地跳过标记不在新来源而再次显示第 4 步。

这是验证通道的端口切换现象，不属于服务端数据或插件兼容缺陷。正常用户按安装说明继续使用 8931，不换端口时没有产生此现象。若以后支持用户改端口，升级说明可补充“重新打开新入口，必要时在向导第 4 步再次跳过”。

### 8.3 既有测试自动化脚本仍不能直接解析界面追加的 YAML

`.local/automation/clean022-model.mjs ensure` 仍只接受从首个 `[` 开始的纯 JSON，而界面保存会向 `cordis.patch.yml` 追加合法 YAML 条目。本批新增 `.local/automation/release072-normalize-patch.mjs`，在每次调用既有 `ensure` 前把隔离配置归一化为 YAML 序列的 JSON 表示。产品行为未受影响；是否另开任务修复旧测试脚本，由 Claude 决定。
