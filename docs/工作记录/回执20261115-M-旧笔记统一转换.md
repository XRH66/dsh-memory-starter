## 命令行

- `check`／`apply` 在既没有 `--vault` 也没有 `--file` 时，使用 `deploymentConfig` 算出的 `ownerDirectory/vault`。
- 同时给 `--vault` 和 `--file` 会报错；`--include-derived` 用于 `--file` 或非 `check`／`apply` 命令也会报错。
- 默认 Vault 和显式 `--vault` 都走同一个转换器；从默认 Vault 导入时，批次来源仍记为 `vault`，不会误记为文件导入。
- `apply` 成功输出新增 `indexingNotice`，提示到「状态」页点「准备索引」（或重启），并说明全文检索不需要等待向量。
- `list`、`undo`、`restore` 的行为未改。

## 发现与取舍

- `check` 不执行任何写 SQL。SQLite 没有待处理 WAL／回滚日志时，先用文件 URI 的 `immutable=1` 只读打开，避免 Node 的普通只读连接生成旁文件；有未检查点的活动 WAL 时，为保证预览看到最新记录，只能使用普通只读连接，SQLite 可能维护 `-shm` 旁文件。这是 Node `node:sqlite` 在不复制数据库、不执行检查点的前提下的限制；测试同时覆盖了“零写入快照”和“活动 WAL 可见”两种情况。
- 条目文件头解析继续复用现有 `parseLegacyNote`，没有在 `lib/legacy-notes.js` 内扩大 YAML 支持范围；本批真实生成格式均可解析。未来若出现旧版手写嵌套 YAML，仍会按文件头无法解析跳过并列出原因。
- 固定主题页、条目旧版存档和对话整理条目都进入 `conversionSkipped` 供核对，但 `errors` 仍为空，不影响 `check` 成功状态。
- 待确认的整理结果只在旧数据库，按任务单没有读取旧数据库，也没有新增这一导入来源。
- 本回执是本机工作记录，不列入 `release-files.json`；没有新增其他发布文件。

## Claude 复核（2026-11-15）

逐项对照任务单核对了转换规则、命令行和两份文档，夹具与 `v0.6.0` 的 `renderNote`、`memoryEntryMetadata`、条目正文标记、`TOPIC_LINE_PREFIX`、主题页固定内容、旧版存档写法一致。0.4～0.6 的整理器对 0.3 笔记只做"加强"（改优先级字段），不会把 0.3 笔记改写成条目，所以不存在"半新半旧"的文件。`check` 用不可变只读方式打开数据库的做法，在 Node 22 和 24 上实测都能读到数据、不留附属文件，保留。

**复核时补改四处：**

1. **首次配置页生成的配置文件没有 `ownerSubject`**（`lib/bootstrap-host.js` 只写 `ownerDirectory`、`socialRoot`、`dshHome`、`dshSessionIds`），运行时这时默认用"用户"，继承命令却直接报错，公开安装的用户根本用不了。改为和运行时用同一个默认值：`lib/config.js` 新增 `DEFAULT_OWNER_SUBJECT`，`lib/platform-host.js` 和 `lib/inherit/cli.js` 共用。
2. **没开向量检索时 `apply` 拒绝导入**。全文检索和 `memory_open` 直接读原话库，不需要向量，所以改为照常导入、跳过编码（`indexing.reason` 为 `vectors-off`），提示改成"以后开启向量检索并点「准备索引」时会一并编码"。
3. **条目的记录编号改用条目自己的 `memory_entry_id`**（没有时才用相对路径），与 11-14 的继承标准一致。用路径的话，用户在 Obsidian 里改了文件名再导入，会多出一份。0.3 笔记和主题页仍用相对路径，日常库已导入的 70 篇不受影响。
4. **文档**：README 和 `docs/install/upgrade.md` 写明 `<配置文件>` 是 `<DSH 主目录>/profiles/<档案名>/basic-memory-bridge/configuration.json`，补上没开向量检索也能导入，理顺了几处句子。另外从 `release-files.json` 移除了 Z 批误加的工作记录（`回执20261115-Z-去掉整理层.md`），工作记录不进发行包。

新增用例"首次配置的配置文件没有所有者也没开向量时照常导入，条目改名后不重复导入"（`test/inherit-cli.test.js`）；两条断言从路径改成条目编号（`test/inherit-vault.test.js`）。

**留给以后：**插件选项里单独设了 `ownerSubject`、配置文件里没有的部署，继承命令仍会用默认值，目前没有这种公开用法；导入记录的 `tags`、`conversation`、`order` 只做格式检查、不保存；`docs/install/setup.md` 的三处过时说法（见上文）留到发版前改文档时一起处理。
