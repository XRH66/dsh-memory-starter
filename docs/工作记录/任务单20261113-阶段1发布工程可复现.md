# 任务单：阶段 1 发布工程可复现

日期：2026-11-13

## 目标

让公共仓库的发布检查可以从源码稳定复现，防止白名单再次漏文件，并对齐 npm 包内容、依赖锁定和第三方版本声明。

## 修改范围

允许新增或修改：

- `scripts/check-release-export.mjs` 或同等职责的新脚本
- `test/release-check.test.js`（发布脚本元数据校验回归）
- `test/package-files.test.js`（npm 包内容与自包含性回归）
- `scripts/check-release.mjs`、`scripts/check-links.mjs`（仅在复用确有需要时）
- `package.json`
- `package-lock.json`
- `README.md`
- `NOTICE.md`
- `.github/workflows/*`
- `release-files.json`（仅登记新增的发布脚本和回归测试）

不要修改：

- `lib/`、`test/` 下的现有运行代码和测试
- `release-files.json` 其余既有内容
- `docs/项目状态.md`
- 本阶段以外的安装器、前端和检索逻辑
- 其他工作记录、版本号和标签

## 实现要求

1. 新增正式的发布导出与校验命令，例如 `npm run release:check`：
   - 读取 `release-files.json`；
   - 在白名单文件缺失时明确失败；
   - 将白名单文件导出到系统临时目录；
   - 导出子进程使用临时 HOME／APPDATA／TEMP，清除 `GIT_*`、Git／SSH／代理凭据和常见 npm 凭据环境，只恢复发布检查自己的安全配置；
   - 导出目录安装依赖时禁用 npm 生命周期脚本；
   - 在导出目录运行全量测试、发布隐私检查和链接检查；
   - 临时依赖处理不得把仓库外真实数据、凭据或本地未跟踪资料带入导出；
   - 命令结束后清理其自建的临时目录。
   - 同时提供 `--validate-only`，让提交前可以先验证白名单路径、Git 跟踪状态和代码文件完整性。
2. 新增白名单完整性检查：
   - `release-files.json` 中每个文件都必须被 Git 跟踪；导出目录没有 Git 元数据时明确提示并跳过该检查；
   - `lib/`、`scripts/`、`test/` 下所有被 Git 跟踪的代码文件，必须出现在 `release-files.json`，或出现在脚本中显式的排除表；
   - 排除表项必须有原因；
   - 当前已知需要排除的仓库维护文件按实际用途明确登记，不能静默忽略。
3. 修正 README 中“在新克隆直接运行 `npm run privacy`”的错误口径，改为指向新的导出校验命令。
4. 核对 `package.json` 的 `files` 字段，补入缺失的 `scripts/install/`，并确保 npm 包内容与 `release-files.json` 的差异是有意的。
   - npm 运行时包必须包含 `NOTICE.md`、第三方许可证、补丁清单和补丁资源；
   - npm 包中不得包含未跟踪的本地资料；
   - Suzu 许可证复制到 `third-party/`，npm 包不再引用包含本机未跟踪资料的 `vendor/suzu-memory/` 目录；
   - `npm pack --dry-run` 的结果必须由回归测试核对。
5. 处理 `package-lock.json` 中公开开发依赖的 `git+ssh`：
   - 优先改为可在无 GitHub SSH 凭据环境中使用的 HTTPS 或等价方案；
   - 若 npm 会强制写回，保留可验证证据，并在 README 写明无 SSH 环境的规避方法；
   - 不得提交真实凭据。
6. `NOTICE.md` 的 `zod` 版本对齐当前锁文件：顶层为 `4.6.6`，DSH rc.5 嵌套为 `4.4.3`；说明版本差异和不在当前阶段单独升级 DSH 依赖的边界。
7. 新增最小 GitHub Actions 工作流：
   - Node 版本与 `package.json` 的 engines 兼容；
   - 执行 `npm ci`；
   - 执行全量测试和新的发布导出校验；
   - 不需要模型、记忆库、DSH 或任何秘密。
8. 不向 `release-files.json` 添加本任务单、README 之外的本地工作记录或新脚本以外的文件，除非它是发布运行所必需。

## 验证

```powershell
npm test
npm run release:check
node .local/automation/check-tracked-privacy.mjs --worktree
git diff --check
```

若新命令在 Windows 上因临时目录占用失败，必须保留现场并报告具体路径与错误，不得改为静默跳过测试。

## 边界

- 不推送、发布、打标签、部署或重启 DSH。
- 不调用模型接口、DSH 或大肥鱼。
- 不升级 DSH，不改现有运行依赖版本。
- 不修改或暂存其他未跟踪本地资料。
- 保留无关工作树修改。
