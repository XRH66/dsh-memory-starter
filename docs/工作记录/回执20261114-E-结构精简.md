## 一、统一原子写入

新增 `lib/atomic-file.js`：

- `writeFileAtomic(file, data, options)` 在同目录创建临时文件，支持 `flag`、`mode`、`encoding`、`fsync`、隐藏临时名和改名前的 `beforeRename` 判断。
- 改名遇到 `EPERM`、`EACCES`、`EBUSY` 时沿用原重试值：最多 6 次统一尝试，前 5 次失败后依次等待 30、60、120、240、480 毫秒。
- 失败时清理临时文件，并抛出当前原始错误；清理错误不会覆盖写入错误。
- `writeJsonAtomic` 通过 `space` 和 `trailingNewline` 保留各调用点原有 JSON 字节格式。
- 下载续传的 `.part` 改名、损坏文件隔离改名和 Vault 移动改名均未并入。

## 四、`lib/client.js` 评估

现状：150,437 字节、1,295 行，外层是一个 `window.__ModuleLoader__.load` 注册块，内部 `factory` 只向宿主请求 `react`。按现有职责可分为 7 块：

| 候选块 | 行数 | 字节 |
| --- | ---: | ---: |
| 入口、样式与共享工具 | 181 | 20,750 |
| 对话开关与基础设置 | 118 | 19,670 |
| 模型准备与运行设置 | 250 | 30,422 |
| 维护页组件 | 246 | 24,340 |
| 重排与模型选择 | 347 | 36,596 |
| 页面组合 | 118 | 15,975 |
| 注册入口 | 35 | 3,961 |

拆分时不能直接改成普通 ES 模块：现有测试和宿主入口都按单个 `window.__ModuleLoader__.load({factory})` 执行，测试里的 `require` 也只接受 `react`。低风险方案是新增构建步骤，把源码模块重新打包成单一 `lib/client.js`；若直接拆成多个宿主模块，则要先确认 DSH 加载器支持包内相对模块或稳定模块 ID，并同步 `package.json`、`release-files.json` 和测试加载器。

保护测试至少包括：

- 现有设置页、对话页头和设置页尾注册树的完整渲染与交互测试。
- `memory-rerank.test.js` 对应的重排设置与状态页测试。
- 模型切换、异步保存失败、权限变化和对话框状态测试。
- 只注册一次 CSS、设置区和两个对话槽位，避免拆分后重复副作用。
- 打包后从入口加载全部模块的测试，以及模块缺失时的明确错误测试。

估计工作量：走打包方案约 2 至 3 人日；直接改 DSH 多模块加载方式约 4 至 5 人日，主要风险不在搬代码，而在宿主加载契约、重复副作用和 UI 回归测试。
