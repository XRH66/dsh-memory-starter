# 预取证据回放评测方案（2026-11-13）

目的：在**不跑答题模型**的前提下，量化 B 批门槛的影响，回答两个问题：该带的证据是否还在，不该带的噪声是否减少。阈值依据数据确定，不靠拍脑袋，同时防止对着题目调参。

## 依据

基准判分材料 `grading-kit/grading/evidence.jsonl` 覆盖全部 714 题。每题都标注了：

- 事实（`facts`）；
- 证据所在的轮次（`evidence_turns`）；
- 原话引文（`sources`）。

因此可以直接判断预取注入的每一条，是否来自证据轮次。不需要答题模型，也不需要判分模型。

## 做法

1. **按截止轮增量回放。** 每个人物的历史按轮写入一个临时原话库，只用虚构的基准数据，不碰真实记忆库。题目按 `cutoff_turn` 排序。回放到某题的截止轮时，对该题做一次检索。截止轮之后的历史不会提前出现在库里。
2. **向量通道**用与日常相同的 `BAAI/bge-m3` 接口，保证向量阈值的量纲和日常一致。需要密钥文件路径时，由 Claude 在运行时传入；脚本不打印密钥，不读其他部署配置。2346 轮历史只需编码一次，费用很低。
3. **每题跑三种口径**：
   - **旧预取**：门槛关闭，只保留 A 批的速度改动，相当于 B 批之前的行为。
   - **新预取**：B 批门槛和折叠规则。
   - **工具检索**：`memory_search` 取前 10 条，作为"这道题能找到证据"的上限参考。
4. **第一期只含原话和向量。** 结构化条目需要整理模型生成，是付费的冷启动，第一期不做。如果第一期结果需要验证"条目和原话折叠"的效果，第二期再对少量人物做按截止轮整理。

## 指标

| 指标 | 定义 |
| --- | --- |
| 证据命中率 | 预取注入中至少有一条出自 `evidence_turns` 的题目占比 |
| 证据保留率 | 旧预取命中的题目中，新预取仍命中的占比（**核心指标**） |
| 非证据占比 | 注入的条目中，不出自任何证据轮次的占比（噪声的近似值） |
| 空注入率 | 不注入的题目占比；单独统计"历史中根本没有证据的题" |
| 平均注入字数 | 衡量上下文开销 |
| 预取耗时 p50 / p95 | 只看本地开销，向量接口的网络耗时单独列出 |
| 上限差距 | 工具检索能命中、但预取没注入的题目占比 |

"非证据"不完全等于"无关"，有些条目虽然不是标注证据，但对回答有帮助。所以它只作为相对比较用：同一套数据下，新旧预取比高低。

## 召回诊断（同一次回放顺带产出）

每道"工具检索也没命中证据"的题，记录以下信息（只记编号、数字和枚举，不记正文）：

- 证据轮次的原话是否在库里；
- 文字通道是否命中证据，名次多少；
- 向量通道是否命中证据，名次多少，相似度多少；向量通道是否超时；
- 查询分词后的检索词数量。

按"文字漏、向量漏、两路都漏、超时"四类汇总。改进召回时，先看哪一类最多，再针对那一类做通用改进，例如同义改写、时间词处理、通道超时。不对单题调整。

## 上下文组装测量

同一套回放中，对每道题记录一次完整请求的构成，只记估算 token 数，不记正文：

- 系统提示；
- 人设；
- 工具定义（逐个工具）；
- 短期接续；
- 预取；
- 回答规则；
- 淡化策略；
- 历史消息。

目的是拆清此前多出的约 12.5k 输入来自哪里，并找出重复内容。已知一处重复：回答规则同时写在 `memory_search` 的工具说明里和每轮附加的规则消息里。

## 阈值怎么定（防止特调）

- 只在粗网格上选：
  - `prefetchMinLexical` 取 {0.4, 0.5, 0.6, 0.7}；
  - `prefetchVectorMargin` 取 {0.05, 0.10, 0.15}；
  - `prefetchMaxRecords` 取 {2, 3, 4}。
- **P01–P03 用来选，P04–P06 用来验。** 选择规则固定为：在证据保留率 ≥ 97% 的组合里，选非证据占比最低的；如果并列，选平均注入字数更少的。
- 选出的组合在 P04–P06 上，证据保留率也要 ≥ 95%。否则说明规则本身不通用，需要回到设计上找原因，不能继续缩小网格去凑数。
- 阈值只能取网格上的值，不按单题结果微调。

## 之后的答题验证

1. 阈值定下后，跑一次 P01（88 题）做答题级别的确认。按以往记录，约 2 小时、4–5 元。分数不低于旧基线（DeepSeek 判分 62/88）就通过。
2. A–F 批全部完成后，再跑 714 题全量，作为新基线。

## 实施

评测脚本写成 `.local/benchmark-cmb/prefetch-replay.mjs`，属于本机私有工具，不进入发行包。B 批提交后，作为 R 批任务交给 Codex 实现。Claude 负责运行和解读结果。

## R 批结果与门槛决定（Claude，2026-11-13）

- 正式题库的人物是 P01、P12、P14、P16、P17、P20，本方案原写的 P01–P06 不存在；R 批照实报告"无法分组选择"，没有私自替换。改为选择组 P01/P12/P14、验证组 P16/P17/P20。
- 召回：工具检索前 10 条命中证据 96.4%；预取总耗时 p50 358 毫秒、p95 550 毫秒（含真实编码和重排往返），没有超出 1.3 秒的检索预算。
- 绝对重排门槛分不开证据和噪声（证据 p25 为 0.19，非证据 p75 为 0.20）。改用"下限 0.02 + 本题最高分 × 0.5"的相对门槛，最多 3 条：离线模拟选择组保留率 97.9%、验证组 96.0%，非证据占比与现行 0.35 门槛相当。由 M 批实施，并用真实 `selectPrefetch` 复算确认。
- 上下文：每回合固定附加约 1211 token，其中回答规则 290、工具定义 921（`memory_search` 说明 463，重复了规则）。M 批精简，并让规则跟着记忆材料走。
- 局限：回放没有结构化条目，也没有闲聊轮，"不该注入时不注入"只能从 13 道"应答不知道"的题看出一点（新门槛下 10 道仍有注入）。闲聊轮的注入率等 N 批正常测评时观察。
