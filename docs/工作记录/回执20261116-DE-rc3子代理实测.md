## 4. 子代理原话处理

隔离原话库 `memory-check/management/raw-recall/raw-recall.sqlite` 只读查询：

- 关闭记忆的正式根会话：`raw_messages=0`。
- 开启记忆的正式根会话：`raw_messages=4`，角色为 user 1 条、assistant 3 条。
- 开启记忆的正式子会话：`raw_messages=0`。
- 4 条根会话记录的数据库 `session_id`、`core_json.sessionId` 和授权记录 `sessionId/rootSessionId` 都指向正式根会话。

这与现有设计一致：

- `lib/session-memory.js` 的 `admitMessage()` 要求当前 agent 本身是根代理。
- `directMessageSource()` 只接受 `rootSessionId === sessionId` 的来源。
- 现有测试 `message recording excludes synthetic context, inherited history and owned child output` 已固定“子代理输出不入原话库”。

因此，本轮子代理取得记忆读取权限，但不贡献新的原话记录；需要 Claude 决定这是否就是本任务期望的“按设计处理”。

## 7. 发现和需要 Claude 决定

1. 子代理原话当前不会进入原话库，只有根会话的 user/assistant 原话入库。代码和测试都把这一行为当作既有设计。若任务要求把子代理输出也保存到根会话，需要另开任务单，本批未改代码。
