## 改动

### 统一读取规范化

`lib/raw-rag/store.js` 新增并导出 `canonicalTurnId(value)`：只把字符串中的旧 NUL 分隔符替换为 `\u001f`，其他类型和内容保持不变。

新增 `sameSourceVersion()`，把旧、新两种 `sourceVersion` 中的转义分隔符视为同一来源版本。`sourceVersion()` 对外保持稳定的旧式转义表示，使迁移前写入的向量文档修订和 Vault 来源版本仍能匹配，避免把同一正文误判为改版。

### 入口清单

| 入口 | 处理位置 |
| --- | --- |
| 默认编号构造、显式写入 | `buildTurn`、`archiveTurn` 先规范化 |
| 按编号读取正文 | `loadTurns`、`storedTurn` |
| 导入可见性与进度 | `markImportedVisible`、`saveProgress` |
| 来源状态复核 | `sourceState` 中 `ref.turnId`、版本比较和身份比较 |
| 回合控制项 | `setControl`、`getControl`、`refreshControl` |
| 删除回合及投影 | `removeTurn` |
| 已审阅作用域视图 | `getLegacyScopeView`、`setLegacyScopeView`、`clearLegacyScopeView` |
| 分块与向量落库 | `putChunks`、`putVectors` |
| 向量打开、邻接与嵌入上下文 | `query-reader.js` 的 `get`、`neighbors`、`embeddingContext`；旧锚点保留原 `revision` 参与向量文档核验 |
| 旧原话分页游标 | `query-reader.js` 的 `legacyPage({after})` |

`memory-documents.js`、`history.js`、`raw-rag/index.js` 未改动。旧向量锚点由 read adapter 在查库时解析，不靠改写持久化锚点。

### 迁移安全性

- 整个迁移仍在 `BEGIN IMMEDIATE` 事务中执行，标记 `turn-id-v2` 只在全部更新成功后写入。
- 任一步失败会整体回滚并关闭数据库连接，不留下半迁移状态；下次打开会重试。
- 标记已存在时直接跳过迁移。测试在标记存在后安装会拒绝 `turns` 更新的触发器，重开仍成功，证明没有重复执行。
- 迁移前先从 BLOB 读取完整旧编号，避免 Node 22.19.0 文本绑定截断内嵌 NUL。

### 主键冲突处理

迁移前先检查 9 张 `turn_id` 表及回合控制项的复合主键冲突。

- 规范新编号行已经存在时，新编号行保持为正常权威来源。
- 旧编号行不会被覆盖或删除，而是改名为确定性的隐藏隔离编号：`\u001fmigration-conflict\u001f<旧编号哈希>`。
- `turns`、8 张关联表、回合控制项和相关投影统一使用该隔离编号；`turn_visibility.excluded` 设为 1，避免隔离正文继续参与检索。
- 冲突旧行的正文、分块、向量、消息映射、导入成员、控制项和已审阅视图记录都保留。隔离行的 scope view 可能显示为 stale，但记录本身不删除。
- 同一旧编号跨表保持同一个隔离编号，并检查目标编号是否已被占用。

## 回退影响

0.5.0 和 0.6.0 均按旧 NUL 分隔符构造默认回合编号，也没有新读取规范化或 `turn-id-v2` 迁移。迁移到新编号后回退旧版本，影响如下：

- 历史重新导入：旧代码按 NUL 编号查 `storedTurn`、进度和控制项，找不到已迁移的 `\u001f` 行，可能重复插入或在后续升级时形成主键冲突。
- 回合控制：`--turn`、按回合排除/加权会写入或查询旧 NUL ID，不能命中已迁移行；消息级控制仍可能通过消息 ID 工作。
- 作用域视图：旧库内已迁移视图的 `turn_id` 是 `\u001f`；旧代码直接使用返回行编号时仍可读取，但自行重建 NUL 编号时会失配。
- 向量档案：原始向量表已随原话库迁移；`documents.json` 与 `vectors.sqlite` 中的旧 NUL 锚点会被旧 `loadTurns` 直接查库而找不到，普通向量命中可能消失，重新准备时可能被当作来源变化。
- Vault 来源追踪：含旧 `turnId` 的 `raw_ref` 无法命中新编号；仅含消息 ID 的来源通常不受影响。
- 混合写入：回退期间新写入的 NUL 行可与现有 `\u001f` 行并存；如果 `turn-id-v2` 标记仍在，再次升级会跳过迁移，不会自动进入隔离冲突处理。旧代码写入的 NUL 行仍留在库中，读取入口按规范编号解析，不能假设混合数据会自动收口；若需要跨编号格式回退，应先使用单独的原始库回退点，回退后不要直接依赖新版本的自动隔离。

影响属于中到高，主要落在历史幂等、回合控制、旧向量命中和来源追踪。建议部署本次迁移前，单独复制一份原始原话库文件作为版本专属回退点；现有通用备份不能替代这次跨编号格式回退点。本任务未执行复制。
