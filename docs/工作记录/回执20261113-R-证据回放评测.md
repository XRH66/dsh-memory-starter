## 发现

1. 任务单和方案写的是 `P01–P03` 选择、`P04–P06` 验证，但正式题库 manifest、题目和历史实际只有 `P01/P12/P14/P16/P17/P20`。脚本检测到缺失后没有替换人物，阈值选择状态如实记为“不可执行”。
2. 当前默认门槛没有达到证据保留目标；216 组网格也没有任何组合达到 97%。这说明需要由后续 M/T 批重新审视门槛、证据候选上限或回放口径，不能直接宣称现有阈值已收口。
3. 统一向量查询返回的原话在 `records` 中经常只有 ID、正文、角色和时间，`source` 字段为空。回放器用同一原话库按记录 ID 补回准确 `source.turn` 后再判证据；补字段只用于测量，不改变预取选择。该元数据缺口可能影响日常按当前轮次/可见消息排除，建议另开任务核查。
4. 714 题中 `vector: partial` 710 题，主要来自向量候选达到 120 条扫描上限；旧笔记通道因本回放不建旧 Markdown 而 714 题均为 `unavailable`。工具状态 712 题为 `budget`、2 题为 `partial`；这些不是接口失败，但说明工具结果仍受输出预算限制。
5. 后台整理按任务要求关闭，所以结构化条目通道 714 题均为空。本批不能验证“条目与原话折叠”，也不能代表日常有整理条目时的最终降噪效果。
6. 有 13 道题同时含截止前和截止后的证据轮次。按任务单“存在证据轮次大于截止轮即归入应答不知道”的口径，这些题已单列，注入全部计噪声。
