# 任务单 Q：本地向量模型改为可选（2026-11-15）

精简计划第 5 步的一部分（项目状态「下一步」第 3 项后半），在独立工作区 `<工作区 q>` 做，与任务单 P（人设笔记清理，工作区 `<工作区 p>`）同时进行。先读 `docs/项目状态.md`、`docs/工作记录/审计20261114-整体结构与冗余.md` 第四、七节。

## 背景

- 用户 11-14 定：本地向量模型降为可选组件，默认不用。默认只走云端向量和重排接口。本地下载、Python 编码进程、常驻时段、按本地型号分档案这些移到可选部分，新用户的默认路径里不再出现。**已经装了本地模型的用户升级后照常可用，不能被悄悄关掉。**
- 现状：
  - `lib/config.js` 的默认模型 `rawRecallModel` 是本地的 `BAAI/bge-small-zh-v1.5`（`fastembed` 引擎，要 Python）。新用户打开"原话检索"后如果不去「检索模型」页另选，用的就是它，没下载时向量不可用。
  - 「检索模型」页（`lib/client.js` 约 600～940 行）的模型下拉框先列"本地运行"再列"云端 API"。本地模型有 4 个（BGE-small/fastembed、Qwen3-Embedding 0.6B/ONNX、4B 和 8B/llama.cpp），各带下载、设备、常驻时段、线程等选项。
  - 只为本地模型服务的代码约 70KB：`lib/raw-rag/install.js`、`install-files.js`、`install-catalog.js`、`install-download.js`、`local-backends.js`、`embed_worker.py`、`assets.js`，以及 `backend.js`、`client.js`、`deployment-config.js`、`settings-host.js` 里的相关部分。`backend.js`、`settings-host.js`、`deployment-config.js` 现在都是静态导入这些模块。
  - 重排只有云端（`memoryRerankSource` 为 `service` 或 `direct`），本批不改重排的行为。
- 用户日常用的是云端：硅基流动的 `BAAI/bge-m3` 加 `BAAI/bge-reranker-v2-m3`，基准测试也是。

## 一、默认改为云端，已有用户不变

1. **新用户**：配置里没写模型、也没装过本地模型的，打开"原话检索"后模型是云端的"自定义 API（OpenAI 兼容）"（`custom-api`）。没填地址和密钥时向量不可用，全文检索照常，状态页和"原话检索"开关旁的提示说清楚"去「检索模型」页填云端向量服务"，不再提"下载模型"。
2. **已有用户**：
   - 配置里明确写了本地模型的，升级后模型不变、照常可用；
   - 配置里没写模型、但实际在用默认本地模型的（有安装回执 `rawRecallInstallReceipt`，或已有这个模型的向量档案），升级后也必须仍是原来的本地模型。
   
   先查清 0.4～0.6 各版本写配置时会不会省略 `rawRecallModel`（用 `git show v0.4.0:<文件>` 等查看），再决定怎么认出"在用默认本地模型"的老用户。做法写进回执。不允许因为改了默认值，把老用户悄悄换成没配置好的云端。
3. 不改 `rawRecallApiBase` 等云端字段的默认值（已有用户可能依赖它们）。推荐的云端示例只出现在界面提示和文档里：硅基流动，地址 `https://api.siliconflow.cn/v1`，向量模型 `BAAI/bge-m3`，重排模型 `BAAI/bge-reranker-v2-m3`。
4. "我知道检索内容会发送到云端，并会产生费用"这个确认保留，和填地址、密钥放在同一块里。没勾选不能保存云端模型，这个行为不变。

## 二、「检索模型」页：本地模型收起来（`lib/client.js`）

- 模型下拉框默认只列云端模型；页面上有一块默认折叠的"本地模型（可选）"，说明"需要下载模型文件、占用本机内存和显卡，离线可用"。展开后下拉框里才出现本地模型。
- 当前用的就是本地模型时，这块自动展开，下载、设备、常驻时段等选项照旧可用。
- 状态页、维护页里只和本地模型有关的内容（下载进度、设备、线程、常驻时段、"检索模型的文件、线程与等待时间（专家）"），在当前不是本地模型时不显示。
- 其余页面布局和文案不动。

## 三、本地模型代码集中、按需加载

- 只为本地模型服务的模块挪到 `lib/raw-rag/local/`：至少 `install.js`、`install-files.js`、`install-catalog.js`、`install-download.js`、`local-backends.js`、`embed_worker.py`；`assets.js` 如果只为本地服务也挪过去。云端和本地共用的（`models.js`、`settings.js`、`embedding-http.js` 等）留在原处。
- 插件启动、检索、云端编码这些运行路径不再静态加载 `lib/raw-rag/local/` 下的模块：
  - `backend.js` 在选了本地引擎时才动态加载本地传输；
  - `settings-host.js` 收到本地安装相关请求时才加载安装器；
  - `deployment-config.js` 只在需要检查本地安装时才加载。
  
  实在不能按需加载的地方，写进回执说明原因。
- 本地模型的代码仍随插件一起发布（`package.json` 的 `files` 和 `release-files.json` 改成新路径），不从发行包里拿掉。
