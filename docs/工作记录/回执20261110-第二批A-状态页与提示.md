## A1：状态页显示向量检索和整理状态

### 做了什么

- 「状态」页现在在运行状态之后、人工审核之前显示 `MemoryRuntimeSettings`，并传入当前实际生效模型和对应的云端标志。

- 原专家面板里的运行状态组件已移除；维护页独立的 `showVectors:false` 实例已移除。
- 旧任务接续、最近优先整理及旧任务恢复回执不再依赖 `showVectors:false`，因此会继续显示在状态页。

## A2：检索模型页保存后真的会切换，提示准确

### 做了什么

- `ModelPicker` 保存前比较所选模型与当前实际生效模型。
- 自定义 API 额外比较地址、服务模型名和维数；只有模型/服务身份变化时才发送 `confirmSwitch:true`。
- 云端模型发生切换时同时发送 `cloudConfirmed:Boolean(rawRecallAllowCloud)`。
- 只修改常驻、设备、线程或等待时间等参数时不发这两个字段。
- 保存成功提示按“切换模型 / 仅改参数”分别显示；删除“在后台切换”的旧提示。
- 云端确认框旁增加“保存并重启后会自动建索引，费用按服务商价格计算。”

### 修改位置

- `lib/client.js`：`ModelPicker.save` 和云端确认区。
- `test/portable-memory-runtime-ui.test.js`：本地切换、云端切换、自定义 API 切换、仅参数保存的请求体和提示断言。

### 验证

- 云端及自定义 API 切换：请求同时带两个确认字段。

## A5：只调查 `sessionMemory=false` 的旧运行方式

本节只读调查，没有修改代码、配置或测试。

### 涉及文件与函数

- `lib/bundle-entry.js`：`startPortable` 把插件参数 `options.sessionMemory===true` 写入 `settings.personal.sessionMemory`。未传时默认 `false`，因此进入不带对话开关的旧运行方式。
- `lib/platform-host.js`（约 226 行）：`apply` 中约 20 处 `sessionMemory`/`!sessionMemory` 分支。核心包括 `selected`、`pinned`、`accepts`、`tracks`，工具执行、工具作用域刷新、事件观察、persona/pure-mode、会话选择保存和状态回执。
- `lib/personal-access.js`（26 行）：`createPersonalAccess` 是旧分支的 access gate，只依据 pure-mode 状态，不提供逐会话正向授权。
- `lib/index.js`（约 663 行）：`gated=hasSessionMemory(access)` 及后续约 10–20 行旧/新双路逻辑，例如消息记录、recent store、worker 和请求门。
- `lib/personal-runtime.js`（24 行）：`gated` 选择 recent store，并把同一 access 传给 `createBridge`。
- `lib/worker.js`（约 358 行）：`hasSessionMemory`、`authorizedTools`、`authorizedLlm` 和 worker 中约 30–50 行无 grant 兼容路径。
- `lib/client.js`：`hasSessionMemory` 以及约 8–12 行“开关尚未接通/旧绑定不作为新授权”的只读降级界面。

### 配置项

- 插件参数 `sessionMemory`：旧方式为缺省或 `false`，新方式必须为 `true`。
- `sessionIds` / 部署 JSON `dshSessionIds`：旧方式直接作为“所有选中会话默认记忆”的授权集合；新方式只保留兼容绑定和已知会话列表，不再构成授权。
- `autoEnableNewSessions`：仍由新会话自动开启逻辑使用。
- `deferProvide`、`configurationFile`、`configurationFingerprint`、`configurationStaticFingerprint` 和 `deployment`：旧分支也参与启动、状态回执和热应用，不能按名字误删。

### 需要删除或修改的测试

- `test/platform-host.test.js` 约 22–35、41–54 行：静态 `sessionIds` 授权、running-turn pinning 和旧热切换断言，应删除或改成 `sessionMemory:true` 的显式授权测试。
- `test/pure-gate.test.js` 约 80–138 行：三个经 `platform-host` 验证 pure-mode/persona 的集成用例，应删除或迁到仍保留的 persona/pure-gate 单元层。
- 若只删平台旧分支，`test/core-without-optional-modules.test.js` 约 25–42 行的无 access 核心构造不必然要改；若同时清理 `index.js`/`worker.js` 的无 grant 兼容路径，该测试及 `bridge.test.js`、`index-growth.test.js`、`recent-context.test.js`、`recovery.test.js` 等无 access 用例需要逐个迁移为显式测试授权或删除。两档删除范围不能混为一谈。
- `test/portable-session-memory-host.test.js`、`test/session-memory.test.js`、`test/session-memory-auto-enable.test.js` 覆盖新授权，应保留。

### 发布文档

- `README.md` 已写明“默认不读不记”、逐会话开启和旧绑定不作为新授权；`MODEL-SETUP.zh-CN.md` 也写明对话记忆由独立会话开关授权。窄范围删除平台旧分支不需要新增发布说明。
- 若删除 core 的无 access 兼容路径，需要另行说明这是内部测试/嵌入接口变化，但不应把它包装成用户数据格式变化。

### 风险点

- 现有宿主若未传 `sessionMemory:true`，当前仍会把 `dshSessionIds` 当默认授权；直接删除后这些配置会变成不读不记。这是安全方向，但属于可见行为变化，必须有启动日志或回执说明。
- `dshSessionIds` 仍被设置页、候选会话和引导流程使用，不能和授权字段一起直接删掉。
- 旧分支没有 grant，后台旧任务、recent cache 和消息记录可能走无授权兼容路径；只删 UI 或只删 `accepts` 会形成一半状态的授权漏洞。
- persona/pure-mode 与新逐会话授权目前有交叉；删除旧分支时要确认“已开记忆优先、未开记忆不读 persona/self-profile”的现有正向门不被放宽。
- 已存在待整理、待审核或旧索引任务不能因授权模式变化被自动重放；应保持 held 或给出明确重新授权路径。

### 没做的事

- 未删除任何 `sessionMemory=false` 分支。
- 未修改部署配置结构、授权策略、测试或文档。
