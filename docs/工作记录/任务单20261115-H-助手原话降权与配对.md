# 任务单 2026-11-15-H：助手原话降权与配对

工作区：`<工作区 h>`（分支 `h-assistant-provenance`，基于 main 的当前提交）。执行方按本单实现，不提交；Claude 复核后提交。

## 背景

L+M+P+Q 回归（P01 68/88）里，变错的 11 题有 9 题是"答对核心事实后又补了记录里没有的内容"。逐题追查材料后发现，有害的几类里一部分直接来自**助手自己以前说过的话**：

- 问"围巾送到哪了"：材料里有一条"原话 · 助手说：围巾在柜里，取的时候别和那次耳机搞混"，模型据此说"围巾还没取、还在柜里"，用户从没说过还没取。
- 问"怎么称呼林晓"：材料里混进了助手的一句"那个称呼被瞧见，是有点不好受"（原本说的是另一个称呼），模型拼出"你说过上次称呼被同事听见挺尴尬"。

统计：L+M+P+Q 那次检索结果里"助手说"占 46%（Z 批 44%），排在前三条的里面占 42%。助手的回复和用户的话用同样的"原话"身份、同样的排序竞争，模型分不清哪句是用户说的事实、哪句是助手当时的应和或发挥。

用户 11-15 定的方向：记忆系统只管"哪些算记得"；说多少、语气归人设和用户偏好。修法用程序规则，不加提示词，不针对基准题。

## 目标

自动预取和搜索结果里，**用户自己的话优先**；助手过去的回复只作为那一回合的上下文出现，不和用户的话平起平坐。

## 要求

### 1. 助手原话降权

在最终排序处（重排之后，和现有 `SUMMARY_RERANK_WEIGHT` 同一处），`kind==='original'` 且 `role==='assistant'` 的记录 rank 乘以新导出的常量 `ASSISTANT_RANK_WEIGHT = 0.5`。全文通道和向量通道来的都算。重排本身的候选、分数和是否启用不变。

### 2. 同一回合配对

结果里同时有**同一会话、同一回合**（`source.sessionId` + `source.turn` 相同）的用户原话和助手原话时：

- 助手那条不再单独占一条，而是挂到用户那条上：内部字段 `assistantReply`，模型看到的记录里键名为 `助手当时回复`，内容取助手原话正文，超过 120 个字截断并以"…"结尾。同一回合有多条助手原话时取排名最高的一条。
- 用户那条的排名取两者中较高的（配对不能让用户那条往后掉）。
- 只配对同一回合；不跨回合、不跨会话。用户那条没进结果时，助手那条照常单独出现（已按第 1 条降权）。
- 被挂上去的助手原话必须和单独出现时一样通过当前的来源校验（`validateResult` 里的 `current()` 那套）；校验不过就不挂。配对放在哪一层由执行方按最小改动选择，回执里写明位置和理由。
- 配对不改变用户那条的 `ref`、`anchor`、`label`、`text`；`memory_open` 展开用户那条时照旧带出邻近消息。
- 导入的旧笔记（`role==='summary'`）和人设资料（`kind==='document'`）不参与配对。
- 向量通道的记录如果自身不带 `source.sessionId`/`source.turn`，按它的 `anchor.ref` 从原话库取出来源再判断；取不到就不配对。

### 3. 自动预取只放用户的话

`selectPrefetch` 不收单独的助手原话（`kind==='original'` 且 `role==='assistant'`）；用户原话、导入旧笔记、人设资料照旧。用户那条上挂着的 `assistantReply` 不写进预取行，预取行格式保持 `- [标签] 正文`。`stats` 增加 `assistantSkipped` 计数。`memory_search` 照常能搜到助手原话（降权、配对后）。

## 测试

新增 `test/assistant-provenance.test.js`，全部用临时目录和虚构数据，至少覆盖：

1. 同样匹配时，用户原话排在助手原话前面；助手原话的 rank 是原来的 0.5 倍。
2. 同一回合的用户原话和助手原话都命中时，结果只剩用户那条，带 `助手当时回复`，超过 120 字时截断；用户那条的 `ref`/`label`/`text` 不变。
3. 不同回合、不同会话的不配对；用户那条没命中时助手那条单独出现。
4. 助手那条来源校验不过时不挂。
5. 预取：只有助手原话命中时预取为空、`assistantSkipped` 计数正确；用户原话上挂的回复不出现在预取行里。
6. 旧笔记、人设资料不参与配对，排序权重不变。
