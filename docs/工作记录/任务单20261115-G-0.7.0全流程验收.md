# 任务单 2026-11-15-G：0.7.0 发版前全流程验收

## 为什么做

0.6.0 之后合并了 W、Y、I、Z、L、M、P、Q、H、J、K、T、U 十三批：去掉了整理层，旧笔记改为用 `scripts/inherit-memory.mjs` 继承，向量模型默认改云端，加了宿主卡顿不计时、报错不外露、短期接续 72 小时上限。单元测试都过了，但还没有在隔离的真实 DSH 里从安装走到底。打 `v0.7.0` 标签前做这一次。

11-14 的 [V 批任务单](任务单20261114-V-隔离全流程验收.md)按当时还有整理层的结构写，没有执行；本单取代它的全流程部分（语气对照仍按 V 批，另行安排）。

## 被测版本

- **旧版**：公开标签 `v0.6.0`。
- **当前版本**：GitHub 上 `main` 的最新提交（第二次会话开始时 `git fetch` 后用 `git rev-parse origin/main` 取，回执写实际提交号）。没有新标签，安装用提交号。
- 本单两次会话之间，Claude 会把本地 `main` 推到 GitHub。第二次会话开始时如果 `origin/main` 不含 T、U 两批（`git log origin/main --oneline | grep "T 批\|U 批"` 为空），停下写回执，不要往下做。

## 怎么跑

`codex exec` 不能停下来等人，所以分两次会话：

- **第一次会话**：第 0、1 段，再做第 8 段要用的虚构旧库，把隔离实例停在首次配置页，结束会话。
- 用户在页面上做第 2 段配置，说"已配置"。
- **第二次会话**：从第 2 段末尾的重启开始，跑到最后。

不另起复核会话，由 Claude 验收回执。

**遇到不通过**：不影响后面各段的，记下原文报错和复现步骤，接着往下；挡住后面各段的，停下写清楚，结束会话。**不改 `lib/`、`test/`、`scripts/`、文档和配置模板**，发现的问题只写进回执。

## 通用规则

- 测试方法以[测试与复测方案](方案20261112-测试与复测.md)第二节为准，本单只写路线、新增检查和规矩；本单没写到的照方案做。
- 只在系统临时目录下新建的 `dsh-full-<时间>` 里操作，`DSH_HOME` 指向其中；隔离 DSH 用端口 **8941**，干净安装用 **8942**。
- **不碰**日常 DSH（3080）、真实记忆库和日常档案；只停自己启动的进程。
- DSH 运行时：全局 `dsh` 0.2.1-rc.5 在"预览版说明 → 继续"时会报 `settings/rejected`。沿用 [11-12 回执](回执20261112-全流程测试.md)第 2 段的做法，用临时目录下已有的独立运行时 `dsh-clean-runtime-20261112`（先核对版本是 0.2.1-rc.5；不在了就照那次的方法在临时目录重装一份），显式用它的 `lib/bin.js` 启动。
- 隔离实例用**独立进程**启动，会话结束后仍在运行；回执写进程号、端口、日志位置。
- **密钥**：不输入、不复制、不打印。带令牌的页面地址只打印到 `?` 之前，告诉用户去哪个日志文件找完整地址。
- **接口操作**：先 GET 带令牌的地址拿 cookie，请求头带 `x-basic-memory-settings: 1`，路径 `/api/basic-memory-settings/*`。
- 发消息、计时、取会话事件：可以复用 `.local/benchmark-cmb/` 里的 `driver`、`request-recorder`；会话事件顺序参照 [F 批回执](回执20261114-F-新对话首轮接续.md)"真实宿主验证"一节。
- 隔离记忆库是测试数据，可以直接查它的 SQLite 和文件核对。
- 不调用大肥鱼；不跑基准；不推送；不打标签。
- **花费**：只有对话模型、向量和重排的少量调用，全程预计不超过 ¥5。第 10 段单独有上限。回执写大致花费。

## 路线

主线是"**先装 0.6.0 → 留下旧数据 → 升级到当前版本 → 在当前版本上做完全部功能段**"，这是老用户真实会走的路；另做一段当前版本的干净安装。

### 第 0 段：单元测试（第一次会话）

当前工作区全量测试 `node --test --test-timeout=60000 test/*.test.js`。不过就不往下做。

### 第 1 段：安装 0.6.0（第一次会话）

1. 按 `v0.6.0` 标签的 README 和安装说明，从 GitHub 安装（`github:XRH66/dsh-memory-starter#v0.6.0`），人设插件按那份说明的固定提交装。
2. 用独立运行时在 8941 启动，过"预览版说明 → 继续"，停在首次配置页。
3. 记录 DSH 版本、两个插件实际装上的版本和提交（从档案的 `package.json` 和安装目录读）。
4. 登录页 200，`/api/basic-memory-bootstrap` 200 且 `configured=false`。

### 第 8 段准备：虚构旧库（第一次会话）

照测试方案第 6 段第 1、2 步，在临时目录按 0.3.0 布局造好虚构旧库，并记下所有旧笔记文件的哈希和修改时间（写进临时目录里的清单文件）。内容全部虚构，可参照 `test/inherit-vault.test.js` 的格式。

**第一次会话到这里结束。** 回执先写到这里，最后给用户一段配置清单（照下面第 2 段），并写清：页面地址去哪个日志找、实例进程号。

### 第 2 段：首次配置（用户动手）

0.6.0 的首次配置页，用户一次配好：

1. 对话用的模型服务，和日常相同；
2. 「记忆框架」首次配置：填临时目录下的**新**记忆目录，选整理模型（0.6.0 还有这一项，和对话用同一个即可），勾一个对话，点启用；
3. 向量接口服务（硅基流动 `BAAI/bge-m3`），保存，先不切换；
4. 重排服务（硅基流动 `BAAI/bge-reranker-v2-m3`），保存，先不打开。

密钥只由用户填。第二次会话从"按页面提示重启"开始。

### 第 3 段：在 0.6.0 上留下旧数据

1. 对话 A0 开启记忆，发测试方案第 3 段的 4 条自然日常对话（团子、植物园、冰美式、海边，不说"记一下"）。
2. 等状态页"无待处理"（0.6.0 会整理出条目）。
3. 记下：原话库回合数、消息数；回合编号里有没有旧分隔符（`\u0000`）；Vault 里条目文件数和类型。0.6.0 上记忆查询报 `BACKEND` 是已知旧缺陷，**不算**失败，这一段只为留数据。
4. 停掉实例，把隔离记忆目录整份复制一份，留给第 12 段回退演练（停机后复制）。

### 第 4 段：升级到当前版本

1. 按当前版本的[升级说明](../install/upgrade.md)操作：卸载 `v0.6.0`，安装 `github:XRH66/dsh-memory-starter#<当前版本提交>`，重启。
2. 核对：
   - 实际加载的插件提交是当前版本；
   - 原话库 `raw_schema` 里有 `turn-id-v2` 标记，旧分隔符回合数为 0，回合数、消息数和第 3 段一致；
   - DSH 日志里没有因旧配置里的整理字段报错（整理字段应被忽略）；
   - 设置页各分页都能打开，浏览器控制台没有报错；页面上不再有整理模型、条目、待确认、旧记忆迁移；
   - A0 能继续开着记忆聊天。
3. 照升级说明第 3、4 步，对这份隔离库跑 `inherit-memory.mjs`：
   - `check`（默认读当前库 Vault）：报告条数；0.6.0 由对话整理出来的派生条目应默认跳过，写明跳过数；
   - 再加 `--include-derived` 跑一次 `check`，只看条数，不 `apply`；
   - `apply`（不加 `--include-derived`）：记下批次号和新增、跳过条数；
   - 旧 Vault 文件的哈希不变。
4. 升级说明和实际操作不一致、或缺步骤的地方，逐条记进回执。

### 第 5 段：对话、检索、接续（当前版本）

照测试方案第 3 段，加：

1. **新对话第一句就接上**：新建 B 开启记忆，第一句问「我的猫叫什么？」
   - B 的第一次模型请求里就有接续消息，事件顺序"系统提示 → 接续 → 用户原话"；
   - 答对"团子"；
   - B 的第二句不再新增接续。
2. **预取只带相关的**：B 里接着发一句无关的新话题（如「周末想看部电影，有推荐吗」）和一句寒暄（如「好的谢谢」），这两轮都不应出现预取材料。
3. **规则消息**：每个开了记忆的回合都附一条规则消息（本地时间加中性回答规则）；有预取或接续时，材料和规则的位置按[运行流程](../记忆系统运行流程.md)所写。只列消息类型和顺序，不贴整段。
4. **问现在的状态偏新**：在 A0 里说一句状态变化，如「这两周开始改喝热拿铁了，冰的有点受不了」；等向量追平后，新对话问「我现在一般喝什么咖啡？」：
   - 回答以热拿铁为准，不把冰美式说成现在的习惯；
   - 搜索或预取报告里 `currentState` 有记录（触发了"偏新"）。
5. **语气粗看**：B 里闲聊的回答有没有"根据记录""记忆库里""检索"这类说法，有就摘录原句。
6. **关闭记忆**：对话 C 不开记忆发一句，原话库里查不到；C 的请求里没有接续、预取和规则消息。
7. 原话入库不含思考和工具调用；向量队列追平后原话向量都已建好；预取材料的标注（说话人、日期、相对日）正确。

### 第 6 段：向量与重排

照测试方案第 4 段，加：

1. **本地模型可选下载**：在「检索模型」页下载 BGE-small-zh-v1.5，**不用命令行绕过**，下载完成后页面能直接保存启用，重启后"准备索引"能就绪。
2. 重排打开、关闭各问一次同一个问题，两次结果都记进回执；状态页能看到重排耗时。
3. **重排失败退回**：把重排地址换成连不上的，问一次。结果照常返回、退回原排序；**回答里不出现"后端""接口""无法返回""BACKEND""错误码"这类说法**。之后恢复。
4. **向量服务失败**：把向量服务地址临时换成连不上的，问一次。聊天在原有时限内回答，不卡住；回答同样不出现技术说法；状态页能看到失败记录。之后恢复。
5. **档案切换**：切到接口服务建索引，再切回 BGE-small，确认复用旧档案、只补差量；档案表的维数、文档数正确；从没建过索引的档案标"未建索引"（做不到就写"没做"）。
6. 状态页「最近 20 次检索」能看到耗时；搜索报告里有 `hostStallMs`（宿主卡顿时长）字段。

### 第 7 段：删除原话

照测试方案第 5 段：「维护 → 删除原话」搜「团子」删除；原话通道、向量通道、预取和 `memory_open` 都不再返回它。第 4 段继承进来的旧条目里如果也有团子，照实写明（继承记录和原话是两份，删原话不连带删继承记录，这是预期）。

### 第 8 段：旧库切换与继承旧笔记

照测试方案第 6 段（用第一次会话造好的虚构旧库），加：

1. **新对话第一句重载不报错**（0.6.0 的 `protected first surface head` 问题）：切到旧库后新建对话、发一句、重启实例、再打开这个对话发一句，都正常。
2. 用请求工具给设置接口发一个数组或字符串当请求体，返回明确的错误，实例不崩。
3. 做完在「维护 → 记忆库」切回第 2 段的隔离库，重启。

### 第 9 段：短期接续时间上限

1. 在隔离部署的插件配置里把 `handoffMaxAgeHours` 设成 `1`（找到实际生效的配置位置，回执写明在哪里改的），重启。
2. 新建对话开启记忆发一句，核对首轮接续里带的原文时间都在 1 小时以内，更早的没带。只列条数和时间，不贴正文。
3. 如果此时所有原文都在 1 小时以内、无法区分，写"无法区分"，不算失败。
4. 改回去（删掉该项，回到默认 72），重启，确认能正常对话。

### 第 10 段：上下文压缩后的接续（可选，花费上限 ¥2）

用户担心长对话被 DSH 压缩之后接续出问题。

1. 先查 DSH 0.2.1-rc.5 有没有手动触发压缩的入口（命令或接口）。有就用它；没有就在对话 D（开记忆）里用虚构的长消息把上下文推到压缩阈值。灌之前先估算花费，超过 ¥2 就不做，写"没做"和原因。
2. 压缩前在 D 里说几件可辨认的虚构小事；压缩后再说一两件。
3. 核对：压缩后 D 还能继续聊；D 的会话事件里接续消息不重复；重启后 D 还能打开并继续聊；D 压缩前后说的话都完整进了原话库。
4. 新建对话 E（开记忆），第一句问 D 里压缩前和压缩后各一件事：E 的第一次请求里有接续，包含 D 最近的原文；回答能接上。

### 第 11 段：日常增量性能（轻量）

照测试方案第三节"日常增量性能"，在 8941 上：

1. 开记忆和不开记忆的对话各发 6 条长度相近的自然消息，记每轮从发出到回答完成的时间，给中位数和最高值，并拆出预取耗时；
2. 写入后多久能被原话检索查到、多久能出现在另一个新对话的接续里；
3. 每批消息后的待处理队列数，以及空闲后多久追平。

### 第 12 段：当前版本干净安装（8942，轻量）

另建一个临时 `DSH_HOME`，端口 **8942**，直接安装 `github:XRH66/dsh-memory-starter#<当前版本提交>`，不先装 0.6.0，按当前版本 README 和[安装说明](../install/setup.md)操作（README 里的 `<标签或提交>` 换成当前版本提交）：

- 能启动，登录页 200；`/api/basic-memory-bootstrap` 200 且 `configured=false`；
- 首次配置页能正常显示，没有整理模型一项，浏览器控制台没有报错；
- 新用户默认的向量设置是云端（`custom-api`），没有默认去装本地模型。

**不配置模型、不填密钥**，看到首次配置页就停，停掉这个实例。安装说明和实际操作不一致的地方记进回执。

### 第 13 段：回退演练（时间不够可写"没做"）

停掉 8941，插件换回 `v0.6.0`，记忆目录换回第 3 段留的副本，启动：实例正常；A0 的回合数和消息数与第 3 段一致；设置页能打开。做完停掉。

### 第 14 段：收尾

停掉自己启动的所有实例，确认 8941、8942 已释放；临时目录保留。
