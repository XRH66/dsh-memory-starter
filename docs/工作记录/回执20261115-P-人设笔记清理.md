## 发现与取舍

1. 工作区没有 `AGENTS.md`，Git 索引中也没有该文件；本批按会话指令、任务单和目录边界执行。

2. 两个校验脚本都用 `git ls-files` 枚举“跟踪文件”，不会跳过仅在工作树中删除、但索引仍记录的文件。若不登记删除，release 校验会把三个已删文件误报为“未列入白名单”，privacy 校验会直接读取不存在的文件。为此本批只用 `git add -u` 把三处删除登记到索引，没有提交或改历史；新文件仍按任务要求用 `git add -N` 登记。

3. `lib/memory-documents.js` 的 `record()` 当前不会把 frontmatter `title` 传给查询层。任务单禁止改其收文档范围，因此 `memory-query.js` 在本层增加 H1/permalink 回退。文件名与 frontmatter 标题不一致的手选资料，在向量搜索中仍可能只能显示文件名形式，不能保证逐字还原 frontmatter 标题；这需要在以后允许修改 `memory-documents.js` 时补传标题。

4. `isStrongCue` 虽没有外部调用方，但仍是保留函数 `adjustedRelevance` 的内部依赖，所以只收回导出，不删除实现。

5. `lib/review.js` 中列出的清单读写、链接和容量函数虽无外部调用方，但都仍被 `appendReviewEntry` 使用；本批通过收窄导出解决接口冗余，没有破坏待审行为。

6. 未读写真实记忆库、真实 Vault、真实部署配置，未重启 DSH，未跑基准，未调用付费模型或外部接口。

## Claude 复核（2026-11-15）

- `createSoftenTool` 与基线 `lib/memory.js` 中的函数原文逐字一致（3009 字节函数体），`sanitizeMemoryTitle` 迁入 `vault-files.js` 后原文一致。
