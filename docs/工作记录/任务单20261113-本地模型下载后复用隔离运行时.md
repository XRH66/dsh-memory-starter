# 任务单：本地模型下载后复用隔离运行时

日期：2026-11-13

## 目标

修复本地向量模型“一键下载”完成后，模型清单仍判定为未安装的问题。下载任务已经创建并校验通过的隔离 Python 运行环境和安装回执，必须在后续清单检查中被重新发现和复用，使页面可以直接保存启用。

## 已确认证据

- 全流程测试中，BGE-small 下载任务最终状态为 `downloaded`；模型文件和独立 Python 运行环境都已创建。
- 随后清单检查选择了系统 Python，未使用安装任务创建的隔离 Python，因而报告缺少 `tokenizers`、`onnxruntime`、`fastembed`。
- `createModelInstaller` 的 `downloadOnly` 路径会写入 `<记忆库>/runtime/embedding-install-v1/receipts/*.json`，但不调用 `stageModel`。
- `inventory()` 目前只检查当前配置、待切换配置和历史配置；找不到时重新调用 `plan()`，而 `findPython()` 不会自动发现上述隔离运行环境。

## 修改范围

允许修改：

- `lib/raw-rag/install.js`
- `lib/raw-rag/install-files.js`（仅在同目录方案确实需要时）
- `test/model-install-split.test.js`

不要修改：

- 前端和设置接口
- 模型下载目录结构或安装配方
- 现有配置格式、向量索引格式和 API
- 其他无关文件
- 文档、版本号、`release-files.json`

## 实现要求

1. 本地模型清单检查应能发现当前记忆库安装目录中已经完成、可验证的安装回执。
2. 只接受与所选模型一致、文件完整、Python 包版本和隔离 Python 路径均通过现有 `inspectSelectedInstallation` 检查的回执。
3. 多个回执同时存在时，优先选择可验证的最新结果；损坏、过期或不匹配的回执必须隔离并继续检查其他候选。
4. 返回给前端的 `settings` 继续只包含现有 `INVENTORY_PATH_FIELDS`，不得暴露 API Key、凭据文件或其他秘密字段。
5. 不改动 `downloadOnly`“只下载、不切换”的语义，也不在清单读取时下载、启动模型或调用网络。
6. 修复应适用于 `onnx` 和 `fastembed` 等需要 Python 的本地模型；不要只识别本次测试的固定路径。

## 回归测试

在现有 `test/model-install-split.test.js` 增加测试，至少覆盖：

- 隔离 Python 不在 PATH、也不在当前／历史配置中，但安装回执可验证时，`inventory()` 返回 `installed:true`。
- 返回的 `settings.rawRecallPython` 指向回执中的隔离 Python。
- 返回的 `settings` 不包含凭据或 Key 字段。
- 损坏或不匹配的回执不会隐藏其他可验证回执。
- `downloadOnly` 仍然不调用 `stageModel`。
