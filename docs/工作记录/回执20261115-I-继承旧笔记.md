## 撤销机制

整批撤销选择了 `raw_controls` 的 turn 级排除，不使用物理删除。

- 导入批次使用 origin `inherit:<batchId>`。
- `undo` 对该批每个 turn 写入 `excluded=true`，现有搜索、预取、`memory_recent` 和 `memory_open` 都会按原控制链路拒绝它。
- `restore` 把同一 origin 的控制改回 `excluded=false`，正文、向量索引和批次成员记录都保留。
- 其他来源的控制仍会参与合并，因此恢复本批不会覆盖操作者另外施加的排除或降权。
- 批次成员和正文分开保存；成员表只记录稳定来源键、正文哈希、turn id、批次和状态，不复制正文。

## summary 说话人

`summary` 已作为独立说话人贯通导入和读取链路：

- `buildTurn()` 接受 `user`、`assistant`、`summary`；摘要全文索引与基础向量文本前缀使用 `旧笔记：`，不再落成用户或助手。
- `query-reader` 返回真实 role/speaker，并带出 `imported`、批次、来源系统、来源种类和来源文件。
- `memory-documents` 接受摘要原话；摘要向量材料使用 `正文｜旧笔记：`，证明指纹绑定来源版本与正文。
- `memory-query` 的标签为“旧笔记（整理摘要） · 写于 …”；导入的用户或助手原话仍在现有标签后加“ · 导入”。
- 最终排序在重排之后、截取条数之前应用命名常量 `SUMMARY_RERANK_WEIGHT = 0.7`，`memory_search` 与预取共用该路径。
- 导入 turn 带批次标记，`recentTurns()` 显式排除；短期接续继续只读 `raw_messages`，导入记录不会进入 handoff 或 recent-context。

## 命令行

```powershell
node scripts/inherit-memory.mjs check --deployment <deployment.json> --vault <旧 Vault>
node scripts/inherit-memory.mjs check --deployment <deployment.json> --file <导入.jsonl>
node scripts/inherit-memory.mjs check --deployment <deployment.json> --vault <旧 Vault> --out <核对.jsonl>
node scripts/inherit-memory.mjs apply --deployment <deployment.json> --vault <旧 Vault>
node scripts/inherit-memory.mjs apply --deployment <deployment.json> --file <导入.jsonl>
node scripts/inherit-memory.mjs list --deployment <deployment.json>
node scripts/inherit-memory.mjs undo --deployment <deployment.json> --batch <批次号>
node scripts/inherit-memory.mjs restore --deployment <deployment.json> --batch <批次号>
```

`check` 只读；只有显式 `--out` 时写转换后的标准 JSONL。`apply` 先完成全部检查，再按 `raw-memory.mjs` 的方式用 `VACUUM INTO` 备份原话库，随后导入并触发向量待编码处理。配置仍由部署配置解析，输出不回显密钥或令牌。

单文件上限为 50MB、10 万条。超过 20000 字的 Vault 笔记会优先在段落、换行或句末边界切成 `part`，切片保持原字符；找不到可保留原文边界的超长段会逐个列出并跳过。
