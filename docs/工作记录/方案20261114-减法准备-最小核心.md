## 三、耦合点（砍之前要先解开）

1. **`raw-rag/store.js` 引用 `memory-entry-index.js`**：条目全文索引和原话库在同一个 SQLite 里。砍条目要先把这部分从原话库剥离，并保证已有库能正常打开（旧表留着不读即可，不做破坏性迁移）。
2. **`memory-query.js` 引用条目、Vault、旧笔记、重要度、旧记忆迁移**：检索通道里有条目通道和旧笔记通道。去掉后通道只剩原话全文和向量。
3. **`memory-vectors.js` 经 `memory-documents.js` 给条目建向量**：去掉后向量索引只收原话，档案切换和差量补建逻辑不变。
4. **`index.js` 组装整理流水线、Vault 监视、旧记忆迁移、更正标记**：整理器的挂载点只有一处（`organizer:resolved.autoCapture?organizer:undefined`），基准里的"关掉整理"就是走这个开关。
5. **更正**：预取对更正记录打 0.6 折，更正标记来自整理层（`changeKind:'correction'`）。整层砍掉后这条规则失效，要么删掉，要么改成原话层面的轻量识别（不调模型）。
6. **设置页**：条目浏览、待确认、旧记忆迁移、整理模型选择各页要一起处理；首次配置目前强制要求填整理模型（`bootstrap-host.js`）。

### 继承标准（取代旧记忆迁移）

旧记忆不再分 12 类，只"搬"不"分类"。定一种统一导入格式，每条记录包括：时间（写下的日期，不知道就留空）、谁说的（用户 / 助手 / 整理摘要）、正文（原样）、来源（文件或系统）、种类（原话 / 笔记 / 日记）。

- 导入后与原话同库：参与搜索、预取，在可视化页面里按时间线显示。旧笔记标成"整理摘要"，权重低于原话；和新原话冲突时，以时间新的为准。
- 常见格式由程序直接转，不调用模型：0.3.0 的 Basic Memory 笔记、0.4～0.6 的条目、DSH 聊天记录。
- 其他格式：发布标准，再附一段给 DSH 用的技能说明，由用户自己的 DSH 用自己的模型转换后交给导入工具。
- 导入工具负责把关：格式校验并说明错在哪里；重复导入不产生重复记录（补写幂等）；按批次号整批撤销；原文件只读。
- 正文里提到的日期原样保留，不让程序去猜事情发生的日期。

### 整体顺序

1. 旧测试脚本测现在的代码，确认新旧脚本给分差多少（11-14 晚进行中）。
2. 恢复每回合规则，同时修"部分检索"误报，跑一次 P01。
3. 统计日常库：原话最早日期和条数、条目数、旧笔记数和时间范围。只计数，不读内容。
4. 定继承标准；导入用户自己的旧库并核对，确认老记忆都能搜到、都能看到。
5. 砍整理层、Vault 层、旧笔记通道、旧记忆迁移，做可视化页面，分两三批。如果整理层还有部分保留、需要反复对照，在这一步之前建好快照。
6. 用最终版本跑 V 批验收和语气对照。
