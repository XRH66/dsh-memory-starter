## 根因与修复

### 一、SQLite 内嵌 NUL 导致回合 ID 被截断

根因：Node 22.19.0 的 `node:sqlite` 在文本参数绑定和文本列读取路径上会截断内嵌 NUL。`buildTurn` 原来用 `\u0000` 拼接默认 `turnId`，例如 `owner:a\u0000s1\u00001` 在数据库中落成 `owner:a`。这造成：

- 不同回合落入同一 ID，重复消息被误判为已属于当前作用域。
- `sourcesNeedingChunks` 找不到实际回合，出现 `fixture source must need model-specific chunks`。
- 控制项、旧作用域视图、检索结果和向量的关联失配；部分测试随后因等待永不发生的路径而被取消或文件超时。

修复：

- 默认回合 ID 改用可安全持久化且不依赖版本分支的分隔符 `\u001f`，统一由 `rawTurnId()` 构造。
- 数据库打开时增加一次性迁移：读取旧 `turn_id` 的完整 BLOB 字节，在 JavaScript 中把 NUL 转换为安全分隔符，再更新所有相关表。
- 同步迁移 `raw_controls` 中 `target_type='turn'` 的目标 ID，以及 `legacy_scope_views.turn_revision` 中 JSON 转义后的 `\\u0000`，保留控制项和已审阅视图关系。
- `scripts/raw-memory.mjs` 的 `control --turn` 使用同一个构造函数，避免命令行与新数据格式分叉。

新增回归测试会模拟旧库中的 NUL ID，并验证回合正文、控制权重和已审阅视图在重开后都保留。

### 二、Node 22 下超时计时器不保持事件循环

根因：`AbortSignal.timeout()` 的计时器在 Node 22.19.0 的测试场景中不保持事件循环。假后端永不返回时，测试运行器先看到事件循环清空，报“Promise 仍待处理”，后续连接测试被父测试取消。

修复：改用显式 `setTimeout()` 配合 `AbortController`，成功或失败后都在 `finally` 中清除计时器。没有按 Node 版本号分支，Node 22 和 Node 24 使用同一路径。
