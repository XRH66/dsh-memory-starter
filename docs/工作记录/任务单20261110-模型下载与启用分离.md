## 要解决的问题

现在「检索模型」页选中本地模型后只有一个按钮「下载并启用」：

- 看不出哪个模型已经装好（日常正在用的 4B 没有安装回执，照样显示「下载并启用」）；
- 下载完成后安装任务直接把模型写成「待切换」（`stageModel`），下载和启用绑在一起。

目标行为：

- **检测**：下拉里每个本地模型标「已安装 / 未安装」。只查文件和依赖清单，不加载模型、不请求网络。
- **下载**：只对未安装的模型显示「下载」按钮；下载只落文件，不改配置里的当前/待切换模型。
- **启用**：下拉选中只是页面上的选项；点「保存」才正式应用（沿用现有保存→后台切换流程）。未安装的本地模型不能保存。
- 云端「自定义 API」不变。「维护」页里的高级面板（`RawModelSettings` + 非 simple 的 `ModelPreparation`）行为不变。

## 代码架构

### 1. 后端：`lib/raw-rag/install.js`

`createModelInstaller` 增加两样东西：

**(a) `inventory(input)` —— 安装检测**

返回 `{revision, models:[{id, installed, source, issues, downloadBytes, settings}]}`，只含本地模型（`rawModelOptions` 中 `!cloud`）。对每个模型按顺序找第一组「文件齐全」的设置（用 `inspectSelectedInstallation` 判定 `ready`）：

1. `source:'current'`：`cfg.pendingRawRecall` 或 `cfg.memory` 当前就是这个模型 → 用它的现有字段；
2. `source:'history'`：`cfg.rawModelHistory` 里该模型的记录（从新到旧）→ 用那次的字段；
3. `source:'installed'`：`plan()` 给出的 `suggestedSettings`（库内安装目录）。llamacpp 先试 `acceleration:'cuda'` 再试 `'cpu'`。

都不 ready → `installed:false`，`issues` 取第 3 步的问题列表，`downloadBytes` 取 `plan()` 的值。

`settings` 只返回路径类字段，不带任何密钥相关字段：
`rawRecallPython, rawRecallCacheDir, rawRecallBgeModelDir, rawRecallOnnxModel, rawRecallOnnxTokenizer, rawRecallGgufModel, rawRecallLlamaServer, rawRecallLlamaCpuServer, rawRecallLlamaCudaServer, rawRecallLlamaGpuLayers, rawRecallInstallReceipt`（没有的字段略过）。未安装时 `settings:null`。

要求：单个模型检测抛错只影响该模型（记为未安装并把错误信息放进 `issues`），不能让整个接口失败；`readGpu` 不开；不启动模型进程。`plan()` 内已有的 `findPython` 会起一个很短的 python 进程查包版本，这个可以保留。

**(b) 只下载模式**

`start(input)` 接受 `input.downloadOnly===true`（仍要求 `allowDownload===true`）。`run()` 在该模式下：下载、校验、写回执都照旧，但**跳过** `stageModel`，结束时 `job.state='downloaded'`，`job.step='已下载；选中后点「保存」启用'`。不带 `downloadOnly` 时行为与现在完全一致（高级面板还在用）。

顺带确认 `verifiedDownload`（`lib/raw-rag/install-download.js` 或同目录相应文件）是否「先写临时文件、校验通过再改名」。如果是，回执里写一句确认；如果不是（半截文件会留在目标路径），**不要自己改**，在回执里报告。

### 2. 路由：`lib/settings-host.js`

`POST /model-install` 增加 `action:'inventory'` → `json(res,200,{ok:true,inventory:await installer.inventory(input)})`。放在 revision 检查之后，和 `plan` 并列。`start` 原样透传 `downloadOnly`。

### 3. 保存校验：`lib/deployment-config.js`

`stageDeploymentRawModel` 里已有 `inspectSelectedInstallation(fields)` 不通过即报错的逻辑，保留。只把本地模型的报错文案改成用户能看懂的：`'该模型尚未下载完整，请先下载：'+issues`（云端模型文案不变）。

### 4. 界面：`lib/client.js`

**`ModelPicker`**

- 新增状态 `inventory`（`null` 表示还没查到）。在 `info.revision` 变化时、以及下载任务结束时，`POST /api/basic-memory-settings/model-install`，body `{action:'inventory',revision:info.revision}`，请求头与现有 `request` 一致。失败时 `inventory` 保持 `null`，页面照常可用（不显示安装标记，不拦保存，由后端兜底）。
- 下拉选项文字：本地模型在现有标题后加 `（已安装）` 或 `（未安装）`；当前使用的仍显示 `（当前使用）`（当前使用的不再重复标已安装）。`inventory` 为 `null` 时不加标记。
- `choose(model)`：若该模型在 `inventory` 中已安装且不是 `base.rawRecallModel`，把 `entry.settings` 合并进 draft（这样保存时带上正确路径）。现有的自定义 API 字段重置逻辑不变。
- 选中的本地模型**未安装**时：显示说明 `'该模型尚未下载（约 X MB）。下载只保存文件，不会切换模型。'`、「下载」按钮；「保存」按钮禁用。
- 选中的本地模型**已安装**时：不显示下载按钮，显示 `'已安装。点「保存」后启用。'`（如果它就是当前使用的模型则不显示这句）。
- 下载任务进行中：显示进度和「取消」（沿用现有显示），下拉禁用（现有 `preparing`）。
- 下载完成（任务 `state==='downloaded'`）：重新取 `inventory`；若当前选中的就是刚下好的模型，把它的 `settings` 合并进 draft，此时「保存」可点。

**`ModelPreparation`（simple 分支）**

- 按钮文字「下载并启用」→「下载」，点击发 `{action:'start',allowDownload:true,downloadOnly:true}`。
- 是否显示按钮不再看 `draft.rawRecallInstallReceipt`，改由父组件传入的 `installed`（布尔或 `null`）决定：`installed===false` 才显示。
- 轮询里：`state==='downloaded'` 时调用新回调 `onDownloaded()`（父组件据此刷新 inventory）；`state==='prepared'` 的原有 `refresh()` 分支保留（高级面板用）。
- 开始下载后的提示改成 `'已开始下载，可取消。下载完成后选中并保存才会启用。'`
- 非 simple 分支不改。

没用到的 `.memory-model-cards` / `.memory-model-card` 样式顺手删掉（确认 `lib test` 里没有引用后再删）。
