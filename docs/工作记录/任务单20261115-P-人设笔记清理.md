# 任务单 P：人设笔记清理与标注（2026-11-15）

精简计划第 5 步的一部分（项目状态「下一步」第 3 项前半），在独立工作区 `<工作区 p>` 做，与任务单 Q（本地向量模型改为可选，工作区 `<工作区 q>`）同时进行。先读 `docs/项目状态.md`、`docs/工作记录/审计20261114-整体结构与冗余.md` 第四、七节、`docs/工作记录/回执20261115-Z-去掉整理层.md`。

## 背景

- 人设笔记（工具 `dafeiyu_records`，实现在 `lib/records.js`）是人设自己的日记、想法、图库和人物印象，存在 Vault 的 `dafeiyu/` 下。用户 11-14 决定保留：工具的 6 个动作（list、read、search、save、archive、delete；后两个只提交给用户审，不真删）、Markdown 文件格式（每条带 `<!-- dsh-entry:` 标记）、待审清单都不变。
- Z 批删掉整理层后，还留着一些只为整理层或旧笔记服务、现在没人调用的代码：
  - `lib/memory.js`（约 23KB）：对外只剩 `createSoftenTool`（`lib/platform-host.js` 用，现在只降低原话权重）和 `sanitizeMemoryTitle`（`lib/vault-files.js` 用）。其余读写旧笔记的函数没有生产调用。`lib/memory-entry.js`（约 10KB）只被 `memory.js` 用。
  - `lib/records.js` 的 `reinforcePersonalEntry`（读一次就延长记忆）：原来只有整理流水线调用，现在没有生产调用。`adjustedRelevance`、`priorityFromMetadata` 的导入没用到。
  - `lib/priority.js` 的 `HALF_LIFE_BY_MEMORY_TYPE`（按条目类型定遗忘速度）：只对带 `memory_type` 的整理条目和 0.3 笔记有意义；人设笔记、`memory-documents.js` 的文档都不带这个字段。`reinforcePriorityPatch`、`softenPriorityPatch`、`isStrongCue` 在上述代码删掉后没有调用方。
  - `lib/review.js`：`managementDirectory` 被很多模块用，要保留；`reviewAbsolutePath`、`fileSize`、`appendReviewEntry` 被人设笔记的待审功能用，要保留；`reviewLink`、`formatBytes`、`vaultCapacity`、`readReviewList`、`saveReviewList`、`reviewListPath` 等对外没有调用方。
- 标注问题：人设的日记、想法和用户手选的资料被向量检索搜到时，记录的 `kind` 是 `document`（`domain` 为 `thoughts`、`diary` 或 `document`），`lib/memory-query.js` 的 `recordLabel` 走到给整理条目用的分支，标成"记忆条目 · 记忆 · 有效性未知 · 依据时间 …"。模型分不清这是助手自己写的日记，还是关于用户的记录。

## 二、修人设笔记和检索资料的标注（`lib/memory-query.js`）

`recordLabel` 对 `kind` 为 `document` 的记录：

- `domain` 为 `thoughts`：`助手自己的想法 · 写于 <时间>`
- `domain` 为 `diary`：`助手自己的日记 · 写于 <时间>`
- `domain` 为 `document`（用户在维护页手选的检索资料）：`检索资料 · <标题>`，有时间时加 ` · 写于 <时间>`
- 时间格式和原话标注一致（`localTimeWithDay`），没有时间写"时间不详"。

`memory_search` 和 `memory_open`、预取都用同一个标注。不改回答规则消息的措辞。
