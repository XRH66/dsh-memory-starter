# 任务单：修复默认主体下的记忆查询失败（2026-11-12）

创建：2026-11-12 03:20，America/Los_Angeles。

2026-11-13 复核：用户已授权按后续阶段计划进行本地提交；提交仍不包含推送、发布或日常部署。

## 现象

0.6.0 首次配置没有显式配置 `ownerSubject` 时：

- 会话记忆授权使用默认主体“用户”；
- 原话查询读取到的主体是空字符串；
- `memory_search` 和 `memory_recent` 返回 `BACKEND`；
- 模型会把技术错误直接说给用户，造成出戏。

## 根因

`lib/platform-host.js` 中：

- `sessionMemory` 使用 `liveOwnerSubject || '用户'`；
- `createPersonalMemoryRuntime` 收到的 `ownerSubject` 函数仍返回空值；
- 查询侧读取主体为 `''`，授权侧主体为“用户”，于是判定 `Message scope changed`。

## 修复范围

1. 在平台入口只解析一次有效主体，未配置时固定为“用户”。
2. 会话授权、个人记忆运行时和对外服务使用同一主体。
3. 增加未配置 `ownerSubject` 时的集成回归测试，实际调用 `memory_recent`。
4. 先跑定向测试，再跑全量测试。
5. 只在隔离部署验证修复，不改日常 3080、真实记忆库或全局 DSH。
