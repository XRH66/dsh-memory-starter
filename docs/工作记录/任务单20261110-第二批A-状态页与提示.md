## A1：「状态」页显示向量检索和整理状态

现状：`lib/client.js` 的 `Page` 里，「状态」页（约第 592、594 行）只显示“个人记忆服务 / 待同步 / 人工审核”。当前向量模型、索引进度、「准备索引」按钮和长期整理状态都在 `MemoryRuntimeSettings`（约第 126–206 行）里，只出现在「维护」页（第 595 行 `showVectors:false`）和维护页专家面板里（`RawModelSettings` 末尾）。用户在「状态」页找不到这些信息。

改法：
1. 「状态」页在“运行状态”之后、“人工审核”之前，渲染 `MemoryRuntimeSettings`，`showVectors` 为 true，`modelId` 取**当前生效的模型**：`sessionInfo.rawModel.fields.rawRecallModel`；`cloud` 按该模型是否云端判断（`sessionInfo.rawModels` 里查 `cloud`）。
2. 如果有待生效的模型（`sessionInfo.pendingRawModel`），在其上方加一行醒目提示：`待生效的检索模型：<名称>。重启 DSH（重新加载记忆框架）后切换；切换后会自动开始建索引。`（第 2 句是否成立取决于 A2 的改动，A2 做完后这句必须属实。）
3. 「维护」页第 595 行那份 `showVectors:false` 的 `MemoryRuntimeSettings` 去掉（后台调度信息已在状态页显示）。维护页专家面板 `RawModelSettings` 里的 `MemoryRuntimeSettings` 也去掉，专家面板只留参数和 `ModelSwitch`（取消切换、重试）。注意：`showVectors:false` 时独有的「旧任务接续」「最近优先整理」两块内容不能丢——改成在状态页那份里也显示（即把这两处的 `!showVectors&&` 条件去掉）。
4. `MemoryRuntimeSettings` 顶部那句“正在查看：…；运行状态：…”改为 `当前模型：<模型名，云端自定义时显示服务里的模型名称 rawRecallApiModel>；运行状态：…`。
5. 「全域索引」那一行改得能看懂：`索引：已就绪（285 / 285）`、`索引：准备中（120 / 285）`、`索引：未建立`（progress 不存在时）；`未建立` 时在下面加一行 `点「准备索引」开始建立。云端模型会把纳入索引的内容发送到服务商并计费。`（本地模型不要第二句）。

## A2：检索模型页保存后真的会切换，提示要准确

现状：`ModelPicker` 的 `save`（约第 488 行）只 POST `settings`，不带 `confirmSwitch`，后端把它存为待生效；重启 DSH 后配置切过去了，但**不会自动建索引**（`lib/memory-vectors.js` 约第 105 行：只有带确认的才会设切换意图并自动准备）。保存后提示却写“已保存，模型在后台切换，进度见「状态」”，与事实不符。

改法（只改 `lib/client.js`，后端已支持这两个字段，不改后端）：
1. 当所选模型与当前生效模型不同（`draft.rawRecallModel!==info.rawModel.fields.rawRecallModel`，或自定义服务的 `rawRecallApiBase` / `rawRecallApiModel` / `rawRecallDimensions` 与当前不同）时，保存请求加 `confirmSwitch:true`，云端模型同时加 `cloudConfirmed:Boolean(draft.rawRecallAllowCloud)`。只改常驻、设备等参数、模型不变时不加。
2. 保存成功后的提示按情况写：
   - 换了模型：`已保存。重启 DSH 后切换到新模型，并自动开始建索引；进度在「状态」页。建好之前，按意思检索暂不可用，文字检索照常。` 云端模型再加一句 `建索引会把纳入索引的内容发送到服务商并计费。`
   - 只改参数：`已保存，重启 DSH 后生效。`
3. 云端模型在点保存前（勾选框旁）补一行说明：`保存并重启后会自动建索引，费用按服务商价格计算。`
4. 测试：换模型时请求体带 `confirmSwitch:true`；云端带 `cloudConfirmed:true`；只改常驻时两个字段都不带；提示文字按情况出现，不再出现“在后台切换”。

## A3：自定义 API 用的是 Qwen3-Embedding 时，检索问题加指令

现状：`lib/raw-rag/models.js` 第 39 行按注册 id 判断模型族；`custom-api` 永远是 `provider-embedding`，所以通过硅基流动等服务调用 `Qwen/Qwen3-Embedding-*` 时，查询不会加 `Instruct: …\nQuery: ` 前缀，检索效果打折。

改法：
1. `custom-api` 时：`apiModel` 匹配 `/qwen3-embedding/i` → 族为 `qwen3-embedding`（加查询指令，与本地 Qwen3 一致）；其他一律 `provider-embedding`（例如 `BAAI/bge-m3` 不加任何前缀，**不要**套用 bge-v1.5 的中文指令）。
2. 只影响查询文本，文档文本不变。模型族本来就进入索引身份（第 100 行），Qwen3 自定义服务的索引身份会随之改变，这是预期的；`BAAI/bge-m3` 等其他自定义服务的索引身份必须**不变**（写一个测试锁住）。
3. 测试：自定义 `Qwen/Qwen3-Embedding-8B` 的查询带指令、文档不带；自定义 `BAAI/bge-m3` 查询和文档都不带前缀，`modelContract` 与改动前相同。
