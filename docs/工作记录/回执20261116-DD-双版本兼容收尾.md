## 2. 双格式补导

### 2.1 宿主格式结论

对照 rc.5 宿主源码和 rc.3 私有安装源码后确认：

- 两版实际写出的都是 `session.v4.jsonl.zstd`，采用多帧 zstd，外层版本相同。
- rc.3 的会话包新增了 `team/mode` 事件，并加强了 `subagent/catalog` 的 version 3 名称、唯一性和关系校验；rc.5 的静态格式目录仍能恢复本次 rc.3 实例产生的普通会话。
- rc.3 普通会话和 rc.5 普通会话的用户/助手消息主体结构相同；部分 rc.3 用户消息带有 `rpcId`、`clientTimeZone` 等额外来源字段。
- `dsh-api-session-controller` 的批量发布、子代理关系和运行期会话 API 差异不改变磁盘正文格式。

### 2.2 实现

修改 `lib/raw-rag/history.js`：

- 正常会话仍先走原有 `sessionFormatCatalog` 严格恢复，旧格式成功路径不变。
- 严格恢复失败时，对 v4 逐行构造容错视图；保留结构有效的已知/扩展事件，按 `seq` 定位，缺失位置不拖垮后续完整回合。
- JSON 损坏、缺字段、重复序号或越界序号计为 `skippedRows`；看不懂的完整行跳过并计数。
- 预览计划新增 `summary.sourceSkippedRows` 和每个来源的 `parse.mode`、`skippedRows`。
- 实际导入新增 `sourceSkippedRows`，同一来源恢复时不会重复累计。
- `scripts/raw-memory.mjs` 原入口和现有参数未改。

新增虚构夹具：

- `test/fixtures/raw-history/rc5-session.jsonl`
- `test/fixtures/raw-history/rc3-session.jsonl`
- `test/fixtures/raw-history/recoverable-session.jsonl`

新增测试覆盖：

- rc.5 和 rc.3 的正常 v4 样本都走严格路径；
- 用户原文、助手回复、原始时间和回合号；
- 缺字段、损坏 JSON、未知扩展事件时跳过并计数；
- 完整回合不被坏行拖垮；
- 预览与实际导入都报告 `sourceSkippedRows: 2`。

## 7. 发现和需要决定

1. `scripts/raw-memory.mjs apply` 当前会为 `createRawRecall` 立即准备嵌入后端；临时部署没有本地 BGE 资源时，CLI 会以 `BGE assets not found` 在写库前停止，即使只想导入全文。本次为避免扩大范围，没有修改 CLI，而是直接调用同一 `applyHistory` 核心并传入不编码向量的空检索器完成两版实跑。是否需要给 `raw-memory apply` 增加明确的全文-only 模式，留 Claude 决定。
2. 本次 rc.5 未发现其他插件代码缺陷；DA 的 `isOwnedBy` 路径在真实子代理请求中工作。
3. rc.3 的 `team/mode` 和增强后的 subagent catalog 关系属于宿主新增能力；本次普通会话样例没有触发读取失败。若以后补导包含这些扩展的会话，现有逐行容错会保留结构完整行，未知内容不参与直接用户/助手回合提取。
