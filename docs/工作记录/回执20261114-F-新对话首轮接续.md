## 改动

### 首轮预选与顺序

`lib/index.js` 在首回合 `onPreStep` 且尚无受保护系统头时预选接续，将消息放在本轮原始用户消息之前。宿主在系统提示之后写入该消息，因此实际顺序为：

```text
system-prompt
memory-handoff-context
user
agent-instructions / runtime-context / skill-catalog
memory-prefetch
memory-answer-rules
```

首轮没有其他材料时，会把本次接续记为成功但为空，不注入空消息，也不反复产生延迟告警。

### 状态衔接

`onRequest` 继续调用现有 `handoff.begin`。若首轮已预选接续，只使用预先生成的消息编号登记 `prepared` 并标记 `delivered`，不追加第二条；不满足接续条件或准备失败时，撤回本轮预选并复用现有消息过期逻辑。

普通会话仍通过既有 `finish`、`lastDelivered`、`unchanged` 路径保护前缀。已有系统头的会话换模型仍走原 `onRequest` 路径。只读会话只保留本轮内存标记和报告，不调用接续状态写入，也不登记目标。

### 闸门

首轮预选继续要求：

- 会话已开启记忆且读授权有效；
- `recentContext !== false`；
- 当前是根智能体；
- 宿主会话具备持久化 `append` 能力；
- 首回合尚无系统头且没有既有接续消息。

- `test/session-read-only.test.js`：按真实顺序覆盖只读首轮接续、系统头后的位置、第二回合不重复和不写接续状态。
