# 任务单 2026-11-16-O2：首次使用向导

工作区：`<工作区 o2>`（分支 `o2-first-run-wizard`，基于合并了 O 批之后的 main）。执行方按本单实现，不提交；Claude 复核后提交。

## 背景

用户反馈：首次使用应该有流程一步步引导用户建库，位置可以自己选。

O 批之后，没启用记忆时「记忆」页显示的还是原来的首次配置：一个路径输入框和几组按钮，没有说明一共几步、现在在哪一步。用户在全流程验收里实际卡住过：不知道要先准备并启用、重启 DSH，然后才能配检索模型。

另有一处会误导用户：首次配置里"选择使用新记忆库的聊天"只写进配置的 `dshSessionIds`。启用后，真正决定一个对话读不读、记不记的是对话页的记忆开关（`sessionMemory`），勾选的聊天并不会打开记忆。

## 目标：五步向导

在设置页「记忆框架」→「记忆」分页，用一个分步向导取代现有的首次配置区块。顶部显示"第 n 步 / 共 5 步"和五个步骤名，已完成的步骤打勾。

**当前步骤由服务端状态决定**（是否已配置、是否已安排启用、记忆框架是否已加载、检索模型是否可用），刷新页面或重启 DSH 后都回到正确的一步。

### 第 1 步：选记忆库位置

- 预填建议位置（现有的默认位置）。说明这个文件夹用来存什么，只存在本机。
- **「选择文件夹…」按钮**：复用 DSH 自己选工作区时用的选文件夹功能。
  - DSH 客户端服务 `uiWorkspace` 提供 `pickDirectory()`（本机原生窗口）；只有"浏览"能力时，它提供 `listDirectory` 和 `createDirectory`。
  - 先读 DSH 运行时里 `dsh-client-ui-workspace`、`dsh-client-ui-directory-picker-native`、`dsh-client-ui-directory-picker-browse` 和 `dsh-api-workspace-controller` 的实现，弄清能力怎么判断、取消时返回什么。
  - 原生和浏览两种都能用最好；只能做一种时，另一种情况退回手动输入，并在回执说明。
  - 插件客户端对 `uiWorkspace` 的依赖必须是可选的：拿不到时隐藏按钮，只留输入框，页面不能报错。
- 输入框可以直接改路径。
- **即时检查**：新增一个只读接口，例如 `POST /api/basic-memory-bootstrap/location`，挂在首次配置路由下，沿用现有的访问检查。它只检查、不创建任何东西，返回状态和一句中文说明，至少区分：
  - 不存在：会新建；
  - 空文件夹：直接使用；
  - 已有本插件的记忆库（有初始化记录）：问"接着用这个库"；
  - 有其他文件：不能直接用，提供"在这里新建一个子文件夹"的按钮，子文件夹名由你定，回执写明；
  - 和现有个人库、群目录、旧 Vault 重叠：说明原因；
  - 不是绝对路径、没有写入权限或是链接：说明原因。

  判断规则必须和现有 `validateNewMemoryLocation`、`initializeMemoryDirectory` 一致，不能出现"检查说可以、创建时报错"。
- 「下一步」才真正创建配置，沿用现有的创建接口。

### 第 2 步：选哪些聊天打开记忆

- 列出 DSH 现有聊天（沿用现有聊天列表）。勾选的聊天**在启用成功后直接打开记忆**，效果和用户在对话页点开开关完全相同，从下一回合开始读和记。
- 一个选项"以后新建的对话自动打开记忆"，默认不勾。对应已有的 `autoEnableNewSessions` 配置。
- 可以一个都不选，提示"以后可以在对话页单独打开"。没有任何聊天时也能继续。
- **同意只用一次**：
  - 这一步的勾选是用户明确同意，随"安排启用"一起记下来，例如写进 `activation.json` 的一个新字段。
  - 启用成功后，用和对话页开关同一条路径打开这些聊天的记忆，并记录已经执行过，以后重启不再重复执行。
  - 旧配置里已有的 `dshSessionIds` 不能被当成同意。
  - 启用失败时不打开任何聊天。

### 第 3 步：启用并重启

- 「启用」按钮安排下次启动时启用，沿用现有接口；也可以取消。
- 写明要重启 DSH，以及怎么重启，用一般说法：关闭 DSH 再重新打开；如果是在命令行窗口启动的，在那个窗口按 Ctrl+C 停止后，重新运行同一条命令。
- 页面开着时，定时查询 bootstrap 状态。检测到记忆框架已加载就自动进入第 4 步，不需要用户刷新。
- 启用失败（`activationError`）时显示原因和能做什么，可以回到第 1、2 步修改。

### 第 4 步：配置检索模型

- 内嵌「检索模型」分页里现有的向量服务表单，复用同一个组件，不要另写一套：填服务地址、模型、密钥文件，测试连接，保存。
- 简短说明：重排可以以后在「检索模型」页打开。
- 可以「先跳过」。跳过记录在浏览器本地存储里（读写都要放在 try/catch 里；读不到就再显示一次，没有害处）。
- 检索模型已经可用（已选好接口服务，或已装好本地模型），或者用户选了跳过，就算这一步完成。判断依据由你定，回执写明。

### 第 5 步：完成

- 汇总：记忆库位置、哪些聊天已打开记忆、新对话是否自动打开、检索模型的状态。
- 告诉用户：打开记忆的对话从下一句话开始记录；其他对话可以在对话页的记忆开关单独打开。
- 「记忆」分页回到正常内容。向导不再出现，除非检索模型变成不可用，且用户没有选过跳过。

### 共通要求

- 第 3 步安排启用之前，可以回到第 1、2 步修改；安排之后，第 1、2 步只显示已选内容，要改得先取消启用。
- 老用户、日常部署（显式 portable 模式、记忆已加载、检索模型可用）完全看不到向导，页面和现在一样。
- 「检索模型」「状态」「维护」三个分页在没加载时的指引保留 O 批的做法，按钮改成跳到向导的当前步骤。
- 文案用平常话，不出现 bootstrap、fingerprint、runtime、profile、portable 这类词。
- 浏览器控制台全程 0 错误、0 个 404。

## 实机验证（必须做）

用全流程测试用过的独立 DSH 运行时（`<独立运行时目录>`，0.2.1-rc.5），每轮新建一个临时 `DSH_HOME`，端口只用 8943，插件从工作区本地路径安装，不配模型、不填密钥。先在 DSH 里建两个空聊天。

1. **位置检查**：依次试一个有其他文件的文件夹（应提示并给出新建子文件夹按钮）、一个已有记忆库的文件夹（应提示接着用）、一个不存在的路径（应提示会新建）。
2. **选文件夹按钮**：确认按钮出现、能打开选择窗口。原生窗口没法自动操作时，打开后取消即可，路径用输入框填；回执写明。
3. **建库**：用新路径建库 → 第 2 步勾一个聊天、勾"新对话自动打开" → 第 3 步启用 → 刷新页面，确认仍停在第 3 步。
4. **重启**：重启 8943，页面自动进入第 4 步。勾选的那个聊天在对话页已经是"记忆已打开"，没勾的那个仍是关闭；再新建一个聊天，确认它自动打开了记忆。
5. **收尾**：第 4 步选跳过 → 第 5 步汇总正确 → 「记忆」分页回到正常内容 → 刷新后向导不再出现。
6. **重启不重复**：再重启一次，确认没有重复执行"打开勾选聊天"。先在对话页手动关掉那个聊天的记忆，重启后它仍是关闭。
7. 全程控制台错误数和 404 数逐步记录。做完停掉 8943 和浏览器，临时目录保留，回执用 `<临时目录>` 占位。
