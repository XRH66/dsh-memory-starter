## 改动文件

### `lib/handoff.js`

- `selectHandoff` 现在跳过整个当前会话的原文，不再只跳过当前轮；候选始终来自其他会话。
- 返回值新增 `newest`，记录遍历中第一条可用的其他会话原文 `{id,revision}`，与 token 预算和是否截断无关；无候选时为 `null`。
- 每个会话状态新增 `lastDelivered:{messageId,newest}`。
- `prepared` 的 receipt 保存 `newest`。
- `finish` 仅在本轮完成、已准备好、已送达且 receipt 有 `messageId` 时更新 `lastDelivered`。
- `begin` 返回调用时已有的 `lastDelivered`；旧状态缺少该字段时按 `null` 读取。

### `lib/context.js`

- 抽出既有消息组替换逻辑，供记忆上下文和接续消息共用。
- 新增并导出 `expireHandoffMessages(session,{turn,step})`，替换当前会话中所有 `source.kind===MEMORY_HANDOFF_SOURCE` 的消息。
- `expireMemoryContext` 的原有筛选、打开步骤要求、替换事件和返回值保持不变。

### `lib/index.js`

- 子代理请求在进入接续流程前被排除，不调用 `handoff.begin`，也不调用 `handoff.observeTarget`。
- 接续分支先读取 `attempt.lastDelivered`，检查旧消息是否仍在 `session.deriveMessages()` 中，并比较最新原文的 `id` 与 `revision`。
- 无新内容时复用旧消息：不追加消息，receipt 使用旧 `messageId` 和当前 `newest`，报告状态为 `unchanged`。
- 有新内容时，正常路径先替换当前会话来所有旧接续消息，失败仅记录 `[memory-handoff] replace: ...` 警告，然后追加新消息。
- 其他会话没有任何原文时，继续沿用 `empty` 分支，不清理旧消息。
- receipt 统一携带 `newest`，原授权检查和 `revokePending()` 调用顺序保留。

### `lib/session-memory.js`

- 新增只读 `isRootAgent(agent)`，复用现有 `rootAgent()` 的运行时所有权判断；身份无效或判断失败时返回 `false`。

## 子代理结论与依据

结论：当前实现中子代理请求会进入 `dsh.onRequest`，且子会话 id 与根会话不同，因此必须阻止子代理参与接续。

- `lib/platform-host.js:138` 对所有 `tracks(payload.agent.id)` 为真的请求调用 `dsh.onRequest`；使用 `sessionMemory` 时，`tracks` 只校验 id 格式，不判断是否为根会话。
- `lib/session-memory.js:33` 的 `rootAgent(agent)` 沿 `agents.isOwnedBy()` 查找运行时根代理。
- `lib/session-memory.js:79-82` 同时保留 `sessionId: agent.session.id` 与 `rootSessionId: root.session.id`，证明子会话身份可与根会话不同。
- `lib/memory-policy/index.js:149` 明确说明受控子代理可以检索和处理根来源，因此不能假设子代理请求天然被授权层排除。

实现后，子代理请求在进入接续状态更新前返回；新增测试验证子代理不注入、不创建接续状态，且下一轮根会话 generation 不变。
