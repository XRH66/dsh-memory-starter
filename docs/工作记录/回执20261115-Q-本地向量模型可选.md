## 老用户识别

查过 `v0.4.0`、`v0.5.0`、`v0.6.0` 三个标签的：

- `lib/bootstrap-host.js` 的 `createBootstrap()`；
- `lib/config.js` 的默认模型和首次配置默认值；
- `lib/client.js` 的「检索模型」页；
- `v0.6.0` 的 `scripts/install/configure.mjs`；
- 各标签的安装器和 `lib/deployment-config.js` 写模型设置的部分。

结论：

1. 三个版本的首次配置都只写 `captureProvider`、`captureModel` 等字段，省略 `rawRecallModel`。
2. 三个版本的运行时缺失该字段时都回退到本地 `BAAI/bge-small-zh-v1.5`。
3. 后续运行安装器或保存模型时会写入模型字段和 `rawRecallInstallReceipt`；旧版统一向量档位则在 `profiles.json` 中记录所选模型。
4. `v0.6.0` 的 `configure.mjs` 只生成部署路径和人设配置，记忆插件仍由首次配置页写入，因此也不能靠它区分新老用户。

因此按以下顺序识别：

- 明确写了 `rawRecallModel`：原样保留。
- 没写模型，但有非空 `rawRecallInstallReceipt`：视为默认本地用户，补齐本地模型。
- 没写模型，但 `management/vectors/profiles.json` 中当前选中的档位是默认本地模型：视为默认本地用户，补齐本地模型。
- 没有任何本地痕迹：使用新的 `custom-api` 默认。

迁移在部署配置启动读取时完成，只补一个显式模型字段，不改地址、密钥或其他检索设置。只检查“当前选中”的本地档位，不因为仅保留在历史里的旧本地档案而覆盖当前云端选择。

## 发现与取舍

- Schemastery 的单字段 `default()` 不能读取同级安装回执，因此真实老用户迁移放在部署配置读取层；纯 `resolveConfig()` 仍对回执提供本地模型回退，但不会单独读取向量档案文件。
- 只按当前选中的默认本地档位迁移，不把仅保留在历史里的本地档案当作“正在使用”；这样可避免覆盖已经明确选择云端的用户。
- 新增测试是 Git 跟踪代码，按现有发布校验规则列入 `release-files.json`；本回执是工作记录，按任务要求只用 `git add -N`，不进入发布清单。

## Claude 复核（2026-11-15）

结论：通过，修一处缺陷，去掉兼容薄壳。

- 老用户识别与我事先查的结果一致：0.4～0.6 首次配置都不写 `rawRecallModel`，按"明确写了 → 安装回执 → 当前选中的默认本地档位"的顺序认出老用户，正确。迁移只在部署配置启动加载时补一个显式字段，沿用现有的指纹核对和原子写入；明确选了云端的不被陈旧本地证据覆盖。日常部署配置明确写着 `custom-api`，不受影响。
- `inspectCloudRawModel` 与旧 `inspectSelectedInstallation` 的云端分支逐行一致。
- **修复（缺陷）**：新用户打开原话检索、还没填云端模型名时，启动登记向量档位（`memory-vectors.js` 的 `registerCurrentConfig`）会抛出"请填写自定义 API 的模型名称"。运行状态接口和各项运行操作都要先等这一步，状态页会整个报错。实测方法：把被改成"显式写本地模型"的 10 个测试文件恢复原版（不写模型），在新代码上跑 93 项，3 项失败，其中 2 项就是这个问题。改为在这种状态下跳过登记、返回 `MODEL_NOT_CONFIGURED`，向量保持不可用，其他照常；把"云端默认但没填模型名"的判断提成 `models.js` 的 `cloudModelUnset()`，原来两处内联判断一并改用它。剩下 1 项失败是本地与云端的向量等待时限不同（2.5 秒和 4 秒），属预期。
- 测试：`portable-session-memory` 的"统一向量接管检索"和 `session-read-only` 的"只读回合仍有预取、搜索和首轮接续"两条用例恢复为不写模型，正好覆盖新用户默认路径（前者加断言确认生效模型是 `custom-api`）。去掉修复时这两条失败，恢复后通过。
- **去掉兼容薄壳**：三处旧路径薄壳只服务 `scripts/embedding-model.mjs` 和两份说明文档里的链接。已把脚本的导入、`MODEL-SETUP.zh-CN.md` 与 `THIRD-PARTY-NOTICES.md` 的链接改到 `lib/raw-rag/local/`，删掉薄壳，并从 `package.json` 和 `release-files.json` 去掉。
- 复核后全量：Node 24 与 Node 22.19 各 692 通过、0 失败。
