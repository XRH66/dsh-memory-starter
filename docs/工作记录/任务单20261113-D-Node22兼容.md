# 任务单 D：Node 22.19 兼容（2026-11-13）

`package.json` 的 `engines` 声明支持 `^22.19 || >=24`。阶段 1 实测 Node 22.19.0 全量测试结果为 691 通过、17 失败、6 取消，失败集中在连接超时、Windows 启动脚本、历史导入和 SQLite 相关测试。用户决定**修好兼容**，不收窄支持声明。

## 步骤

1. 从 nodejs.org 官方下载 Node 22.19.0 的 Windows x64 便携包（`node-v22.19.0-win-x64.zip`），校验官方 `SHASUMS256.txt` 中的哈希，解压到 `.local/tools/node-v22.19.0-win-x64/`。不安装到系统，不修改 PATH。
2. 用这个 `node.exe` 跑全量测试：`<该 node> --test --test-timeout=60000 test/*.test.js`。逐个记录失败和取消的测试，以及失败原因。
3. 按根因分类修复。修法必须通用，同时兼容 22.19 和 24：
   - 必要时用特性检测，例如 `node:sqlite` 的 API 差异、`AbortSignal.any`、`zlib` 的 zstd 支持、`fs` 选项、`process.getBuiltinModule` 等；
   - 不针对某个版本号写分支，除非没有别的办法，并在回执里说明理由；
   - 某项能力在 22.19 上确实不存在时，例如 zstd 压缩：如果它只被测试用到，就让测试在缺少该能力时**明确跳过并说明原因**；如果产品代码用到，要么提供可用的替代实现，要么写入回执，交给 Claude 决定。
   - 不允许用增大超时、关闭断言的办法掩盖失败。
4. 修完后，两个版本都要全量 0 失败：用 22.19 便携包跑一次，用系统的 Node 24 跑一次。跳过的测试要逐条列出原因。
5. 修改 `.github/workflows/release-check.yml`，改成 Node 22.19 和 24 的矩阵，两个版本都运行 `npm ci`、`npm test`、`npm run release:check`。

## 可以改的文件

`lib/` 中与失败直接相关的文件、`test/` 中相关测试、`scripts/` 中与失败直接相关的文件、`.github/workflows/release-check.yml`。改动范围以修复失败为限，回执里逐个文件说明原因。

## 验收

1. Node 22.19.0 和 Node 24 全量测试均为 0 失败，跳过的测试单独列出并说明理由。
2. `node scripts/check-release-export.mjs --validate-only` 通过。
3. `node .local/automation/check-tracked-privacy.mjs --worktree` 违规为 0。
4. `git diff --check` 通过。
5. 回执写到 `docs/工作记录/回执20261113-D-Node22兼容.md`，内容包括：
   - 失败清单；
   - 每类失败的根因和修复方式；
   - 两个版本的测试结果。
