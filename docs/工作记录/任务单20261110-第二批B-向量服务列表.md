## 用户要的功能

检索模型页选「自定义 API（OpenAI 兼容）」时，能把用过的服务（例如硅基流动的 bge-m3）**存成一个列表**，可以**新建、编辑、删除、选用**。现在只有一个自定义位置：切到别的模型再切回来，地址和模型名就变空了，Key 也要重填。

## 数据（`lib/deployment-config.js`）

1. 部署配置新增 `embeddingServices: [{ id, name, apiBase, apiModel, dimensions, apiKeyFile, apiKeyService, createdAt, updatedAt }]`，`id` 用 `randomUUID()`。最多 20 个。
2. `readDeploymentSettings` 返回 `embeddingServices` 的**公开形式**：`{ id, name, apiBase, apiModel, dimensions, hasKey, inUse }`，`inUse` 表示当前生效或待生效的模型正在用它（按 `apiBase`+`apiModel`+`dimensions` 与 `cfg.memory` / `cfg.pendingRawRecall` 比对，且二者为 `custom-api`）。**不返回** `apiKeyFile`、`apiKeyService`。
3. `removeUnusedStagedKey` 的引用列表加上所有服务的 `apiKeyFile`，保证被列表引用的密钥文件不会被清理。
4. 新增 `manageEmbeddingServices(file, input, expectedRevision)`，与现有函数一样使用 `.lock` 文件和 `deploymentFingerprint` 版本检查，动作：
   - `save`：新建（无 `id`）或编辑（有 `id`）。字段校验复用现有规则：地址必须 https（用 `embeddingEndpoint` 校验，**不要放宽**）；模型名 1–200 字符、无控制字符；维数 1–4096 整数；名称 1–60 字符，空则默认 `<地址主机名> · <模型名>`。带 `apiKey` 时按现有方式写新密钥文件（`randomUUID()+'.key'`，`mode:0o600`，`flag:'wx'`），`apiKeyService` 记为 `embeddingEndpoint(apiBase)`；编辑时换了新 Key，旧 Key 文件在不再被任何地方引用时删除（复用 `removeUnusedStagedKey`）。**编辑时如果改了地址而没给新 Key，拒绝**：`服务地址已改变，请填写这个地址对应的 API Key`。
   - **正在使用的服务（inUse）只能改名称**，改地址/模型名/维数/Key 一律拒绝：`这个服务正在使用；要更换地址、模型或密钥，请先切到其他模型`。
   - `delete`：正在使用的服务拒绝删除；删除后其 Key 文件在不再被引用时删除。
   - 不提供“读取 Key”的动作。
5. 选用服务保存模型：`stageDeploymentRawModel` 接受 `input.serviceId`。有 `serviceId` 时，从列表取 `apiBase`/`apiModel`/`dimensions`/`apiKeyFile`/`apiKeyService` 填入待生效设置（`rawRecallModel:'custom-api'`），不要求再填 Key、也不触发“服务地址已改变”的报错（因为 Key 与地址是列表里成对保存的）。`serviceId` 不存在时报 `所选服务已不存在，请刷新`。
6. 用户在检索模型页直接填写自定义服务并保存（不经过列表）时，保存成功后**自动把这套配置加入列表**（按地址+模型名+维数去重：已存在则只更新它的 Key 引用和 `updatedAt`），这样当前正在用的硅基流动配置在用户下次保存时会自动进入列表。

## 接口（`lib/settings-host.js`）

新增 `POST /api/basic-memory-settings/embedding-services`，body `{ action:'save'|'delete', revision, id?, name?, apiBase?, apiModel?, dimensions?, apiKey? }`，返回与 `/model` 相同的 `{ ok:true, ...readDeploymentSettings 的结果 }`。同样要求请求头 `x-basic-memory-settings: 1`，沿用现有路由的写法和错误处理。保存服务**不需要**重启，不调用 `afterSave`。

## 界面（`lib/client.js` 的 `ModelPicker`）

选中「自定义 API」时，在现有输入框上方加：
1. **「已保存的服务」下拉**：列出 `info.embeddingServices`（显示 `名称（模型名）`，正在用的加“当前使用”），外加一项「新建服务…」。选中某个服务 → 输入框填入它的地址、模型名、维数，Key 输入框留空并显示 `已保存，留空沿用`（`hasKey` 为真时）；点「保存」时请求带 `serviceId`。
2. 选中服务后显示两个按钮：**「编辑」**（展开同样的地址/模型名/维数/Key/名称输入框，点「保存服务」调用 `save`；正在使用的服务只开放名称）和 **「删除」**（先出现确认行 `删除「<名称>」？只删除这条服务配置和它的密钥，不影响已有记忆和索引。` + 「确认删除」「返回」；正在使用的服务按钮置灰，旁边说明 `正在使用，不能删除`）。
3. 选「新建服务…」：输入框清空，填完后既可以直接点「保存」（保存模型，并按第 6 条自动入列表），也可以点「只存入列表」（调用 `save`，不切换模型）。
4. 所有按钮在请求进行中置灰；出错时显示后端返回的中文错误。不使用浏览器 `confirm()`。

## 测试（新增，全部用虚构地址如 `https://fictional-a.example/v1`、虚构 Key）

- 界面：下拉列出服务并能选用；选用后保存请求带 `serviceId`；编辑、删除确认、正在使用时的置灰与说明；「只存入列表」不调用 `/model`。
