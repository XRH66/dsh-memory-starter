# 任务单 2026-11-16-O：首次引导、继承脚本随包、配对回复

工作区：`<工作区 o>`（分支 `o-first-run-package`，基于 main 的当前提交）。执行方按本单实现，不提交；Claude 复核后提交。

## 背景

0.7.0 发版前的全流程验收（[任务单 G](任务单20261115-G-0.7.0全流程验收.md)、[回执](回执20261115-G-0.7.0全流程验收.md)）只有第 12 段干净安装不通过，另外发现两处问题：

1. **未启用记忆时页面报错**：新装好、还没启用记忆框架时，DSH 不提供 `/api/basic-memory-settings/*` 这些接口，直接回一个纯文本 `not found`。设置页和对话页照样去请求，把 `Unexpected token 'o', "not found" is not valid JSON` 原样显示出来，浏览器控制台有 3 条 404。「检索模型」「维护」分页只有这行报错，没有说明下一步。用户实际卡在这里：照"先配向量服务"的顺序做，「检索模型」页是空的，不知道要先在「记忆」页准备并启用、重启 DSH。
2. **安装包里没有继承脚本**：`package.json` 的 `files` 不含 `scripts/inherit-memory.mjs` 和 `lib/inherit/`，用 `dsh plugin add` 安装的老用户升级时拿不到继承旧笔记的工具，而升级说明要求用它。
3. **配对回复被当成用户的话**（项目状态"未解决"第 9 条）：检索结果里，用户那条下面挂着键名为 `助手当时回复` 的字符串，H 回归里有一题把这段回复说成了用户自己说的。

## 目标

### 1. 未启用记忆时的页面

涉及 `lib/client.js`，必要时 `lib/bootstrap-host.js`。

- **先判断再请求**：用始终存在的 `/api/basic-memory-bootstrap` 判断"本次 DSH 启动时记忆框架是否已加载、设置接口是否可用"。现有返回值不够判断的，给它加一个字段（名字由你定，回执写明含义和取值）。没加载时，页面**不再请求** `/api/basic-memory-settings/*`，浏览器控制台不能出现 404。
- **不显示解析报错原文**：所有读取 `/api/basic-memory-settings/*` 和 `/api/basic-memory-bootstrap` 的地方，响应不是 JSON 时，不把 `Unexpected token…` 这类原文显示给用户，改成中文提示。
- **「记忆」分页**：
  - 还没准备时，照常显示首次配置，不出现红色报错；
  - 已准备、已安排"下次启动时启用"但还没重启时，明确写：重启 DSH 后生效，生效后再到「检索模型」配置向量服务。
- **「检索模型」「状态」「维护」分页**：记忆框架没加载时，只显示一段说明和一个跳到「记忆」分页的按钮。说明的意思是：记忆框架还没启用，先在「记忆」页准备记忆库并启用，重启 DSH 后再来这里配置。
- **对话页的记忆开关**（现在显示"重试记忆状态"的那一处）：记忆框架没加载时，显示"记忆未启用"和去设置页的指引，不显示报错原文，不反复重试。
- 记忆框架已加载之后的页面行为不变。

### 2. 继承脚本随安装包

- `package.json` 的 `files` 加上 `scripts/inherit-memory.mjs` 和 `lib/inherit/` 下它用到的全部文件；`release-files.json` 缺的也补上。**不改 `version`**（打标签时再改）。
- 用 `npm pack` 打出的包解到临时目录，在那里实际运行一次继承脚本（例如对一个虚构 Vault 跑 `check`），确认不缺文件、不缺依赖。依赖要靠插件自己的 `node_modules` 时，写清楚在什么环境下能跑。回执写结果。
- 文档：`README.md`、`docs/install/upgrade.md`、`docs/install/setup.md` 里运行继承脚本的命令，改成从已安装的插件目录运行（插件在 DSH 档案的 `node_modules/@local/dsh-basic-memory-bridge/` 下，按实际安装结构写），同时保留"也可以在仓库检出目录运行"。
- 现有"npm 包只含已跟踪文件"之类的测试按新清单调整；新增断言：打包结果包含继承脚本和 `lib/inherit/` 的文件。

### 3. 配对回复写明说话人

涉及 `lib/suzu/search-session.js` 的 `modelRecord`。

- 不再用字符串键 `助手当时回复`，改成带说话人的嵌套对象：键名 `同一回合助手的回复`，值是 `{label, text}`。`label` 以"助手"开头，格式和检索结果里助手原话记录的 `label` 一致（同一回合，时间相同）；`text` 照旧最多 120 字。
- 其余不变：截断长度、预算计算、哪些情况配对、预取不带回复。
- 不改回答规则、工具描述和提示词。
- 更新 `test/assistant-provenance.test.js` 里对应的断言，并新增一条：配对后的结果里，回复的说话人在结构上能和用户原话区分开。
