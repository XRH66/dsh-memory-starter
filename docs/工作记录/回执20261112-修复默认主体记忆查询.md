# 回执：修复默认主体下的记忆查询失败

创建：2026-11-12 03:28，America/Los_Angeles。

关联任务单：[任务单20261112-修复默认主体记忆查询](任务单20261112-修复默认主体记忆查询.md)。

## 根因

首次配置未显式提供 `ownerSubject` 时：

- 会话授权使用默认主体“用户”；
- 原始记忆运行时收到的 owner 仍为空；
- `memory_search` / `memory_recent` 查询与授权主体不一致，被判为 `Message scope changed`；
- 工具层把内部异常收敛成通用 `BACKEND`，模型再向用户表达成“记忆后端不可用”。

## 代码改动

- [lib/platform-host.js](../../lib/platform-host.js) 只解析一次有效主体：
  - 显式配置时使用配置值；
  - 未配置时使用“用户”；
  - 会话授权、原始记忆查询和对外服务共用同一值。
- [test/portable-session-memory-host.test.js](../../test/portable-session-memory-host.test.js) 新增默认主体集成回归，实际执行 `memory_recent`，要求返回空结果而不是后端错误。

## 体验问题（后续优化）

当前模型在工具返回 `BACKEND` 时会直接对用户说“记忆后端没能返回结果”，明显出戏。

建议后续把用户话术和技术错误分层：

- 技术错误只写日志和状态页；
- 对话侧改为自然的临时说法，例如“这条我一时没想起来，你再提醒我一下”；
- 不向用户暴露“后端、工具、接口失败”等实现细节；
- 模型仍需遵守“不编造记忆”的事实边界。

本次只记录，不修改这条用户话术。
