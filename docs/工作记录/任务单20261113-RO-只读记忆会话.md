# 任务单 RO：只读记忆会话（2026-11-13）

## 目的

给单个会话提供"只读"模式：可以读记忆，包括预取、`memory_search`/`memory_open`/`memory_recent` 和短期接续；但这个会话的任何内容都不写回记忆。

两个用途：

1. **正常基准执行器**（N 批）：同一截止点的多道考试题要并发作答。考试会话必须只读，否则一道题的问答会被另一道题检索到，也会进入后续的接续和整理。现行执行器靠"答完再撤回"兜底，既慢，又不能并发。
2. **产品功能**："这次对话用记忆，但别记下来"，即无痕对话。本批只做接口和状态，界面开关以后再说。

## 现状（Claude 已读代码）

- `lib/session-memory.js` 的控制器有 `set(sessionId, enabled)`、`check(agent)`、`status(sessionId)`，底层授权在 `lib/memory-policy/`，带区间和纪元（epoch）。
- `lib/index.js` 中，会话的写入点有：
  - `onSessionEvent` 里的 `messageRecorder?.observe(...)`：保存原话，并经订阅通知整理流水线和向量索引；
  - `turn/end` 里的 `finishHandoff(...)`：写入短期接续状态，下一个会话会读到；
  - `bindTurn`：签发写入用的来源授权；
  - `onRequest` 里的 `handoff.observeTarget(target)`：记录接续目标模型；
  - `soften_memory` 工具：淡化已存记忆；
  - `pipeline.markChange` 等由本回合触发的整理标记，如果有的话。
- 读取路径用的是 `memoryReadAuthorization`，由 `onPreStep` 里的 `access.grant(agent)` 签发。

## 要求

1. **控制器接口**：在 `session-memory.js` 的控制器上增加：
   - `setReadOnly(sessionId, readOnly)`；
   - `isReadOnly(sessionId)`。
   `status(sessionId)` 的返回值增加 `readOnly` 字段。只读标记只在记忆已开启时有意义：记忆关闭的会话，只读标记不产生任何效果，但仍保留标记值。
2. **持久化**：只读标记单独保存在 `session-memory` 现有存储目录下的一个小文件里，用原子写入（先写临时文件再改名），重启后仍然有效。**不改 `lib/memory-policy/` 的授权语义**，包括区间、纪元和授权种类。只读是叠加在"已开启"之上的一层写入抑制。
3. **写入抑制**：只读会话中，以下行为全部不发生：
   - 原话保存，因此也不会通知整理流水线和向量索引；
   - 短期接续写入（`finishHandoff`），以及 `observeTarget`；
   - 写入来源授权（`bindTurn` 直接返回，不签发）；
   - 整理标记。
   `soften_memory` 在只读会话中不出现在工具列表里；如果该工具由大肥鱼注册、本插件控制不了，就让它在只读会话中执行时返回明确的拒绝，并且不写盘。
   读取照常：预取、三个查询工具、接续读取（新会话第一回合注入的近期对话）都不受影响。
4. **判断时机**：只读状态在每回合 `turn/start` 时读取一次，存进该回合的状态，避免回合中途切换导致半写。中途切换从下一回合生效，与现有"开关下一回合生效"的语义一致。
5. **测试**（新建 `test/session-read-only.test.js`，参考 `test/portable-session-memory.test.js` 和 `test/handoff-head-replay.test.js` 的夹具）：
   - 只读会话完成一回合后：原话库没有该会话的消息，整理队列没有新任务，向量队列没有新任务，接续状态没有变化；
   - 只读会话里，预取和 `memory_search` 能读到另一个普通会话已保存的内容；
   - 只读会话第一回合仍能拿到接续消息（来自之前的普通会话）；
   - 两个只读会话并发作答，互相检索不到对方的问答；
   - 切换只读从下一回合生效；
   - 重启（重新创建控制器）后，只读标记仍在；
   - 关闭记忆的会话设置只读：不报错，也不产生读写。
6. **文档**：`docs/记忆系统运行流程.md` 补一段"只读会话"，说明接口、行为和用途。README 暂时不写，因为还没有界面入口。
