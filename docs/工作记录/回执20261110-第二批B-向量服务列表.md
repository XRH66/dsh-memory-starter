## 数据结构

- 部署配置新增 `embeddingServices`，每项为：
  `{ id, name, apiBase, apiModel, dimensions, apiKeyFile, apiKeyService, createdAt, updatedAt }`。
- 最多保存 20 项；新建 `id` 使用 `randomUUID()`。
- `readDeploymentSettings` 只返回公开字段：
  `{ id, name, apiBase, apiModel, dimensions, hasKey, inUse }`。
- `inUse` 按规范化服务地址、`apiModel` 和维数与当前生效或待生效的 `custom-api` 配置比对。
- 不返回 `apiKeyFile`、`apiKeyService`，也不提供任何读取 Key 的动作。
- `removeUnusedStagedKey` 的引用集合加入全部服务 Key，取消待切换或模型重选不会误删列表引用的密钥。
- `deploymentStaticFingerprint` 不包含 `embeddingServices`：服务列表用于 UI/CRUD，不改变已加载运行配置；这样列表保存不调用 `afterSave` 也不会使后续会话设置写入误判为静态配置变化。

## 后端与接口

### `manageEmbeddingServices`

- `save` 支持新建和编辑，复用 HTTPS、模型名、维数和 Key 文件的现有约束。
- 空名称默认 `<地址主机名> · <模型名>`。
- 地址变化但没有新 Key 时拒绝：`服务地址已改变，请填写这个地址对应的 API Key`。
- 正在使用的服务只允许改名；改地址、模型名、维数或 Key 均拒绝，不能删除。
- 编辑并更换 Key 时写新文件；旧文件在不再被活动、待生效、历史或服务列表引用时删除。
- 删除后同样清理不再引用的 Key。
- 使用与现有部署写入相同的 `.lock` 和 `deploymentFingerprint` 版本检查，冲突返回 `REVISION_CONFLICT`。

### 模型选用与自动入列

- `stageDeploymentRawModel` 接受 `serviceId`，从服务列表填入地址、模型名、维数和 Key 引用，不需要重新填写 Key。
- `serviceId` 不存在时报 `所选服务已不存在，请刷新`。
- 直接填写自定义服务并保存模型时自动加入列表；按规范化地址、模型名和维数去重，已存在时更新 Key 引用和 `updatedAt`。

### HTTP

- 新增 `POST /api/basic-memory-settings/embedding-services`。
- Body：`{ action:'save'|'delete', revision, id?, name?, apiBase?, apiModel?, dimensions?, apiKey? }`。
- 返回 `{ ok:true, ...readDeploymentSettings }`。
- 沿用 `x-basic-memory-settings: 1`、JSON content-type、同源/本机校验和现有中文错误处理。
- 保存服务不调用 `afterSave`，不启动或重启模型。

## 界面

- 「检索模型」选中「自定义 API」后显示「已保存的服务」下拉：
  `名称（模型名）`，正在使用的追加「当前使用」，另有「新建服务…」。
- 选择服务后自动填入地址、模型名和维数；有 Key 时 Key 输入框留空并显示「已保存，留空沿用」。
- 使用已保存服务保存模型时请求带 `serviceId`，不重新提交 Key。
- 选中服务后可「编辑」「删除」：
  - 编辑展开名称、地址、模型名、维数和新 Key 字段；正在使用的服务只开放名称。
  - 删除先显示确认行，明确只删服务配置和密钥，不影响已有记忆和索引。
  - 正在使用的服务删除按钮置灰并显示「正在使用，不能删除」。
  - 使用 `role="dialog"`，没有浏览器 `confirm()`。
- 新建服务可直接保存模型，也可点「只存入列表」；后者不调用 `/model`。
- 所有服务写入请求进行中会禁用相关按钮；后端错误原样显示中文提示。
