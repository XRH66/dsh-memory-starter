## “部分完成”现状

现在只有下列情况会让 `degraded=true`，进而让 `memory_search` 返回 `partial`：

1. 通道自身返回不完整结果，状态为 `partial`，例如原话全文投影标记为不完整，或向量服务返回 `degraded`。
2. 通道超过共享截止时间，状态为 `timeout`。
3. 通道抛出非取消错误，状态为 `failed`。
4. 调用方取消尚未完成的通道，状态为 `cancelled`。
5. 整个搜索等待已超时，但先前已有可返回的草稿结果；`search-session` 使用 `fallback=true` 返回 `PARTIAL`。这覆盖“重排来不及完成、退回已找到草稿”的路径。
6. 最终来源复核发现来源变化，或把向量正文退回到可用的原话草稿；来源校验会把结果标成 `source_changed` 并保持 `degraded=true`。
7. `memory_open` 的旧来源已变化时，返回空记录并带 `source_changed`。

以下状态不再算未完成：

- `ready`
- `empty`
- `unavailable`

因此没有配置向量、没有旧笔记来源，或某个可选来源不存在时，只要已有通道正常完成，状态仍可为 `ok`。真正超时仍为 `timeout` 或 `partial`。

重排器自身的 `timeout`、`failed` 或 `paused` 会保留在 `channels.rerank` 中；若重排失败后直接返回融合顺序，这不单独扩大为整次检索失败。若外层等待先到期、系统需要退回重排前草稿，则按第 5 条标成 `partial`。预取准入门槛和注入行为未改。

- 删掉的用例只测已删除的旧笔记通道、`createLegacyNoteReader`、`readVaultNote`、`resolveMemoryNotePath`，没有误删保留功能的用例；任务单要求的新用例都在。

- 修复后复跑：Node 24 与 Node 22 各 678 通过、0 失败；三项检查通过（发行导出校验、隐私检查 319 个文件 0 违规、空白检查）；`lib/`、`scripts/` 下全部脚本语法检查通过。
