## 兜底安全检查

后端提交的只是会话内部的融合初稿，不会直接返回模型。正常路径和兜底路径都调用同一个 `validateResult`，再经过同一个 `fit` 完成：

- 当前读取授权仍由 `policy.validate(grant)` 和 grant 信号检查；兜底只绕开本次调用自己的超时中断，不绕开整次回答的取消或撤权。
- 原话、结构化条目和向量来源继续检查当前修订、来源状态、可见消息集合和已撤回控制。
- token 上限、单次条数、正文长度、短引用编号和 `anchors` 登记仍由 `fit` 一次完成。
- 正常打包若在超时前已经推进了未提交的短编号，会回滚到打包前；兜底结果和后续调用不会乱号或重复计费。
- 无可用记录时不把空 `PARTIAL` 冒充成功，仍返回 `TIMEOUT`。
