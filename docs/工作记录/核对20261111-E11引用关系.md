## 3. benchmark-public-360.mjs

`scripts/benchmark-public-360.mjs:12` 引入 `createRawRecall`；`:470` 创建 `analyzer`；`:283` 直接调用 `analyzer.select(...)`。该脚本没有调用 `analyzer.recall(...)`，因此它调用的不是返回对象上的 `recall`，而是同一返回对象上的 `select`。

结论：删旧召回链会让基准脚本失效。准确地说，删除 `createRawRecall.select` 或其依赖的 `selectEvidence` 会使 `scripts/benchmark-public-360.mjs` 失效；仅核对 `recall` 的调用点时，该脚本不是调用方。

## 6. 不带记忆开关的 portable 运行方式

`lib/platform-host.js:29` 仅在 `options.sessionMemory === true` 时创建 `sessionMemory`，否则为 `null`。`lib/bundle-entry.js:48` 的该值直接来自 `options.sessionMemory === true`，不是从 deployment 配置的 `cfg` 字段推导。

不带 `sessionMemory` 时的分支：

| 机制 | 位置 | 行为 |
| --- | --- | --- |
| `selected`、`pinned` | `lib/platform-host.js:26` | `selected` 来自配置的 DSH 会话列表；`pinned` 保存运行中回合的临时选择状态 |
| `createPersonalAccess` | `lib/platform-host.js:31` | `sessionMemory` 不存在时，用 personal access 和 `pureMode` 服务作访问门 |
| `accepts`、`tracks` | `lib/platform-host.js:34-35` | 根据 `pinned`、`selected` 接受和跟踪会话 |
| 工具执行 | `lib/platform-host.js:46` | 无 `sessionMemory` 时直接执行已通过门检查的工具，不包一层 session grant |
| 回合开始时 pin | `lib/platform-host.js:146` | `turn/start` 时把当前 `selected` 状态写入 `pinned` |
| 回合结束时解除 pin | `lib/platform-host.js:148` | `turn/end` 时删除临时 pin |
| `createPureGate` | `lib/platform-host.js:161` | 无 `sessionMemory` 时创建 pure gate |
| persona 渲染 | `lib/platform-host.js:162` | persona renderer 使用上述 pure gate |
| prompt 工具过滤 | `lib/platform-host.js:171` | 无 `sessionMemory` 时跳过按 session-memory 授权过滤工具 |
| `knownSessions` | `lib/platform-host.js:177` | 无 `sessionMemory` 时只返回 `selected` |
| 运行中切换选择 | `lib/platform-host.js:198-199` | 运行中的会话先 pin 旧状态，再替换 `selected`，等待回合结束生效 |
| 待生效回合数 | `lib/platform-host.js:210` | 用 `pinned` 与 `selected` 的差异计算 |

日常配置第 103 至 109 行是否传入 `sessionMemory: true`：是。

覆盖不带 `sessionMemory` 的测试：

- `test/platform-host.test.js:25`、`:44` 调用 `apply` 时没有传 `sessionMemory`。
- `test/pure-gate.test.js:87`、`:115`、`:131` 调用 `apply` 时没有传 `sessionMemory`。

这些测试会走 `sessionMemory === null` 的 selected、pinned、`createPersonalAccess` 和 `createPureGate` 分支。由于代码要求严格等于 `true` 才创建，省略该字段与传 `false` 走同一分支。
