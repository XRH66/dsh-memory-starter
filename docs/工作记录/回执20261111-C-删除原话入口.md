## 实现

- 新增 `manageRawMessages(input, check)`，支持 `search` 和 `withdraw`。权限检查沿用设置页管理入口，并在每次读取或写入原话时重新检查管理请求仍然有效。
- 搜索没有找到合适的现成原话列表查询，因此在 `RawMessageStore` 新增只读 `search`，由 `messageReader` 暴露。查询只读当前版本的 `raw_messages` 和 `raw_message_versions`，跳过 `withdrawn=1`，按消息时间倒序；不跨 owner 或 project。
- 搜索结果返回 `id`、`revision`、`sessionId`、`role`、按个人时区格式化的 `time`，以及命中位置附近最多约 200 字的 `excerpt`。搜索不按对话记忆开关过滤，覆盖当前记忆库内所有对话。
- 删除前先读取当前原话并精确比较 `revision`。不一致时返回「这条原话已经变化，请重新搜索」。比较通过后调用现有 `rawRecall.withdrawMessage(...)`，只标记撤回并删除全文投影，不物理删除消息版本。
- 新增 `GET /raw-messages` 和 `POST /raw-messages`。POST 继续经过本机访问、`x-basic-memory-settings: 1` 和 JSON 内容类型校验；GET 只做本地只读查询。
- 「维护」页新增「删除原话」一栏：搜索框、结果表、每行删除按钮和行内「确定／取消」确认；没有使用浏览器 `confirm` 对话框。成功后该行显示「已删除」；接口返回相关条目数组时会列出类型和摘录，并提示可在 Obsidian 修改或对条目点淡化。

## 通知与条目行为

- `withdrawMessage` 返回的 `notice` 与 `messageRecorder` 订阅到的消息变更通知来自同一个 `createSourceNotice`，结构核对一致，包含 `kind:'message'`、`operation:'withdrawn'`、`ownerSubject`、`project`、`revision`、`sessionId`、`messageId`、`role`、稳定 `id` 和事件 `position`。
- 删除成功后直接调用 `vectors?.notifyChanged(notice)` 一次，让向量目录重新核对边界；没有组装另一套通知结构。
- 来源被撤回后，未手工改过正文的派生条目会在 `memory-entry-service` 中变成 `sourceStatus.eligible=false`，后续条目检索会过滤它。若用户已经手工修改条目正文，`manualBody=true`，该条目仍以手工正文作为权威并保留在检索中。
- 不自动删除、改写或淡化由被撤回原话整理出的条目。
