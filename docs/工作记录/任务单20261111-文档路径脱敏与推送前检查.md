# 任务单：已上传文档的本机路径脱敏，以及推送前检查（2026-11-11）

执行者：Codex。设计与验收：Claude。

## 为什么做

GitHub 仓库是公开的。发行包（`release-files.json` 列出的 194 个文件）每次发布前都会跑 `scripts/check-release.mjs`，但仓库里另外还有 36 个 `docs/` 工作记录，从来没被检查过。扫描结果：没有密钥或令牌，但有 22 个文件共约 80 处写了本机的绝对路径，里面带着 Windows 用户名和目录结构。

本次做两件事：
1. 把这些已上传文档里的本机路径换成中文占位符；
2. 加一个推送前检查，扫描 Git 里所有已提交的文件，以后不再漏。

历史提交不改写，旧版本仍留在历史里，用户已知晓并接受。

4. **本任务单、回执和任何会被提交的文件里，都不能出现真实的本机路径或用户名。** 真实路径与占位符的对照表只在本地提示文件里（`.local/` 不上传）。回执里举例时只写占位符。

## 一、替换路径

范围：`git ls-files docs` 列出的已跟踪文件（除上面第 7 条的两个文件外）。

1. 先列清单：找出所有盘符绝对路径（形如「盘符 + 冒号 + 斜杠」开头的路径，包括反斜杠写法、反引号里的、Markdown 链接里的），以及其他出现 Windows 用户名的地方，按「路径前缀 → 出现次数 → 所在文件」汇总。
2. 按本地提示文件里的对照表替换，**长的前缀先匹配**（例如备份目录要先于记忆库目录）。前缀后面跟着的子路径保留，例如 `<记忆库目录>/vault/chats`。
3. 对照表覆盖不到的路径，不要自己编占位符：在回执里列出（只写占位符化的描述，不写真实路径），换成通用的 `<本机路径>`。
4. 替换后的检查：
   - 所有已跟踪的 `docs/` 文件里，盘符绝对路径和用户名都为 0 处；
   - 文档里原有的相对链接（`](工作记录/…)`、`](../…)` 之类）一个都没坏。替换前后各数一次相对链接，数量必须相等；
   - 用 `git diff --stat -- docs` 确认只动了含路径的文件，并且每处改动都是路径替换（`git diff --word-diff` 抽查）。

## 二、推送前检查脚本

新建 `.local/automation/check-tracked-privacy.mjs`（放在 `.local/`，不上传）。

- **默认模式**：检查 `HEAD` 里所有已提交的文件，也就是推送出去的内容。用 `git ls-tree -r -z HEAD` 列出文件，`git cat-file` 读取内容。
- **`--worktree` 模式**：检查当前工作区里所有被 Git 跟踪的文件（`git ls-files -z`），用于提交前自查。
- **规则**：
  - 照抄 `scripts/check-release.mjs` 里的 7 条规则（盘符绝对路径、私钥、API 密钥、GitHub 凭据、网址内嵌密码、Bearer 凭据、真实会话号），并在注释里注明「与 check-release.mjs 保持一致」；
  - 再从本地文件 `.local/automation/private-terms.txt` 读取禁用词（一行一个，`#` 开头为注释），文件里出现任何一个都算违规。这个文件由本任务新建，内容取自本地提示文件。
- **例外**：发行包里的测试固定样例如果因为规则误报（例如测试代码故意构造的盘符路径），用脚本内的允许清单按「文件 + 规则」逐条放行，不要放宽整条规则。回执里列出每一条例外及其理由。
- **输出**：每处违规打印「文件:行号  规则名」。路径类可以带 60 字以内的片段；密钥、凭据、禁用词类**只打印规则名，不打印内容**。最后打印「共检查 N 个文件，违规 M 处」。有违规时退出码为 1，否则为 0。
- **自测**：在临时目录里 `git init` 一个虚构仓库，放入含盘符路径、`sk-` 开头的假密钥、禁用词，以及干净的文件，提交后分别用两种模式跑，确认能查出来、不打印密钥内容、退出码正确。跑完删掉临时目录。不需要加进 `test/`。

2. 默认模式（检查 `HEAD`）此时仍会报旧的路径，因为还没提交，这是预期的。贴出统计行。
