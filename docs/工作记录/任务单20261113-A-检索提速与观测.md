# 任务单 A：检索提速与观测（2026-11-13）

总览见[全面优化总览](方案20261113-全面优化总览.md)。本批**只提速、加观测**，不改变检索结果的排序规则，也不改变预取注入的内容。去噪留给 B 批。

## 背景（已由 Claude 核实）

- `lib/memory-query.js` 的 `searchOnce` 会启动四路通道：`originals`、`structured`、`legacy`、`vector`。前三路内部全是同步调用（`DatabaseSync`、`fs.*Sync`）。`runMemoryQueryLanes` 按键的顺序用 `Promise.resolve().then` 启动各路，所以向量通道的编码请求要等三路同步工作都跑完才发出。
- `createLegacyNoteReader`（`lib/legacy-notes.js`）的缓存挂在每次 `createMemoryQueryAnswer` 实例上。预取（`lib/index.js` 的 `prefetchMessage`）和每次回答都会新建实例，所以每轮都要重新读文件、计算 SHA-256；`search` 里的 `lexicalMatch` 也要对每篇笔记重新分词。
- `legacyImportFingerprints(config)`（`lib/legacy-import.js`）每次检索都会重新读状态文件。
- `profiles.query`（`lib/unified/profiles.js` 约 989 行起）返回前已经对每条入选记录重新调用一次 `resolve`。`searchOnce` 中 `vectorReviewMs` 那段 `while(true)` 复核循环会再核对一遍；最终 `validateResult` 还会检查一次。
- `lib/unified/vector-index.js` 的 `rank` 用 `blob.readFloatLE(i*4)` 逐元素计算点积。

## 要做的事

### A1 向量编码请求尽早发出

目标：一次检索开始后，向量通道的查询编码请求（后端 `embed`，`kind:'query'`）要在三路同步文字检索开始之前发出；至少不能排在它们之后。

允许的做法（任选，或组合使用）：

1. 在 `searchOnce` 里把 `vector` 放到通道对象的第一个键，同时让三路文字通道在开头先 `await` 一次让出主线程，例如 `await new Promise(resolve=>setImmediate(resolve))`。这样向量通道能先走完它的异步准备，把请求发出去。
2. 在 `lib/memory-vectors.js` 的 `managedBackend` 代理里，给 `kind:'query'` 的 `embed` 加**查询编码缓存**：
   - 键为 `模型身份 + 查询文本`；
   - 进行中的请求共享同一个 Promise；
   - 只缓存成功结果，失败或中止的立即移除；
   - 最多 64 条，10 分钟过期。
   - 缓存的是查询文本的向量，不含记忆正文，不落盘。

必须保留的行为：

- 共享截止时间不变；
- 慢通道超时后已完成的文字结果照常返回；
- 撤权立即生效：取消授权时进行中的检索要中止，缓存不能绕过授权检查（命中缓存只是省掉编码，后续的授权和来源核对照常执行）。

### A2 去掉重复的向量复核循环

- 删除 `searchOnce` 中 `vectorReviewMs` 那段 `while(true)` 复核循环，以及只为它服务的变量和常量。
- 来自 `vectors.query` 的记录视为已核对（`profiles.query` 返回前已复核）。
- `validateResult` 中的最终来源复核和文字结果兜底（`_textFallback`）**保留不动**。
- `channels.vectorValidation` 字段不再产生。检查 `lib/` 和 `test/` 中所有引用它的地方：
  - 测试只是断言这个字段存在的，删掉或改为断言最终来源复核；
  - 测试断言的是"来源变化后不返回旧内容"的，必须继续通过，必要时改为经 `validateResult` 路径验证。
- 回执中逐条列出改动或删除的测试和理由。

### A3 旧笔记读取共享缓存

- `lib/legacy-notes.js`：缓存改为模块级，按 `vaultPath + directories` 共享，跨实例复用。
  - 缓存项里保存笔记分词后的词集合，供检索复用。
  - 在 `lib/raw-rag/lexical.js` 新增导出 `lexicalMatchTerms(profile, termSet)`，与 `lexicalMatch` 结果完全一致；`lexicalMatch` 改为调用它。
  - `search(query, limit)` 只计算一次 `queryProfile(query)`。
- 仍然每次 `stat` 文件来判断是否变化（大小 + 修改时间），保证 Obsidian 手改能立即生效。
- 删除或改名后的文件要从缓存中移除（现有逻辑保留）。
- `legacyImportFingerprints`：按状态文件路径缓存，状态文件大小和修改时间不变就复用上次结果。
  - 迁移写入状态时，必须让缓存失效：要么写后立即清除，要么依赖修改时间变化，但要有测试覆盖。

### A4 向量点积改用 Float32Array

- `vector-index.js` 的 `rank`：
  - 把向量块转成 `Float32Array`。`byteOffset` 不是 4 的倍数时，先复制到对齐的缓冲区。
  - 点积用普通循环计算。
  - 计算结果与原实现的差异不超过 `1e-6`，要有测试证明。
  - 维数检查和非有限值检查保留。

### A5 寒暄和过短输入跳过预取

- 新建 `lib/memory-prefetch.js`，导出 `shouldPrefetch(text)`，返回 `{ok:boolean, reason?:string}`。
- 以下情况返回 `ok:false`，`reason` 写 `'trivial'`：
  - 去掉空白、标点、表情后为空；
  - 是纯寒暄或纯应答：好的、好、嗯、嗯嗯、哦、行、可以、谢谢、谢了、继续、接着说、哈哈（连续）、晚安、早、早安、在吗、ok、okay、thanks、thx、yes、no、收到、明白、知道了、对、是的、没事；
  - 允许带"啊""呀""吧""～""！"这类语气尾巴；
  - `queryProfile(text).terms` 为空。
- 其他情况一律 `ok:true`。宁可多查，也不要误跳过真实问题。测试里要证明以下输入返回 `ok:true`：
  - "我上次说的那家店叫什么"
  - "阿岑"
  - "好的，那周末去哪吃"
  - "5号"
  - "继续说说我妈的事"
- `lib/index.js` 的 `prefetchMessage`：在检索前调用它，跳过时直接返回，不建检索会话。

### A6 预取观测

- `prefetchMessage` 每次结束都通过已有的 `recordSearch` 记一条摘要，`kind` 为 `'prefetch'`。字段只记数字和枚举，**不记查询文本和正文**：
  - `outcome`：`'injected' | 'skipped' | 'empty' | 'timeout' | 'failed'`
  - `reason`：例如 `'trivial'`、`'disabled'`、`'no-candidates'`
  - `candidates`：按种类计数，`{original, entry, legacy, vector}`
  - `injected`：注入条数
  - `injectedChars`：注入字数
  - `totalMs`：总耗时
- 现有检索摘要字段保留。如果字段名和现有 `search` 摘要冲突，可以把预取特有字段放进一个 `prefetch` 子对象。
- 状态页的"最近检索"如果是通用渲染，不用改；如果需要改 `lib/client.js` 才能显示，**本批不改界面**，在回执里说明。

### A7 离线测速脚本

- 新建 `scripts/bench-prefetch.mjs`，用 `node scripts/bench-prefetch.mjs` 运行。
- 在系统临时目录建虚构库：2000 轮原话、300 条结构化条目、200 篇旧格式笔记。可以参考 `test/` 里已有的夹具和辅助函数。
- 向量后端用可配置延迟的假实现，默认 300ms；参数 `--vector-delay=<ms>`。
- 输出 JSON，包含：
  - 预取 50 次的 p50 和 p95；
  - 向量编码请求发出时刻相对检索开始的毫秒数（p50）；
  - 各通道平均耗时；
  - 旧笔记通道首次和缓存命中后的耗时。
- 结束时删除临时目录。
- 加入 `release-files.json`。
- 在回执里贴出本批改动**前后**两次运行的结果。改动前的数据：先用 `git stash` 或临时工作树在当前 `HEAD` 上跑一次。如果脚本依赖本批新增的接口，就只给出改动后的数据，并说明原因。
