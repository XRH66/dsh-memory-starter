## A1 向量编码请求尽早发出

- `searchOnce` 的通道顺序改为 `vector` 在前。
- 配置了向量时，三个同步文字通道先各让出一个 `setImmediate`，让向量通道先完成异步准备并提交查询编码。
- `managedBackend` 增加查询编码缓存：
  - 键为 `modelKey + 查询文本`。
  - 仅处理生产查询实际使用的单文本 `kind:'query'` 调用。
  - 在途请求共享同一个 Promise。
  - 只保留成功结果，失败或中止立即删除。
  - 最多 64 条，成功后 10 分钟过期，仅驻留内存。
  - 命中前后都执行当前请求的授权检查；后续档位、来源和最终交付校验未跳过。
- 共享检索截止时间和“文字结果已完成时照常返回”的原有逻辑未改。

定向覆盖包括：向量请求先于文字通道、在途共享、成功复用、失败移除、撤权中止、重新授权后命中缓存。

## A2 去掉重复的向量复核循环

- 删除 `searchOnce` 中 `vectorReviewMs`、`reviewDeadline`、`reviewStates`、`while(true)` 复核循环和 `channels.vectorValidation`。

- `validateResult` 的最终来源复核和 `_textFallback` 文字兜底保留。
- 向量记录的最终失效仍会移除旧内容并回退到同版本文字记录。

## A3 旧笔记与迁移指纹共享缓存

- `legacy-notes.js` 的缓存改为模块级，按 `vaultPath + directories` 共享。

- 每次读取仍逐文件 `stat`；修改会重新读取、校验和分词，删除或改名会从缓存移除。
- `raw-rag/lexical.js` 新增 `lexicalMatchTerms(profile, termSet)`；`lexicalMatch` 改为调用同一实现。
- 旧笔记搜索只计算一次 `queryProfile(query)`。
- `legacyImportFingerprints` 按状态文件路径、大小和修改时间缓存派生 Map；迁移写状态后递增缓存纪元并显式清除该路径。

## A4 向量点积改用 Float32Array

- `vector-index.js` 的 `rank` 将存储向量块转为 `Float32Array`。
- `byteOffset` 未按 4 字节对齐时，先复制到新的对齐缓冲区。
- 点积改为普通循环；维数检查、长度检查和非有限结果检查保留。
- 新旧实现结果一致性测试误差上限为 `1e-6`。

## A5 寒暄和过短输入跳过预取

- 新增 `lib/memory-prefetch.js`，公开导出 `shouldPrefetch(text)`。
- 去掉空白、标点、符号和表情后为空、纯寒暄或纯应答、或 `queryProfile(...).terms` 为空时返回 `{ok:false,reason:'trivial'}`。
- 允许“啊、呀、吧”等语气尾词；连续“哈”按寒暄处理。
- 任务单指定的真实问题样例和短名称、数字、延续请求均返回 `{ok:true}`。
- `prefetchMessage` 在创建查询会话前调用判定；跳过时直接返回，不建检索会话。

## A7 离线测速

新增 `scripts/bench-prefetch.mjs`：

- 在系统临时目录生成 2000 轮虚构原话、300 条结构化条目、200 篇旧格式笔记。
- 默认假向量后端延迟为 300 ms，可用 `--vector-delay=<ms>` 调整。
- 运行 50 次预取，输出 p50、p95、向量编码发出时刻、各通道平均耗时，以及旧笔记冷读取和跨实例缓存后耗时。
- 输出 JSON，结束时删除临时目录。
- 已加入 `release-files.json`。

同一脚本在源码改动前的当前 HEAD 状态运行过一次，源码改动后又在最终状态运行一次。脚本没有依赖本批新接口，前后数据可直接比较。

改动前：

```json
{
  "prefetch": {"p50Ms": 403.95, "p95Ms": 417.87},
  "vectorDispatchMs": {"p50": 91.39},
  "channelsMeanMs": {"originals": 91.94, "structured": 92, "legacy": 92, "vector": 400.41},
  "legacy": {"firstMs": 65.87, "cachedMeanMs": 57.65}
}
```

改动后：

```json
{
  "prefetch": {"p50Ms": 310.85, "p95Ms": 316.64},
  "vectorDispatchMs": {"p50": 0.46},
  "channelsMeanMs": {"originals": 35.41, "structured": 38.22, "legacy": 41.24, "vector": 306.63},
  "legacy": {"firstMs": 79.72, "cachedMeanMs": 2.66}
}
```

观察：

- 预取 p50 从 `403.95 ms` 降到 `310.85 ms`，p95 从 `417.87 ms` 降到 `316.64 ms`。
- 向量编码请求发出时刻从 `91.39 ms` 提前到 `0.46 ms`。
- 新建旧笔记读取器后的平均耗时从 `57.65 ms` 降到 `2.66 ms`。
- 旧笔记首次读取受系统文件缓存影响较大，前后单次值不适合单独比较；主要证据是跨实例缓存均值。
