### 调用参数问题

只保留模型能通过改参数、重新定位或重新读取后重试的错误。模型可见的 `summary` 和 `errorMessage` 是简短中文；结构化 `errorCode` 保留。

`lib/records.js` 白名单：

- `INVALID_ACTION`
- `INVALID_KIND`
- `INVALID_TEXT`
- `INVALID_NAME`
- `INVALID_ENTRY`
- `INVALID_IDENTIFIER`
- `INVALID_IMAGE`
- `NOT_PERSONAL`
- `NOT_FOUND`
- `MISSING_EXPECTED_CHECKSUM`
- `STALE_REVISION`
- `WRITE_CONFLICT`
- `DIARY_OLD_DAY`

`WRITE_CONFLICT` 按“连续版本冲突，重新读取后重试”处理。未列入白名单的 `INVALID_ENTRY_STATE`、`NOT_OWNED`、`MEMORY_ERROR`、`EMPTY_RECORD`、`DIARY_LIMIT`、`INTERNAL` 及未知错误都按运行故障处理。`DIARY_LIMIT` 不是换一个合法参数就能解除的当日容量限制，因此不进入参数白名单。

### 运行故障

存储读写、网络、超时、授权、未知异常等统一返回：

> 这次没能读写记忆（技术原因已记录在状态页）。回答时自然地说这次没办成即可，不要提后端、接口、错误码，也不要编造。

具体原因只写 `logger.warn`。实现范围：

- `createMemoryQueryTools` 的搜索、展开、近期读取三个工具都包住查询对象创建和调用异常；返回与 `search-session` 错误结果同形状的 `status=error`、空 `records`、`error` 和 `budget`。已有中性结果原样透传。`lib/index.js` 创建工具时传入现有 `logger`。
- `dafeiyu_records` 的失败返回保留 `errorCode`，但 `summary` 和 `errorMessage` 按白名单给出中文；工具外层也包住配置读取、参数校验和调用异常。
- `soften_memory` 的参数提示改为中文；`softenRawMessage` 抛错时返回中性 `ok:false`，原始异常只进日志。

## 接续时间上限

- `handoffMaxAgeHours` 默认 72，schema 要求整数且范围为 1～8760。
- `resolveConfig` 对缺失、越界和非整数按默认 72 处理；浮点不会被四舍五入成合法值。
- `selectHandoff` 使用 `source.time ?? source.recordedAt`。时间为空或不是有限数值的原文不带入；早于 `now() - maxAgeMs` 的原文不带入，并在遇到第一条过期项时停止继续翻页。
- 其他选择逻辑保持原样：来源对话排除、角色与标签、4096 token 预算、截断、展示顺序和 `newest` 语义均未改。
- 三个调用点均改为传入 `maxAgeMs: resolved.handoffMaxAgeHours * 3600000` 和插件现有 `now`：首轮预选、只读首轮替换、正常准备/替换。

## Claude 复核（2026-11-15）

结论：通过，复核时改了两处。

1. **接续翻页的停止条件**：原实现遇到第一条过期原文就停止往前翻，前提是原话库的存放顺序和时间顺序一致。重启后补录的旧回合会排在较新的位置上（时间却很早），这时接续会整个变空。改为：过期或没有时间的原文跳过；一整页里都没有时限内的原文时才停止翻页。补了一条测试"selectHandoff still finds fresh originals behind an expired one stored later"；原测试改名为"…stops after a page with nothing inside it"，期望不变。`recent-memory-authorization` 那条调整仍成立（第一页全过期，只翻一页）。
2. **用户中途停止时不包装**：三个查询工具的兜底在 `exec.signal` 已中止时把原异常抛回，不包成"没办成"的普通结果，免得取消被当成一次正常回答。

同意的取舍：`DIARY_LIMIT` 按运行故障处理（模型只看到中性提示）；`WRITE_CONFLICT` 按可重试处理。

复核验证：Node 24 与 Node 22 全量各 710 项 0 失败。
