# DSH 记忆系统功能清单

[整体说明](记忆系统整体说明.md) · [运行流程](记忆系统运行流程.md) · [README](../README.md)

本页按用户实际能做的事分组。每项都写明工具、设置页位置、配置文件字段或命令入口。

## 存

| 功能 | 入口 | 一句话说明 |
| --- | --- | --- |
| 按对话开启记忆 | 「记忆框架 → 记忆 → 对话」，或对话页头部的记忆开关 | 所有对话默认关闭，开启后从下一新回合开始保存和读取；关闭不会删除已有内容。 |
| 新对话自动开启 | 「记忆框架 → 记忆 → 新对话自动开启记忆」 | 打开后，新建且尚未开始的对话从第一句起自动获得记忆授权。 |
| 保存用户原话 | 开启记忆后自动进行 | 提交的直接用户正文按回合写入原话库，保留消息身份、时间、顺序和完成状态。 |
| 保存助手原话 | 开启记忆后自动进行 | 助手最终正文单独保存并标明角色；不保存推理、工具结果和附件块。 |
| 保存旧笔记导入记录 | `node scripts/inherit-memory.mjs apply ...` | 把 0.3～0.6 的可用旧笔记写成原话库记录，标成“旧笔记（整理摘要）”。 |
| 写助手人设笔记 | `dafeiyu_records` 工具，`action=save` | 维护 `thoughts`、`diary`、`gallery`、`people` 四类 Markdown 主观记录。 |
| 手选检索资料 | 「维护 → 手选检索资料」 | 每行保存一个记忆库内 Markdown 相对路径，让这些文件进入向量检索。 |

## 找

| 功能 | 入口 | 一句话说明 |
| --- | --- | --- |
| 自动预取 | 「记忆 → 回答前预先带上相关记忆」 | 每次开启记忆的实质对话先用用户本轮原话检索一次，默认带入最多 3 条、1000 字候选。 |
| 子对话只读使用记忆 | 「记忆 → 子对话也能用记忆」 | 默认关闭；打开并重新加载 DSH 后，DSH 任务开出的子对话和孙代理可使用工具、预取和回答规则，但不保存子对话原话，也不进入短期接续。 |
| 搜索原话和相关资料 | `memory_search` | 只在缺少会改变答案的历史依据时按查询词搜索，返回带来源、角色和时间的短编号。 |
| 展开原话依据 | `memory_open` | 按搜索结果里的短编号展开同版本原文、保存的同回合上下文、有限前文或旧笔记依据。 |
| 查看近期原话 | `memory_recent` | 按需读取最近保存的用户和助手正文，与搜索、展开共用本次回答预算。 |
| 全文检索 | `memory_search` 自动使用 | 直接查本地原话全文，不需要向量模型。 |
| 向量检索 | 在「检索模型 → 向量」配置模型；「记忆」页的「原话检索」也要开着（新安装默认开着） | 按语义查找原话、人设想法／日记和手选资料；未配置完整时只停用语义分支。 |
| 重排 | 「检索模型 → 重排」 | 可选地把候选交给重排服务重新排序；失败或超时保留原顺序。 |
| 当前状态偏向新记录 | `memory_search` 自动使用 | 查询含“现在、目前、最近”等词时，有时间原话按新旧最多增加 20% 权重。 |
| 助手原话降权与配对 | `memory_search` 自动使用 | 助手原话最终权重乘 `0.5`；同一回合同用户和助手都命中时，助手内容挂在用户那条下，最多显示 120 字。 |
| 排除不可用来源 | 检索自动进行 | 过期版本、已撤回、未配置、旧条目和旧笔记向量会在结果交付前被过滤或标明。 |

## 用

| 功能 | 入口 | 一句话说明 |
| --- | --- | --- |
| 每回合事实规则 | 开启记忆后自动附带 | 附加当前本地时间和 8 条中性规则，约束模型只把记录里写到的内容当事实。 |
| 自动预取材料 | 开启记忆且预取开启后自动附带 | 把候选放在 `<memory_prefetch>` 中，并明确标成程序找到的背景而不是用户指令。 |
| 短期接续 | 「记忆 → 短期接续」 | 新对话、换对话、连接或模型变化、上次未完成时，从其他对话带入最近原话。 |
| 设置接续长度 | `handoffTokens` 或「记忆 → 短期接续」 | 默认 4096 tokens，可选 4K、8K 或 1～16384 的自定义整数。 |
| 设置接续时间上限 | 配置文件 `handoffMaxAgeHours` | 只取最近多少小时内的原话，默认 72，整数范围 1～8760；没有时间的原话不带入。 |
| 控制模型检索预算 | 工具调用自动执行 | `memory_search`、`memory_open`、`memory_recent` 每回答合计最多 4 次、约 4096 tokens；单次搜索约 1024，展开约 2048。 |

## 改和删

| 功能 | 入口 | 一句话说明 |
| --- | --- | --- |
| 淡化某条原话 | `soften_memory` | 用户明确要求别再提时，降低该原话所在回合的默认召回权重；正文不改、不删，强线索仍可召回。 |
| 删除原话 | 「维护 → 删除原话」 | 按 1～100 字关键词搜索并确认，把单条原话标为撤回；它不再进入新的检索和接续。 |
| 修订人设笔记 | `dafeiyu_records`，`action=save` 并带 `title`、`entryIndex`、`expectedChecksum` | 用版本校验修改已有条目，避免覆盖并发改动。 |
| 提交人设笔记人工审阅 | `dafeiyu_records`，`action=archive` 或 `delete` | 只写入待审清单，不删除、不停用、不降权笔记；实际文件仍按原样保留。 |
| 撤回或恢复导入批次 | `scripts/inherit-memory.mjs undo`、`restore` | 用导入批次号整批排除或恢复旧笔记记录，原话和批次记录不物理删除。 |
| 删除单个向量档案 | 「状态」页对应模型的「清理此模型的索引」 | 只删除该模型已建索引，不删除原话、人设笔记或当前使用的模型。 |

## 设置与维护

| 功能 | 入口 | 一句话说明 |
| --- | --- | --- |
| 管理四个设置页 | 「记忆框架 → 记忆／检索模型／状态／维护」 | 分别管理对话授权和功能开关、模型与服务、运行状态、记忆库和删除入口。 |
| 设置时区 | 「记忆 → 时区」 | 默认北京时间，可换成 IANA 时区；保存后重新加载记忆框架生效。 |
| 控制子对话记忆访问 | 「记忆 → 子对话也能用记忆」 | 默认关闭，非根代理看不到工具、不能预取且执行前会被拒绝；打开后恢复只读使用，保存后重新加载 DSH 生效。 |
| 创建或选择记忆库 | 「维护 → 记忆库」 | 新建独立目录或登记另一个记忆库，当前库在重新加载和检查通过前继续使用。 |
| 选择云端向量模型 | 「检索模型 → 向量」 | 默认模型档位是 `custom-api`，必须填服务地址、模型名、维数和密钥后才可用。推荐硅基流动的免费模型 `BAAI/bge-m3`（1024 维），填法见[向量模型说明](../MODEL-SETUP.zh-CN.md#推荐硅基流动免费向量和重排)。 |
| 管理云端向量服务 | 「检索模型 → 向量 → 服务」 | 保存、编辑、测试或删除带密钥的 OpenAI 兼容向量服务，最多保存 20 个。 |
| 选择本地向量模型 | 「检索模型 → 向量 → 本地模型（可选）」 | 本地模型按需下载和加载，不随插件默认安装；可设置运行设备、线程、常驻或空闲释放。 |
| 准备和续建索引 | 「状态」页 | 可准备、取消、续建索引，查看进度、待追平来源、模型状态、运行设备和检索耗时。 |
| 管理索引档案 | 「检索模型 → 向量 → 索引档案」 | 查看不同模型的维数、文档数、更新时间和估算占用，切回旧档案时只补差量。 |
| 设置重排 | 「检索模型 → 重排」 | 默认关闭，可复用已保存服务或单独填写地址和 Key；保存后重启 DSH 生效。推荐硅基流动的免费模型 `BAAI/bge-reranker-v2-m3`（也是默认值）。 |
| 查看检索状态 | 「状态」页 | 最多保留本次启动最近 20 次搜索的耗时、通道状态、是否部分完成和是否含模型加载，不显示查询正文。 |
| 记忆星图 | DSH 左侧栏「记忆星图」；开关在「记忆 → 记忆星图」 | 把原话按意思画成星空或平面图，可搜索、看原文、删除新版本记下的原话；第一次打开时后台计算并缓存，关掉后不计算。自己写的画法放进 `<记忆库目录>/views/`，见[记忆星图](../MEMORY-MAP.zh-CN.md)。 |
| 设置只读会话 | `sessionMemory.setReadOnly(sessionId, boolean)` 接口 | 让开启记忆的会话只读、不写原话和接续；没有设置页入口。 |

## 还没有的

- 按时间逐条翻看的原话库浏览界面：记忆星图能按意思看全貌和搜索，但还不能按时间顺序翻页。
- 前后说法变化的专门标注界面：当前回答规则会要求模型按更新时间和记录核对，但没有可视化对照页。
- 只读对话的设置页入口：目前只有 `setReadOnly` 接口。
- 导入旧笔记的设置页入口：目前必须运行 `scripts/inherit-memory.mjs`；命令行导入已有 `check`、`apply`、`list`、`undo`、`restore`。
- 原话删除界面已经存在，入口是「维护 → 删除原话」；旧任务单把它列为缺口，与当前代码不一致。
- Linux 实机验证：当前已记录的是 Windows 上的实际使用和自动化测试，Linux 尚未实机验收。
