# DSH 记忆系统运行流程

[整体说明](记忆系统整体说明.md) · [功能清单](记忆系统功能清单.md) · [README](../README.md)

本页按一轮对话的时间顺序说明插件实际做了什么、用了哪些时限，以及失败时怎样退。

## 一轮对话的主流程

```text
turn/start
  ├─ 读取本对话的记忆开关和只读状态
  ├─ 子对话且「子对话也能用记忆」关闭 → 不授予读取，也不写原话
  ├─ 关闭 → DSH 正常聊天
  └─ 开启 → 冻结本回合读取授权

pre-step / request
  ├─ 需要接续 → 从其他对话的近期原话中取一块
  ├─ 需要预取 → 用最后一条用户原话做一次有界搜索
  └─ 附加当前本地时间和 8 条回答规则

模型作答
  ├─ 材料够用 → 直接回答
  └─ 需要核对 → memory_search / memory_open / memory_recent

消息提交
  ├─ 用户和助手正文分别写入原话库
  ├─ 建立全文投影
  └─ 通知向量队列，在后台按当前模型追平

turn/end
  └─ 记录完成或中断状态，完成本次接续状态
```

## 1. 回合开始：判断能不能读写

DSH 发出 `turn/start` 时，插件先判断该对话是否已开启记忆。所有对话默认关闭；在设置页或对话页头打开后，从下一新回合开始使用。关闭会立即使新操作失去授权，重新打开不补记关闭期间的内容。

本回合开始时会：

- 冻结本次读取是否可用；
- 读取 `setReadOnly` 标记；
- 为后续读取建立带回合身份的授权；
- 只有在真实用户消息提交后，才为写入原话建立来源授权；
- 如果向量队列可用，恢复与该对话有关的后台追平工作。

只读回合仍然可以预取、搜索、展开、看近期原话和读取第一回合接续，但不会保存原话、写接续状态、接受淡化或通知向量队列。只读标记在回合开始时读取并冻结，中途修改从下一回合生效。

设置页保存的功能开关和模型设置可能要求重新加载记忆框架或重启 DSH；界面会显示“下一新回合生效”“重新加载后生效”或“重启后切换”。不要只看保存成功的提示就假定正在运行的进程已经切换。

### 子对话

DSH 通过 `subagent` 等工具开出的子对话（包括孙代理）默认不接入记忆。插件用宿主提供的运行时归属判断它是不是根代理；归属无法确认时按非根处理。非根代理在「子对话也能用记忆」关闭时不显示任何记忆工具，工具执行前守卫会拒绝，回合开始也不建立读取授权，因此不会自动预取、附加回答规则或带短期接续。

在「记忆 → 子对话也能用记忆」显式打开并重新加载 DSH 后，子对话恢复为只读接入：可以使用记忆工具、自动预取和回答规则，但不保存子对话的原话，也不会把子对话当作短期接续的来源。根对话的开关和原话保存不受这一项影响。

## 2. 接续、预取和规则消息

### 短期接续

接续材料来自其他对话最近保存的用户和助手原话。以下情况会触发选择：

- 新对话的第一回合；
- 从另一个对话切过来；
- 可识别的服务线路、提供方或模型变化；
- 上一次回答没有完成。

首回合会在模型请求前预选一块接续材料。其他触发点在请求配置确定后计算目标线路，再把接续消息放到当前输入之前。同一对话只保留一条接续块；连续正常聊天主要沿用 DSH 自身上下文。

选择从新到旧扫描原文，只取：

- 其他对话的原话；
- 有可用时间且位于 `handoffMaxAgeHours` 窗口内的原话；
- 总量不超过 `handoffTokens` 的材料。

`handoffTokens` 默认 4096，范围 1～16384，按估算 tokens 计量。`handoffMaxAgeHours` 默认 72，整数范围 1～8760；没有时间来源的原话不进入接续。接续只取原话，不生成摘要；旧笔记导入记录默认也不进入接续。

如果接续已经存在且最新来源没有变化，就沿用现有块；有更新版本时替换旧块。材料为空时不注入空消息。若宿主还未发布受保护的系统首条消息，插件会延迟追加，连续三次会记录警告，不把接续混入错误的位置。

### 自动预取

记忆开启且 `autoRecall: true` 时，插件在每轮第一次进入模型前读取最后一条直接用户消息，只对非空、非纯寒暄、有可检索词的内容执行一次预取。

默认参数：

| 项目 | 当前值 |
| --- | --- |
| 最多候选 | 3 条，可配置 1～4 |
| 最多字符 | 1000，可配置 0～4000 |
| 预取搜索等待 | 1300 毫秒 |
| 预取外层硬限 | 1500 毫秒 |
| 预取重排候选 | 16 条 |
| 重排绝对门槛 | 0.02 |
| 重排相对门槛 | 本题最高有效分的 0.5 倍 |

搜索使用与 `memory_search` 相同的授权、来源复核和查询服务，但会把本轮用户已经能看到的原话排除，避免占用旧记忆名额。预取首轮会把候选合并、按相似文本去重，再截到条数和字符上限。自动预取不显示单独的助手原话；同一回合同用户与助手都命中时会折叠。

有重排时只检查带有效重排分的当前记录。没有重排时，任一条件成立即可准入：词面分达到 `0.6`；向量相似度超过模型下限加 `0.1`；或者词面与向量双路同时达到较弱门槛。自动预取选中带时间的行会按从旧到新排列，没有时间的行放在前面。

### 规则消息

只要本回合允许读取，插件就附加一条 `<memory_answer_rules>` 消息：

- 当前本地时间；
- 8 条中性事实规则；
- 如果当前回合可用 `soften_memory`，再附加它的使用条件；
- 一句“这些规则不是用户记忆，不得保存为事实”。

规则消息每回合都有，不依赖预取是否找到材料。它是程序消息，模型不能把它当成用户新指令或记忆内容。

## 3. 模型调用工具

模型按需调用三个读取工具：

| 工具 | 作用 | 主要边界 |
| --- | --- | --- |
| `memory_search` | 搜原话和相关资料 | 单次约 1K tokens，最多返回 10 条，可带时间范围 |
| `memory_open` | 展开搜索结果中的 ref | 单次约 2K tokens；核对原话、同回合上下文、有限前文或旧笔记依据 |
| `memory_recent` | 查看最近保存的双方原话 | 与搜索和展开共用本回答预算 |

三个工具共用同一条回答的账本：默认最多 4 次调用、约 4096 tokens。普通搜索的等待时间按模型和设备决定：

- 云端接口通常为 4000 毫秒；
- 本地 4B／8B 在 GPU 上通常为 2000 毫秒；
- 本地 CPU 或轻量模型通常为 2500～4000 毫秒；
- 配置文件里的 `rawRecallQueryWaitMs` 可在 1000～10000 毫秒之间覆盖，设为 0 表示自动。

每次调用从单调时钟计时。搜索和向量查询共享同一条绝对截止时间；收尾预留取 `max(300ms, 总等待的 10%)`，供结果复核、去重和 token 打包使用。

检索结果先合并全文和向量候选，再做授权、可见性、来源版本和撤回检查。已有原话如果不到 3 个字符，不进入结果。可选重排只处理前一组候选：普通搜索默认 30 条，预取默认 16 条；重排预算受 `memoryRerankTimeoutMs` 控制，默认 1500 毫秒，可配置 300～5000 毫秒。

最终排序还会：

- 把助手原话乘 `0.5`；
- 把同一回合同用户与助手都命中的助手内容折叠到用户结果下，最多 120 字；
- 在“现在、目前、最近、后来”等查询里，按记录新旧给有时间原话最多 `1.2` 倍权重；
- 根据来源版本和撤回状态剔除已经失效的候选。

## 4. 保存原话和后台追平

用户在真实事件里提交消息时，程序只保存正文。用户消息可以先入库，不必等助手回答结束；助手最终正文保存为另一条原话，并保留角色和来源身份。推理、工具调用、工具结果、附件块和文本块附加字段不保存到原话正文。

每条原话记录包含：

- 会话、消息身份、角色、顺序和回合；
- 提交时间或记录时间；
- 文本投影；
- 版本和完成状态；
- 必要的来源授权凭据，供后台消费者再次核验。

原话提交和全文投影不等模型、不等待向量编码。投影任务失败会留下回执和错误状态，下一回合或恢复流程可以重试；来源版本变化、授权撤销或原话撤回后，过期任务跳过。

助手回答完成后，回合标成 `completed`；中断、取消或未完整结束时标成 `interrupted`。短期接续据此识别“上次回答未完成”，不会把被中断的回答当成完整历史。

### 向量队列

打开「原话检索」并配置好向量模型后，原话、想法／日记和手选资料会进入统一向量档案。后台队列：

- 先等前台查询退出，再处理文档编码；
- 默认合并 300 毫秒内的变更；
- 一次只处理一个任务；
- 普通失败按 1 秒起步的退避重试，最多 3 次；
- 授权失效、来源改版或模型档案变化时标记跳过或取消；
- 每个任务写回前重新核对来源版本，避免把旧内容写成新索引。

原话编码（0.7.3 起）：前面有对话时，每个原话分块编码两份，一份带最多 4 条前文（2000 字以内）作为背景，一份只编码正文；没有前文的只编码一份。检索时同一条原话只算一个候选，取两份中较高的相似度，向量候选名额按不同原话计数。编码方式写进索引身份，版本变化时自动排队重建一次新索引，建完前旧索引仍可读（带旧背景的向量会被拒绝，按意思检索暂时以全文为主），建完原子切换。删除或修订原话时两份向量一起移除或替换。

索引准备使用 `rawRecallPrepareTimeoutMs`，默认 120000 毫秒；单次编码／分块使用 `rawRecallIndexTimeoutMs`，默认 30000 毫秒。切换模型会建立或复用对应档案；旧档案默认保留，切回时只补差量。

## 5. 失败和超时怎样退

| 场景 | 结果 |
| --- | --- |
| 对话记忆关闭 | 不预取、不附加规则、不暴露记忆工具；原话库不受影响 |
| 子对话记忆关闭 | 子代理和孙代理不预取、不附加规则、不暴露记忆工具，守卫拒绝执行；原话库不受影响 |
| 自动预取跳过 | 纯寒暄、空消息、关闭预取或无可检索词时不附 `<memory_prefetch>` |
| 自动预取超时或失败 | 本轮不附预取材料，规则消息照常附加；错误只写日志和状态 |
| 全文通道完成、向量不可用 | 返回全文结果，向量通道标不可用，不把整个搜索判失败 |
| 搜索外层超时且已有结果 | 对已有结果做同样的授权和预算检查，返回“部分完成” |
| 搜索超时且没有任何结果 | 返回中性“没能在等待时间内完成”提示，不暴露接口、错误码或路径 |
| 重排超时或失败 | 保留重排前的融合顺序，继续返回可用结果 |
| 来源已改版或撤回 | 不返回旧版本正文；能回退到当前全文版本时回退，否则删除该条 |
| 工具参数错误 | 返回简短中文参数提示，模型可以改参数后重试 |
| 其他工具运行故障 | 返回统一的中性中文提示，详细原因只进日志；不把堆栈、英文内部错误或本机路径交给模型 |
| 后台索引失败 | 保留原话和全文；队列记录待重试或最终失败，状态页显示计数，不阻塞当前聊天 |

### 宿主卡顿不计入检索时间

DSH 主线程被其他插件同步卡住时，插件自己的计时器也会晚触发。0.7.0 的检索计时使用单调时钟并扣除这类宿主卡顿：

- 每个计时器最多补 10 秒；
- 到点时重新计算剩余时间，刚被卡住就按剩余时间顺延；
- 预取、普通搜索、向量查询、重排和向量库内部截止检查使用同一套剩余时间；
- 没有卡顿时，行为和各级原时限相同；
- 检索摘要保留 `timings.hostStallMs`，状态页可以区分“插件慢”和“宿主卡住”。

这项豁免只处理宿主同步卡顿，不会延长远端请求的授权，也不会跳过来源复核。

## 6. 撤回、淡化和接续状态

「维护 → 删除原话」先按关键词找回当前版本，再要求用户确认。确认后程序：

1. 把 `raw_messages` 中的来源标成撤回；
2. 删除它的全文文本投影；
3. 发出更新通知，让向量侧跳过旧版本；
4. 后续搜索、展开和接续不再读取该原话。

原话版本仍保留用于追溯，不会物理改写历史正文。

`soften_memory` 不删除正文，只降低该原话所在回合的默认召回权重。用户说“别忘了”“我忘了”不算明确淡化请求；必须先定位唯一条目，工具成功后才能说已经淡化。

回合结束时，非只读会话会更新接续状态：

- 回答完整结束且接续已交付，记录最后一个已交付块；
- 回答中断或取消，记录失败状态，让下一回合知道需要接续；
- 接续选择、准备或写入失败只写警告和状态，不撤销已经完成的聊天回答。

## 7. 设置和维护

「记忆」页管理对话开关、自动开启、预取、短期接续、子对话只读访问、原话检索和时区。「检索模型」页管理向量模型、云端服务、本地模型、索引档案和重排。「状态」页显示模型、索引、最近 20 次检索和运行操作。「维护」页管理记忆库、手选资料和删除原话。

记忆星图（0.8.0 起）挂在 DSH 自带网页服务的 `/api/basic-memory-map` 下，左侧栏入口用 DSH 的侧栏和主区域插槽。打开页面时才读取当前向量索引：按索引成员算指纹，有缓存就直接用；没有就在后台线程里降维、分团、算深度，写到记忆库旁边的 `management/vectors/memory-map/`，新增原话时在原位置上微调。正文按向量文档里存的定位从原话库读回（新旧两种存储都认），只给页面显示，不写进缓存。开关关掉后接口返回已关闭，不做任何计算。

模型、记忆库、功能开关等配置有时采用“待生效”快照：保存后写配置文件，当前进程继续用旧值，重新加载或重启后才应用。状态页和设置页必须显示这种边界；看到“已保存”不等于当前回合已经切换。
