## 当前行为

- 对话记忆默认关闭，按会话开启；可另设新对话自动开启。
- 日常没有“先建库再聊天”：开启后的正文按轮增量保存，前台使用已写入的原文和接续，后台整理与向量索引分别追平；首次准备索引、切换档案后的重建和恢复属于维护动作。
- 用户和助手正文由程序保存，独立思考、工具块和附件块不进入新原文。
- 短期接续在切换会话／模型／可识别线路或上次回答未完成时补入近期原文。
- `autoRecall` 默认开启：每轮用用户原话执行一次最多 4 条、搜索等待 1.3 秒、整链硬时限 1.5 秒的预取，并附 `<memory_prefetch>` 候选。候选不是用户新指令，可在「记忆」页关闭；模型仍可用 `memory_search`、`memory_open`、`memory_recent` 按需查证。
- 后台整理形成十二类 Markdown 条目；向量按模型和接口服务分档案，旧档案切回时复用并补差量。
- 「维护」提供记忆库切换、旧记忆迁移、删除原话和检索模型专家设置。

## 暂缓与已知问题

- **记忆故障话术**：记忆查询或后台技术故障时，模型仍可能直接说“记忆后端暂时无法返回结果”。后续应把技术错误留在日志和状态页，对话侧使用自然说法，同时保持不编造记忆。
- **自动预取噪声**：当前预取只有“有候选就注入”的弱边界，缺少低相关度拒止；同源原话、条目和旧笔记也可能占用多个槽位。真实失败样本仍不足，不能先做架构级重写。
- **答题输入量**：基准答题输入曾多出约 12.5k，来源尚未拆清。
- **整理并发**：整理仍在关键路径上，当前没有并发执行。
- **撤回范围**：删除原话只撤回单条消息，不自动删除派生条目、相邻原话或整段事件转述。
- **向量服务身份**：正在使用的地址、模型和维数不能原地改成另一套身份；要新建服务再切换，这是有意的数据保护。
- **代码审查欠账**：前端 `setPlan` 作用域、Vault 单文件解析容错、档案维数匹配、配置锁陈旧与错误包装、Windows 原子改名重试、旧记忆确认并发窗口、设置接口非对象输入和本地文档隐私检查范围等问题尚未修。
- **精简第三批暂缓**：拆 `lib/client.js`、合并 Vault 读写原语，均留待后续。内部目录 `lib/unified/` 名字虽旧，仍在承载文件型适配。

详细代码证据见[记忆系统代码审查与检索方案评估](research/memory-audit-and-retrieval-review-20261112/README.md)。
