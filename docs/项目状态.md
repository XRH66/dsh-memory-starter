## 0.5.0 有什么

在 0.4.0 的基础上（按对话开启、原话由程序保存、按需检索、后台整理、遗忘曲线、短期接续、可选向量检索与重排，详见 README）：

- **向量索引档案**：每个本地型号、每个接口服务（按地址＋模型名＋维数区分）各有一份索引。换模型不清理旧索引，切回来复用原档案、只补差量。「检索模型」页列出各档案的维数、文档数、最后更新、估算占用，可一键切换；没有删除入口。
- **删除原话**：「维护 → 删除原话」按关键词搜所有对话的原话，行内确认后标记撤回，并通知向量索引同步；由它整理出的条目不会自动删除。
- **旧记忆迁移**：「维护 → 旧记忆迁移」一次点击后台自动跑完：程序搬结构化字段，整理模型每批最多 30 个旧笔记只做分类选择题，拿不准或和原状态矛盾的进「待确认」；可暂停、继续，重启后自动续做；旧文件不改。迁移条目走专用导入入口（无原话依据、依据性质为人工），普通条目的来源校验没有放宽。迁移后又改过的旧笔记会重新出现在检索里，可再迁移。
- **接口向量维数**：服务记录实际使用的维数（旧记录里的 0 显示为「1024 维（默认）」）；可为支持的模型勾选「向服务商请求这个维数」，这个选项不改变索引身份。
- **架构精简**：去掉不用对话开关的运行方式（插件配置写 `sessionMemory: false` 直接报错）、旧整理器和「恢复旧任务」、旧近期缓存、纯净模式门控、防删除守卫、Basic Memory 回退、旧原句召回链（含 `verify:raw-recall` 脚本）、旧整理动作写入器；历史导入工具 `raw-rag/history.js` 留在仓库但移出发布包；退役配置项 `maxIndexChars`、`maxTimelineChars`、`recentContextTokens`、`maxAutomaticFailures`、`rawRecallMaxChars`、`rawRecallCandidates`、`rawRecallTop`、`rawRecallTimeoutMs`（旧配置里有照样接受并忽略）。`lib/` 从 98 个文件、约 2.1 万行降到 90 个文件、约 1.8 万行。
- **行为变化**：没有整理模型时只保存原话，不再退回旧整理器写旧格式笔记。

**部署新版本的做法**：

1. 按白名单导出快照：`node .local/automation/export-release.cjs . .local/runtime/versions/memory-<名字>-<UTC 时间>`；
2. 备份 `cordis.patch.yml` 为 `*.bak-<快照名>`，把记忆插件那一行（`name: 'file:///…/lib/bundle-entry.js'`）改指新快照；
3. 用 `.local/automation/restart-dsh.ps1` 重启（会打断正在进行的对话）；
4. 核对插件已加载、设置页正常。

## 暂缓与已知问题

- **答题输入量**：基准里答题输入多出约 12.5k，来源没查清；测量框架已在 `.local/benchmark-cmb/` 准备好（约 100–120 次模型调用），等用户同意再跑。
- **整理并发**：整理还在关键路径上（只影响基准等待），没有并发。
- **撤回入口**：DSH 的回退、重新生成、删除对话不会通知插件，只能用「删除原话」手动处理。
- **正在使用的向量服务只能改名**：改地址、模型、维数要新建服务再切换（有意如此，避免索引对不上）。
- **精简第三批**：拆 `lib/client.js`（约 1300 行）、合并 Vault 读写原语，均不改行为，暂缓。
- 内部目录 `lib/unified/` 名字是旧的，但仍在使用，不改名。
