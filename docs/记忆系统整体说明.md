# DSH 记忆系统整体说明

[运行流程](记忆系统运行流程.md) · [功能清单](记忆系统功能清单.md) · [README](../README.md)

## 它是什么

这是给 DeepSeek Harness（DSH）用的个人长期记忆插件。它按对话开启：开启的回合会把用户和助手的正文原样保存到本地原话库，之后用全文、向量和可选重排找回相关内容，再交给当前对话模型参考。

它不是另一套聊天记录，也不是后台整理器。对话记忆的唯一权威记录是原话库；向量和重排只负责定位，不负责改写事实。用户关闭某个对话的记忆后，该对话不再读写个人记忆；关闭不会自动删除已经保存的内容。

`v0.7.2` 支持 DSH `0.2.1-rc.5` 和 `0.2.2-rc.3`。DSH 做任务开出的子对话默认不接入记忆；在「记忆」页打开「子对话也能用记忆」并重启 DSH 后，子对话可以只读使用记忆，仍不保存子对话的话，细节见[运行流程](记忆系统运行流程.md#子对话)。

## 现在有哪些层

| 层 | 保存什么 | 作用 |
| --- | --- | --- |
| 原话库 | 用户和助手的正文、角色、消息身份、时间、回合和完成状态 | 保存对话证据；全文检索、原话展开和短期接续都从这里读取 |
| 原话向量 | 原话分块的向量及来源版本 | 按语义找到可能相关的原话；来源改动或撤回后旧结果会失效 |
| 人设笔记 | `vault/dafeiyu/` 下的想法、日记、图片印象和人物印象等 Markdown | 保存助手自己的主观记录，不是用户事实；想法和日记可进入向量检索 |
| 手选资料 | 用户在「维护 → 手选检索资料」中指定的 Markdown 相对路径 | 让明确选中的资料进入向量检索，不会把整个 Vault 自动纳入 |
| 短期接续 | 其他对话最近的双方原话；接续状态文件只存元数据 | 换对话、换模型或上次回答未完成时帮助接上话 |
| 向量索引 | 按模型档案保存的文档和分块向量 | 提供语义候选；切换模型不会清掉旧档案 |

聊天原话不会先被模型总结成“条目”。原话库之外的人设笔记、手选资料和旧笔记导入记录，都是不同的材料类型，检索结果会标明来源和说话角色。

## 检索怎么工作

一轮里可能有三条检索路径：

1. **原话全文**：直接查当前保存的用户和助手原话。
2. **原话向量**：把原话、人设想法／日记和明确选中的资料按当前向量模型编码后，按语义找候选。
3. **重排**：可选。先取一小组候选，再让重排服务按与问题的相关性重新排序。推荐的组合是硅基流动的免费向量 `BAAI/bge-m3` 和免费重排 `BAAI/bge-reranker-v2-m3`，见 README 的[推荐配置](../README.md#推荐配置硅基流动的免费向量和重排)。

全文和向量结果会按来源版本、授权、撤回状态和可见性复核，再合并、去重并装入回答预算。少于 3 个字符的短原话不进入搜索结果。旧版本遗留的“条目”和 0.3 旧笔记向量文档会在查询时排除；当前检索不再直接读 Vault 里的旧聊天笔记。

如果开启重排，自动预取使用两个门槛：重排分不低于 `0.02`，并且不低于本题最高分的 `0.5` 倍。没有重排时，按词面、向量相似度和双路一致规则把关。重排失败、超时或没有时间时，保留原来的融合顺序，不把整次搜索判成失败。

## 自动预取和按需检索

对话开启记忆且「回答前预先带上相关记忆」开启时，插件会用本轮最后一条直接用户原话做一次有界预取。默认最多放 3 条、合计 1000 字；设置允许 1～4 条和 0～4000 字。纯寒暄、空消息和没有可检索词的内容会跳过。

预取结果放在 `<memory_prefetch>` 中，明确标成程序找到的背景，不是用户本轮说的话。模型仍需自己判断是否相关；需要核对时再调用：

- `memory_search`：按查询词搜索原话和相关资料；
- `memory_open`：展开搜索结果里的短编号，核对原话、同回合上下文、有限前文或旧笔记依据；
- `memory_recent`：按需读取最近保存的双方原话。

这三个工具共用本次回答的调用和返回预算，默认最多 4 次、约 4K tokens。搜索结果先按来源复核；普通搜索默认等待时间随模型和设备变化，云端接口通常为 4000 毫秒，自动预取固定使用更短的预算。

## 每回合的回答规则

每个开启记忆的回合都会附加一条规则消息。里面有当前本地时间和 8 条中性规则，核心要求是：只把记录里实际写到的内容当事实，计划不冒充已发生，时间按记录标注，同一件事有前后说法时以较新的为准，不主动翻无关私事，没有依据时自然说不知道。

规则消息一直存在，不依赖本轮是否真的找回材料。它不是用户记忆，也不会被保存成事实。

## 短期接续

新建对话、切换到已有对话、服务线路或模型变化、上次回答未完成时，插件可以从其他对话的最近原话中取一段接续材料。新对话从第一句就可能带上；同一对话只保留一条接续块；连续正常聊天主要沿用 DSH 自身上下文。

接续默认按 `handoffTokens: 4096` 估算预算，可在「记忆 → 短期接续」中选择 4K、8K 或 1～16384 的自定义值。0.7.0 的配置项 `handoffMaxAgeHours` 控制只取最近多少小时内的原话，默认 72 小时，整数范围 1～8760；超出范围按默认值处理，没有时间来源的原话不进入接续。这个配置没有单独设置页入口。

接续只取原话，不取模型摘要。助手说过的话会保留“助手”角色，不能当成用户事实；导入的旧笔记默认不进入短期接续。

## 人设笔记和手选资料

助手自己的人设笔记由 `dafeiyu_records` 工具维护，类型包括 `thoughts`、`diary`、`gallery` 和 `people`。想法和日记可以进入统一向量检索；命中时会标成“助手自己的想法／日记 · 写于……”，不会被套成用户原话。

用户也可以在「维护 → 手选检索资料」填写记忆库内的 Markdown 相对路径。保存选择只会让这些明确路径进入向量索引；删除某行并保存即可撤回。这个入口不是原话库浏览器，也不会扫描整个 Vault。

## 继承旧笔记

0.7.0 不再提供旧版整理器的“一条纲一条目”模型，也不再直接搜索 0.3 Vault 旧笔记。升级时使用：

```powershell
node scripts/inherit-memory.mjs check --deployment <配置文件>
node scripts/inherit-memory.mjs apply --deployment <配置文件>
node scripts/inherit-memory.mjs list --deployment <配置文件>
node scripts/inherit-memory.mjs undo --deployment <配置文件> --batch <批次号>
node scripts/inherit-memory.mjs restore --deployment <配置文件> --batch <批次号>
```

`check` 只读；`apply` 先备份原话库，再把可导入的旧笔记写成原话库中的“旧笔记（整理摘要）”。旧 Vault 原文件不改。默认跳过从对话整理出来的派生条目；确实需要时在 `check` 和 `apply` 上加 `--include-derived`。主题页固定内容、条目旧版存档和只在旧数据库里的整理结果不导入。

导入后的旧笔记排序权重为 `0.7`，不会进入短期接续。每批可以整批撤回和恢复；全文检索不用等向量，向量索引需要当前模型准备好并追平。

## 淡化、删除和只读

`soften_memory` 会在用户明确要求“别再提、淡化或忘掉”某条已保存原话时，把该原话所在回合的默认召回权重降低。正文和版本仍保留，明确线索仍可能召回。

「维护 → 删除原话」按关键词找到一条原话并标记撤回。撤回后它不再进入新的全文、向量或接续结果；原文版本仍保留用于追溯。删除入口不会删除整本记忆库，也不会顺带删除人设 Markdown。

只读会话通过 `sessionMemory.setReadOnly(sessionId, true)` 接口设置。只读回合仍可预取和调用查询工具，但不保存原话、不写接续状态、不接受淡化；当前没有设置页开关。

## 失败时怎么退

- 全文通道照常可用时，向量服务不可用不会阻止聊天。
- 自动预取超时、失败或没有候选时，本轮不附预取材料，规则消息照常存在。
- 工具搜索已经拿到结果后才超时时，返回已核实的结果并标“部分完成”；只有没有可用结果时才返回中性超时提示。
- 重排失败时保留融合顺序；向量失败时保留全文结果。
- 后台向量队列可以重试和恢复；来源版本变化、授权撤销或原话撤回后，旧任务会跳过，不把过期内容写回索引。
- 检索时限只计算插件能运行的时间。DSH 主线程被其他插件阻塞的时间会从预算中扣除，每个计时器最多补 10 秒；这不会延长服务端请求本身，也不能绕过授权和来源复核。

## 现在没有的东西

没有整理器、结构化条目、待确认清单、主题页维护、Vault 监视或旧记忆后台迁移。没有原话库浏览界面、前后说法变化标注、只读对话设置页、导入旧笔记设置页，也还没有 Linux 实机验证。这些缺口不等同于已有功能，不要按旧版文档操作。
